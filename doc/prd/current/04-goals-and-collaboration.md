## 现在能做什么

一句话可以变成一件还要继续做的事。Bot 把它记成目标，自己选一种已经授权的做法去推进，并留下证据。人不用先选任务模式。对话、目标和执行是三层。对话是说话的入口。目标是要达到的结果，一只 Bot 可以同时有多件。执行是推进这件目标的一次尝试。一次结束不等于目标完成。

没有分配到这场执行的目标时，保存进度返回现有的明确错误「No goal is assigned to this execution」。同一次执行里只出现一次，不会接着再试，也不会为此新造一个目标。上一波没跑完、恢复后才执行的那一次也一样，不会再保存第二次。来源范围拒绝仍是拒绝，不会被改成成功，也不会被换成这句没有目标的错误。已经分配了目标时，种类无效仍是「Invalid checkpoint kind」，没授权的等待仍是「Waiting requires an execution reference authorized by goal_dispatch」。这两句都不会变成成功，也不会换成没有目标的那句，同一次执行不会因此一直保存到步数上限。

目标的状态是排队、进行中、等待、受阻、暂停、完成、失败、取消。等待必须说清什么会把它叫醒。受阻必须说清原因，以及怎样才算解开。完成只能来自一次独立的核对。模型说做完了、证据不够，都不能算完成。能用构建结果或文件是否存在来核对时，优先用这些。判官暂时不可用时，已经走完的回合保留已有结果并继续，不把这次收成完成。产品规则同时要求：核对不可用就不要宣称完成，证据留下待查。

一句话先存下来，再判断它是新的一件事、给已有的事加约束、问问进展、暂停恢复取消或改优先级，还是闲聊。一句话可以同时有几种。问问进展不新建目标。闲聊不产生持久任务。加了约束就版本加一，还在按旧版本做的执行停下来。指哪一件，看明确的目标、这条消息回复的是谁、当前选中的目标，以及这场对话。判断不清的那一下只停住有争议的修改，其他目标继续。回执要说新建或改的是哪一件，人可以纠正。旧对话不会把全部历史一次性猜成一堆目标。点名某一件追加要求时，要求写进该目标的约束，不另开一件。指代不清时先澄清。

对话里有最近的未完成目标时，说「继续」或问进度，这一轮就接着做那件目标，结束时照样要过完成核对。目标正在执行时只报告状态。没有目标的一轮，如果说了接着做却停下、在能自己决定的事上停下来问人，或自己列的待办没做完，运行时会让它继续，次数有上限，没有新动作就结束。需要人登录、给凭证或确认不可逆操作时照常停下。说了稍后汇报却没有任何等待在跟进时，运行时到点把 Bot 叫回来核对，次数有上限，人发了新消息就作废。一轮因步数上限结束时记为到达上限；绑定的目标没被核对为完成就回到排队继续，对话里会说明还在做。这些在实验室的「Bot 收尾跟进」里开关和调整。

每次派发先看现在真正能用的东西：工具、权限、工作区、预算、相关能力是否健康。默认选能完成这件事的最简单做法。问一句就能答，就在主对话里直接回。一件要做的事，主 Bot 自己做。同时多出来的独立工作，每件多出来的交给一个子任务。另一只更合适的 Bot，就委派给那只，用它的权限。查资料可以用研究配置。网页或桌面用已经授权的对应能力。重复地读和合并，可以用只对这一次生效的动态做法。依赖清楚的协作可以用团队任务图。已经有角色流水线时可以用群体协作。首选不可用时，只能在同样的授权范围内换一种。不能靠换做法绕过审批、隔离或扩大能看到的数据。做不到就说明具体原因。

只有一件在做时，不派子任务，主 Bot 自己做。两件或更多同时在做时，主对话留下一件，多出来的每一件各有一条子任务。主对话仍是协调者。子任务可以检索父 Bot 的笔记、这只 Bot 的记忆、技能、文件和上下文。找不到另一只 Bot 的私有记忆，也进不了共享记忆池。对外发消息、改定时任务、改写父记忆，子任务做不到。

同一只 Bot 再开任务时，沿用这只 Bot 已经生效的档位。自动档里该审批的仍要审批。完全放行不因为拆了一条会话就再确认一次。更严的档位和计划模式保持更严。委派给另一只 Bot 时，用对方当前的权限。源 Bot 的放行覆盖不了它，源 Bot 更严也不把它改严。有人声称自己是某只 Bot 来提权，直接拒绝。权限档位传下去，不等于多给工具或数据。已经存在的会话不会被成批提权，挂着的审批也不会自动通过。

子任务停在需要人批准的步骤时，这张待批准出现在该 Bot 的主对话里，目标写明在等这个批准。批准或拒绝之后，子任务按这个决定继续或停住。待批准不会被自动通过，也不会被当成目标已经完成。

改了约束之后，旧版本晚到的结果可以留下当证据，不能直接把新版本判完成。已经发生、撤不回的外部动作要照实说。结果不明就停住等人核对，未核对前不自动再做。授权失效可以重新接上再继续。每次执行留下自己的交付：报告、这次的产物、软件回执、失败原因。用户上传的文件不算 Bot 的产出。报告能导出，文本产物能限量预览和下载。来源或回执没有的，不编一个。人可以基于某一交付版本继续修改。新成果记录来源和版本关系，旧版本仍可查看。

部分失败时，做成的和没做成的分开写。成功的成员不再跑一遍。可以只重试失败的那个。还在等审批的成员显示受阻，批准之后从原来的执行继续。只有协调者回复了，不能当成整组完成。预算、没有进展、尝试次数用尽，就停止继续派。重要的状态变化合并成一次通知，不刷屏。

服务重启后恢复已经记下的状态。本进程已经不再持有的执行会收口：可安全重试的本地工作继续排队，结果不明的外部操作变为受阻并等待核实。子任务在重启时被标成结果不明后，同样立即收口。主对话上一次进程留下的写入锁会放开，目标状态仍能写进主对话。宿主进程不在线时，新的派发不会自己发生。取消之后不再派后续工作，迟到的结果也不能把它重新启动。

完成、失败和取消的目标不常驻对话底部。在对话顶部展开「目标历史」可查看结果、失败原因和已有证据。历史默认折叠。进行中的多目标面板仍只在至少两件未结束工作时出现。即使只剩一件，待核对、受阻或暂停时也会显示「目标需要你处理」。待核对结果可以接受，或填写原因打回。普通单目标仍不展示多目标列表。可以只为这一件追加预算或批准额外尝试。新增额度不清零历史，也不修改其他目标及默认设置。额度保存后由人恢复。等待已有执行时不能直接恢复成新执行。

费用用这一次上报的用量和独立工人的费用。不能把整段主对话的历史总费用算成这一件目标的费用。没有账单回执时，成本就是未知。人可以记录交付验收。效果统计支持时间范围，包含首次有效交付耗时、验收成功率、已记录的人工干预次数、故障恢复成功率和成功交付成本。统计要说明分母和样本从哪来。没有上游账单时，不用估价冒充实付。

并发、预算、尝试上限和策略偏好在实验室里改，保存后下一次派发生效。单次执行的步数上限可以选不限、二十四、四十八或九十六。不限步数仍受停止、循环检测、审批和错误处理约束。这里的一步不是目标尝试次数。同一只 Bot 名下，不同用户的目标互相看不见。

子会话、委派、团队任务图、群体协作、工厂和演进的结果，会回到原来那件目标。结束、失败和缺记录会收口，不会停在进行中或一直等待，也不会把缺失记录当成完成。这些专项要各自核过之后才接进自动选择。没接上时保持不可选，并说明原因。研究配置不等于已经接上独立的深度研究产品。

一只 Bot 可以给另一只有权联系的 Bot 发消息。对方的主对话收到并开始处理。发给自己，或发给别人名下的 Bot，直接拒绝，任何一边都不写入。待处理消息和委派在重启后仍可查询。收到或派发不等于完成。委派结果写入请求方对话后即完成投递。旧目标还在等回复时，新到的独立委派仍能开始。团队任务页看一组人的目标、完成数、谁堵住了、已有的交付。展开成员才能看到详情、回到对话处理审批，或只重试失败的那个。看团队状态时先读已有快照。会话空闲不代表外面的执行已经停。过期的观察会标成陈旧。要新状态才发起刷新。助手自己说健康，不能充当观察证据。进程状态也不能代替原目标的完成核对。

群至少有两只不同的 Bot，有自己的名字、成员、主持人和历史，重启还能读。从「新建」里选已经有的 Bot。之后可以再加入或移出成员，不能减到只剩一只，也不能把同一只加两次。不是成员的名字不会被拉进来。未指定主持人时，用成员列表第一只。

按相关性回复时，所有群都是稀疏的，包括两三只的小群。点名只叫醒被点到且不超过这一轮人数上限的成员。点名没有命中，就说明没找到，不叫醒别人。引用某只 Bot 的回复，只叫醒被引用的成员。没有点名也没有引用时，按名字、头衔、简介和职能组匹配，先叫醒过门槛且不超过人数上限的成员，并行回答。没人达到门槛时，整群可以零回复，不发兜底套话。专家有实质回复后，尚未发言的主持人可以补一次短收尾。没有新信息就不发。主持人已经回复后，若还有明显更贴题且未发言的成员，最多再补一位。静默和「我不知道」这类短否定不显示。停止后，还没出现在群里的回复不再出现。群的费用预算和工具调用上限默认关闭，新建的群没有这两项；要用就在那个群的设置里打开，或在「设置 → 群规模」里保存新群的默认预算。升级前按旧默认值（1 美元、100 次）带着预算的群，升级后这两项自动关闭，其它数值不动。一轮被群的费用预算或工具调用上限停下时，已经写完的回复照常出现，还在执行的成员被取消、不再花费；群聊顶部写明是哪一项预算停下的、哪些成员没有回复，并指向群设置；成员自己执行失败才提示检查成员模型。每只 Bot 从这一轮一开始就用自己的身份发言。

群也可以保存为任务协作。下一轮先由一位临时负责人推进。负责人按需邀请群内成员，并指定任务和交付证据。非负责人不能派发，群外成员不能加入。明确点名不额外叫醒没点名的人。共享记录保留执行状态和公开回复证据，由负责人汇总。预算不足时保留待核验。真实用户在这种群里明确点名派工时，群先返回接收回执，工作登记到该 Bot 原来单聊里的持久目标，由现有调度继续做。群讨论结束或讨论预算用尽，不表示工作已经交付。普通 Bot 自动发言不能借文字取得这条人的授权。回执可以打开原工作会话。完成、受阻、失败会向原群发布状态和入口。私聊正文和私有证据不会自动复制到群。成员退出或来源失效后，停止这条公开投递。

群还可以保存为辩论。用户发出辩题后，参与者按设定的顺序一人一条、多轮交替发言，每个人都能看到此前的全部发言，对手最近一条是全文。每条发言都要回应对方的论点，不能沉默跳过。全部轮次结束后，裁判总结并给出裁决。轮数、参与者与顺序、各自的立场和裁判在群设置里填写；不填时默认三轮，主持当裁判，其余成员轮流。一场辩论的发言总数有上限，群的发言数、工具和费用上限照常生效。用户停止后不再出现新发言。在辩论群里点名某位成员，仍然只是向他提问。

群还有自己的目标。人可以在群里中途插话。群目标不写进某只 Bot 的单聊目标。成员之间的接力、进度和局部失败分别可见。大群可以折叠成员、搜索、整组加入，并单独滚动，目标条独立。群内原位批准默认关闭。单独启用后，等待只挂在那个成员身上，不把整群卡住。默认仍是：要真人登录、验证或批准时，转到这只 Bot 的私聊里做完。群里只留一句短说明。结果不自动贴回群。

被叫醒的成员看到的是这次推给它的纪要、共享条文和最近消息。它可以按权限只读找回更早的原文、附件和产物。没推送、也没取回的内容，不因为「在这个群里」就自动出现。私人对话的原文不会整段抄进群。它自己的单聊记忆可以用，所以单聊里记住的事实可能出现在群回复里。后来的单聊只能用这次真正碰到的群内容。

软件连接在实验室里配。默认表单支持网页接口和外部工具服务，可以导入接口说明并筛成只读，也保留高级自定义入口。格式错误、名称冲突或不支持的接口，不覆盖已经保存的有效连接。人能看见连上了没有、范围是什么、上次验证是什么时候、能支持哪些任务。凭证进密钥库，界面不回显。调用用的是这份连接自己的凭证。撤销或失效后明确拒绝，并给出修复入口。恢复后保留任务上下文。Bot 根据真实回执说明成功、失败或待核对。不把「已连接」或「已提交」当成做完。不支持的接口明确拒绝。结果不明就留下待核对，不盲目再做一次。人可以看操作记录并登记核对结论。第一次使用时有连接引导。

有权限的安装主人可以让默认总助手保存机器的远程登录别名、容量、关联的 Bot 和协调者，创建包含它自己的工厂群并关联配置。未指定协调者时用它自己。可以用已有别名发现远端的代码检出。只发现一个仓库时可以填入该路径。默认不开启巡检，明确要求后再开启。配置后可以继续修改。满足连接、仓库和派单权限后，可以发起只读试跑。非主人或管理员不能修改。Bot 拿不到服务令牌和远程私钥。

已有的即时通讯可以在配置和授权后承接消息。已绑定 Bot 的入站沿用主对话和命令。飞书可以双向：人的消息能驱动对话，回复能发回去。企业微信要经自建桥接才能把消息送进来，群机器人通道主要用于发回复，不是完整的企业微信应用。Slack 的入站事件可以进入会话，并叫醒监听该类消息的定时任务。直接把回复发回 Slack 对话仍未交付，出站仍经草稿确认。钉钉、Telegram 和个人微信没有内置。人直接发来却没有更多要补充时，不把静默标记发到聊天软件里，而发一句短确认。渠道推送若是静默，则什么都不发。飞书和企微的出站在发送前记账，进程重启后重放还没确认送达的记录。这是至少送达一次，可能重复，不是恰好一次。

外部软件可以在设置里获准把任务交给指定 Bot。Bot 用自己的权限做独立任务。调用方只能查询这件任务的结果，看不到主对话历史。可以只授权 Bot，不授予通用执行者。另一项是连接远端助手：保存地址、凭证、目标执行者，以及允许使用这条连接的本地 Bot。授权的本地 Bot 可以派工、看状态、补充输入或取消。保存后马上生效，凭证不回显。对方需要支持本项目的任务交接，或自备转换。接收不等于完成。接收结果不明时，保留原来的派工标识再试。

对话里的 Bot 可以查看和修改它负责的产品配置。改配置走原来的权限和审批，不因为是「管理」就绕过。

## 从哪里进入

目标从主对话里的话产生。两件以上未结束时看「目标与进展」。终态在对话顶部的「目标历史」。待处理的单件看「目标需要你处理」。子任务从主对话小入口、详情页签或普通会话列表打开。团队任务页看一组人的目标和交付。群从 Bot 列表「新建」进入，和单只 Bot 在同一条列表里。软件连接在实验室的连接设置里。多机工厂在「设置 → 运维 → 多机软件工厂」核对。外部助手在「设置 → 集成与可观测」。即时通讯在网关设置里配置，保存后生效，密钥不回显。

## 现在还不能当成已经交付

编排器、自愈、演进和工厂全流程，没有各自核过生命周期之前，不能当成 Bot 已经会自动选用的做法。研究配置不是独立的深度研究产品。只读试跑和工厂配置完成，不等于任意远程命令、生产发布或无人值守已经认证。多机生产现场验收仍未完成。跨机器、跨工作区和提交证据的连续盯梢组合验收未完成。发布证据仍缺真实模型、长时间浸泡和实际部署回滚，不能宣称可以发布。

群成员管理离开主聊天区仍是草稿。不是每种聊天软件都能双向控制或一键授权。Slack 直接发回复、钉钉、Telegram 和个人微信都还不是内置能力。外部助手交接不包含把另一套产品的历史会话、记忆和定时任务迁过来，也不表示兼容其他代理协议。

效果统计只覆盖已经记录的样本。没有采集的无人完成率、非工作时段交付和连续运行可用性，不能写成已有指标。

Bot 委派在登记自动等待前就已结束时，调度器可以直接领取该结果。旧版遗留的同类等待也能恢复，显式等待下一次版本变化的条件仍按原条件执行。见 `bot-task-terminal-wait`。

Bot 私聊首轮直接提供已授权的 `bot_delegate`。连续三轮单独查询同一个 Bot 且配置结果完全相同时，触发恢复保护；默认再给一轮改用委派或其他操作的机会，继续重复即结束本次运行。

## Bot 工作流

任务 → 工作流按 Bot 读取已有对话工具回执、委派父子任务、群成员执行记录和定时运行。可查看结果、已记录费用与耗时，点击打开来源会话。评审分支只依据已有父任务或群轮次。
工作流读取子会话时仅请求关系、状态与用量，避免重复传输完整上下文。

任务 → 工作流默认打开多 Bot 协作图。曲线连接委派双方或群轮次的实际参与者；头像与连线可查回执、会话和单 Bot 明细。Bot 设置中的定时任务默认显示名称、周期与开关，展开可管理任务及执行记录。
从 Bot 链接进入时，镜头从该头像拉开至协作全图。选中的点线沿记录方向流动，发起端显示最近一条协作摘要。系统开启减少动态效果时直接显示静态全图。
协作全景默认同时展示参与者与空闲 Bot。按住画布或头像可左右拖动，触屏可横扫。未选中 Bot 时回放最近有记录的交接，依次聚焦发起者、传递光点并显示消息；手动拖动暂停回放，可在画布右上角恢复。
