## 现在能做什么

Bot 不另做一套安全规则。它用实验室里已经有的权限、审批、隔离和敏感路径拒绝。人能改的是这只 Bot 自己的那一层。

每只 Bot 有自己的权限档位、工具范围和技能范围。新的主对话默认是自动：按规则能做的就做，该问人的仍问人。改成完全放行必须再确认一次。请求里没带这次确认，服务器拒绝，档位不变。其他档位不用二次确认。入口在对话头部，打开的是这只 Bot 已有的权限、工具审批和允许名单，不建立第二套授权。

自动档允许的操作按自动规则走，原本要审批的仍要审批。完全放行只在二次确认之后生效。同一只 Bot 新开的任务沿用它，不重复确认。更严的档位和计划模式保持更严。计划模式禁止的执行和委派仍然禁止。跟随旧的默认放行时，打开设置有警告，可以一键改成自动，不擅自改。跨 Bot 委派用目标 Bot 的档位。声称身份来提权会被拒绝。

工具允许名单和技能允许名单是另一层。工具名单空着表示不额外限制。技能名单空选并保存，则是一个都不用。权限档位传给子任务，不会把名单外面的工具一起带上。完全放行也不取消数据边界和隔离。已经挂着的审批不会因为切档或新建子任务被自动批准。

需要人点头的操作，展示来源任务、要做什么、影响谁、实际将要发出的内容或配置变更。凭证打码。看不出副作用的，要求人核对，不默认通过。批准或拒绝之后，对话、列表和任务详情一起更新。无人处理的审批在十分钟后过期。过期是失败，不是成功。明确批准之后，从原来的工作继续。批准这个动作本身不等于工作已经做完。群里的审批默认转到这只 Bot 的私聊。群内原位批准要单独打开，默认关闭。

同一套工具被原样调用很多轮，或目录浏览、代码搜索次数太多时，弱模型会被打断。强模型默认不会。设置在「对话默认行为」里，三项：仅弱模型、全部模型、关闭。仅弱模型是默认。本地演示模型，以及名字里能认出偏小、偏快那一类的模型会停。其余模型和认不出来的名字，不停。全部模型时，强模型也停。关闭时，谁都不因为重复或查看次数停。保存后下一轮生效，不用重启，也没有单独的环境开关。

关掉重复检测，或对强模型不生效时，这些限制仍在：打开图形界面、没有深度上限的扫盘、读取环境文件这类敏感文件、隔离、该有的审批。同一次调用用同一组参数连续失败也会停。那是失败，不是重复。换着参数失败不共用这条熔断。没有工具调用、只是重复同一段正文，也跟重复检测同一个开关。停住时要能看出是重复检测，还是这次调用失败，而不是一句笼统的工具循环。

失败时不假装做完。模型说做完了但核对没有通过，目标不算完成。核对暂时不可用，就标成受阻或写明证据待查，不宣称完成。外部系统的结果还不知道，就停住等人核对，不自动再执行。连接断了，说不能确认，并留下上次更新时间，不显示成空闲或完成。没有账单回执，费用是未知。部分成员失败时，做成的留下，只处理失败的那个。配置保存失败时，原来的配置仍生效，编辑内容留着，可以重试，不显示假成功。未知工具会说明没找到，并给出接近的名字，不会让这一问悬空。

模型在对话的模型设置里填写服务地址和密钥，然后发现可用的模型名字，再选一个。也可以不配密钥，用本地演示模型做能力检查。演示模型不代表真实回答质量。每只 Bot 可以固定一个已配置模型，或跟随全局默认。可选再接一个看图模型。含图的用户回合可以走看图模型。没接、或当前模型不识图时，按对话章的规则说明不兼容，不假装看懂。第三方服务若不接受严格的结构化输出，可以关掉这一项，这是连接设置，不是功能开关堆在环境里。

人能碰到的工具包括读文件、改文件、跑命令、待办、子助手、队友之间的消息、后台任务和技能。文件查找、网页抓取、外部工具服务和编辑器辅助是接上之后才有。没接上或不健康时说明限制，不因为仓库里有这个模块就假定能自动调用。可选的外部编程助手要单独打开，并且默认每次需要批准。本机要有对应的命令。产品书没有把它写成 Bot 默认会调用的能力。

跑命令时可以套上本机隔离。在苹果电脑上阻止进入密钥和云凭证目录。在 Linux 上用命名空间隔离。系统不支持时，退到去掉危险注入的环境清理，不假装已经隔离了整台机器。隔离方式在实验室的命令沙箱里保存。保存成直接运行时，命令不再套系统隔离，也不再为这一项单独审批。保存成系统隔离时，即使当次要求直接运行，仍走系统隔离，并在结果里说明原因。保存成自动时，可以自选。省略则用本机最强的可用隔离，直接运行仍须审批。容器隔离还没实现。保存或指定成容器时，命令不运行，不会当成直接运行或系统隔离。工具结果里的密钥值会被打码。读取被禁止的路径，或名字像环境文件、私钥、凭证的文件，会直接拒绝。

语言有中文和英文。新增说法两边一起加。语言记在浏览器里，不靠环境变量。产品策略优先在实验室里保存，保存后按该项自己的范围生效。密钥、上游地址和进程启动仍按部署需要管理。改了进程级配置后要重启才进新进程。

桌面端是一个系统窗口，里面带上服务和网页控制台，状态放在本机用户数据目录。托盘可以打开配置。打包产物覆盖苹果芯片的 macOS，以及 Linux 的两种常见架构。Windows 和 Intel 版 Mac 不打包。自动构建的苹果安装包没有签名和公证。系统若提示损坏，那是隔离属性，不是文件本身坏了。需要先去掉隔离属性再打开。这是接触产品的一种方式，不增加 Bot 功能，也不等于已经上架。

接入方可以把回合循环嵌进自己的程序，也可以嵌整套运行时。只嵌循环时，不自带网页控制台、命令行和桌面端。浏览器和扩展里的宿主只能用精简档，不能用依赖本机能力的完整档。要审批、外部工具和调度时，用完整运行时，自己提供状态目录和工作区。这是给接入方的稳定做法。产品书没有把它写成普通用户在界面里的一项开关。

本机桌面操作可以在「设置 → 工具 → 本机桌面操作」里打开，保存后生效，不用为这项新增环境变量。运行前本机要装好对应程序和已签名的对话应用，并且桌面已解锁。授权请求进入审批列表。批准后只在这场会话里有效。子助手和定时任务触发的回合不复用这次授权，仍要逐次审批。浏览器能力和音频没有启用。停止会取消还没发出的操作。已经发给系统的动作撤不回。

## 从哪里进入

权限从 Bot 对话头部进入。重复检测和回顾、下一句建议的开关在对话默认行为里。模型在对话的模型设置里发现和选择。命令沙箱的隔离方式在实验室的命令沙箱设置里。语言在工作台的语言切换，以及更多里的语言设置。桌面端从安装好的应用和托盘进入。嵌入由接入方在自己的程序里完成，不在 Bot 列表里。本机桌面操作在设置的工具里。审批出现在对话、列表和任务详情，群里默认转到私聊。

## 现在还不能当成已经交付

完全放行不是取消一切限制。容器隔离没有实现，不能写成可选的现成隔离。外部编程助手默认关闭，打开后也不是免审批。本地演示模型不能当成真实模型质量。看图模型是可选连接，不是每只 Bot 都已具备。

本机桌面操作的开关和审批路径已经写在说明里。同一份说明写明：运行检查通过不能代替实际桌面验收。当前本机的应用版本组合不是上游已测试组合。升级后要复测。真实验收要能在本机建成一份指定文字的文档，并由独立读取核对，还要确认截图真正到达模型。协议演练和界面开关测试不能代替这一步。因此不能把「可以操作用户的整个桌面」写成已经认证的交付。

桌面安装包没有公证，不覆盖 Windows 和 Intel Mac。嵌入文档写的是接入方用法，不是已交付的托管云服务。可选的实验室登录和跨域设置是部署项。产品书没有写成面向所有用户的账号体系。发布验收仍未完成。单机软件通过不等于这台已经安装的环境已经升级，也不等于可以对外发布。

路线图里的合规行业包、配额计费和服务等级，不是现在的安全功能。

### 夜间运行可靠性

受限技能的能力边界按普通请求隔离：新请求不继承上一请求加载的限制；重启、重试和转向仍保留当前边界。缺少加载来源的继承权限保持保守限制。实时回复以已保存消息 ID 关联正文、思考和工具片段，历史刷新后只显示一份；下一轮相同文字仍持续可见。本机资料采集的目标彼此隔离，单个任务删除或更新失败不会阻断后续任务。见 [验收标准](../../../acceptance/night-runtime-reliability.yaml)。
