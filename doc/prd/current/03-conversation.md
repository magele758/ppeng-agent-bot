## 现在能做什么

在桌面浏览器的「设置 → 通用 → Bot 桌面通知」开启并允许通知后，保持 Agent Home 标签页打开。Bot 完成工作、提问或等待审批时会提醒，点击可回到会话或 Bot 任务页。首次打开不会补发已有状态。

登录检查超过八秒会提示重试；如果网页脚本没有启动，加载画面也能重新打开首页。

Bot 侧栏只读取屏幕内会话的最近问题，滚动后再读取新出现的行。点选会话直接加载该对话，后台任务列表继续按原节奏刷新。

人对 Bot 说的话都进它的主对话。这条对话不更换身份。压缩是把较早的内容收成摘要，留在同一条里。回复可以边生成边出现。推理过程、工具信息和长内容按需展开。助手正文用可读的排版显示，不是一整块纯文本。

只有整句是命令时才生效。一句话里顺便提到这些词，仍是普通消息。没选中 Bot 的普通对话，以及没绑定 Bot 的外部消息，不会被当成 Bot 命令吞掉。选中了 Bot 再发，作用在它的主对话上。带着附件时，这些文字按普通消息发送，不执行命令。已经绑定某只 Bot 的外部入站，同样作用在它的主对话上，命令不交给模型。

整句 `/new` 不新开对话，只把较早内容压进同一条的摘要。整句 `/stop` 停止当前回合，对话还是原来那条。整句 `/model` 后面跟上已配置的供应商和模型，改这只 Bot 以后使用的模型。`/model default` 或「跟随默认」改回全局。名字不存在，或同一个名字对上多个模型，拒绝修改，原来的模型不变。

压缩看的是这只 Bot 真实模型窗口，不是一条被挤过的历史预算，也不是模型没报窗口时误用的一个固定小数。不到窗口一半，不压缩。到了一半，做一次结构化摘要，覆盖目标、约束、进展、决定、涉及的文件和后面的步骤。下一份摘要在上一份上增量更新，不把整段历史从头再总结。到了窗口的大约百分之八十五，再做一次更短的压缩，只留更近的原文。没配对完的工具调用不能被拦腰截断。已经配对的调用和结果不能拆开。被替换的原文仍留着，会话搜索还能找到摘要。普通对话不受这两档影响，仍走原来的压缩点。普通会话的历史上限仍是模型窗口的大约两成。

Bot 还在这一轮里工作时，下一句先收下来，马上出现在对话里，并在下一步改方向。不会为了这一句再开一个执行者去抢主对话。同一输入不会做成两件工作。只保存、没有要求运行的消息，不会因为当前回合结束就自动执行。待审批、已取消或待人工核对时，追问不能绕过这些状态自动续跑。发出后应立刻出现在对话流里，不重复，并滚到新消息。发送失败时，文字回到输入框。

人在忙时提交的任务要能看见：已接收或在排队、排队数量、可以取消。排队、执行、等人、受阻、待核对、完成，在对话、列表、活动栏和任务详情里说法一致。执行结束但目标还没达到时，不显示成完成。和服务器断开时，界面说状态暂时不能确认，并留下上次更新的时间。不把失联显示成空闲或完成。恢复后显示最新状态。

引用是一块有名字的操作。输入区显示作者和最多三行摘要，可以取消。取消只拿掉引用，草稿还在。发出去之后仍指向原来那条回复。定时任务的结果用一张卡片：任务名、能读懂的状态、结果摘要，以及查看详情。内部标记、运行编号和很长的历史默认收着。普通用户写的字不会只因为长得像这些标记就被藏起来。

主对话里已经有的图片，后来换了不识图的模型，旧消息和旧图仍能看，对话不会因此一直失败。这一轮又贴了当前模型不能看的图时，界面说明不兼容，不悄悄丢掉，也不假装看懂了。图片可以随消息带上。热图太多时，会收成一张总览，便于继续看。

Bot 回复结束后，输入框是空的，可以用淡色字显示下一句建议。这行不是已经打进去的内容。按 Tab 才把它变成可以继续改的真实输入，再发送。还可以有一到两条备选，再按 Tab 换成下一条，到最后回到第一条。不按 Tab、直接打字，建议马上消失，打出来的是自己的字。按退出、把消息发出去、输入框里已经有字，或输入框失去焦点，建议都消失，不会被一起发出去。开关在对话默认行为里，默认开着。关掉之后再回复，不再生成。

建议由模型根据这场对话生成，指向具体的下一步，正文最多五百字。没有合适行动就为空，不用固定套话填充。同一轮最多问一次。空结果和失败也不在同轮反复再问。建议会保存。切换会话、刷新或重启后仍可读回。新一轮完成后生成新的。旧轮迟到的结果不能覆盖，也不能串到其他会话。

对话进行了至少三轮、上一轮结束至少三分钟、并且离开过这个页面再回来时，输入框上方出现一行回顾。这行优先由当前会话所选模型根据最近几轮写成，说明刚刚做到哪了，即使进程启动时的默认模型不可用也能生成。一行最多四百字。它只给人看，不会变成一条对话，也不会发给助手。模型没写成时，这行会说明这次没回顾成。同一段进展只自动出现一次。接着聊过之后，再离开够三分钟，才会再来一行。不到三轮、还在打未发送的字，或者助手这轮还没结束时，不会自动冒出来。

发送整句 `/recap` 或 `/回顾`，或者点「回顾这段会话」，马上看到同样的一行。这句话不会发给助手，没离开过也可以。整段回顾的开关在设置的行为里，默认开着。关掉之后，输入框上方不再出现回顾，也不会再让模型写这一行。这时再发整句 `/recap` 或 `/回顾`，会当作普通消息发给助手。自动回顾可以单独关掉，默认开着。只关掉它时，回来不会自动出现，当场回顾仍然可以用。整段关掉时，这个选择先留着。

最近一次已经发给模型的请求，要能看到估算的输入长度、占模型窗口的比例，以及这次请求的时间。这个数包含系统侧说明、工具定义和最终送出的消息。发送前的预览、发送时的估算、上游报回来的实际用量、历史累计，四者分开。缺了就显示未知或等待，不用累计用量冒充这一次的长度。已经结束的轮次可以显示本地结束时间，最后一轮标为会话结束。进行中或缺少有效时刻时不显示。这里是结束时间，不是消息发送时间。

思考力度在设置的行为里，四档：关闭、低、中、高。默认关闭。关闭时，发给模型的对话请求不带力度，和加上这项之前一样。选低、中或高后，下一轮对话按这一档要求模型思考，重新打开设置仍是这一档，不用重启。摘要和系统自己的内部判断不带这个力度。上游若不接受，改回关闭。这和模型目录里已有的开、关、自动不是一回事。那个只决定用不用带思考能力的模型。

纯回复语言上的偏好留在对话里，不因此另建一件长期目标。明确的目标修改和真正要做的开发要求，仍按原来的意思处理。

实时插话立即保存到对话，模型下一次请求读取。若插话到达时模型仍在生成旧计划，旧计划的工具启动前也会检查转向：明确停止或改用其他执行方式而冲突的工具会被取消，独立工具继续。普通补充不取消工具；判断失败或五秒内没有结论时保留工作。下一次模型输入会明确标记最新插话并要求回应和调整冲突计划，原始聊天记录不改写。此提示不代表模型必然遵从；已执行的外部操作也不会被回滚。

Bot 目标的结束检查同时核对原目标与本次执行中的全部用户插话，按顺序区分新增要求和被后续指令替代的要求。逐条结论缺失、地址未给出等遗漏不能算全部完成；有新进展时在原有运行预算内继续补齐，不限于一次纠正。撤回内容和其他执行者转述不成为新要求。真实阻塞、无法核验或没有进展时仍保留未完成状态，不以推荐下一句代替交付。

## 从哪里进入

选中一只 Bot，在主对话底部输入。命令整句发送。引用从一条回复上发起，在输入区里取消。下一句建议出现在空的输入框里，用 Tab 采纳。回顾出现在输入框上方，或通过 `/recap`、`/回顾` 和「回顾这段会话」当场打开。开关在设置的对话默认行为里。思考力度在设置的行为里。用量跟在已结束的轮次上，和累计分开看。打开一场会话，在标题栏点「收藏」；之后在左侧「收藏」分组或「只看收藏」里找到它。

## 现在还不能当成已经交付

输入区左侧再去掉加号、会话设置、模型和工作区、只留 Bot 头像，是草稿，现在还没做。用户气泡改成这只 Bot 的主题色，也还没做。产品书没有把「任意聊天软件都能双向控制」写成已经交付。图片能力依赖当前模型是否识图。没接看图模型时，不能把旧图历史说成已经识别成功。

会话回顾和下一句建议的软件行为已经验收。它们不保证模型每次都写出有用的一句。模型没写成时，回顾会说明没回顾成，建议可以为空。真实模型的长期质量不由这些检查代替。

### 控制台刷新与异常诊断

会话列表轮询使用 `GET /api/sessions?view=summary`，只返回列表所需身份、状态、时间和归属字段；完整接口与会话详情保留原有数据。未改变的摘要返回 304，重叠的概览刷新共享一次请求。打开会话或 Bot 时不携带累积的内部运行日志和检查点；概览列表不等版本与健康状态返回即可开始加载。停留在对话页时只定时刷新会话、Bot 和待审批，切到任务、日程等页面时立即补读对应列表；在途相同定时请求合并复用，保存修改或用户动作触发的读取单独发送。标签页切到后台时暂停普通定时读取并放慢工作状态轮询，回到前台按是否有新活动补读；空闲会话放慢轮询，Bot 空闲时工作状态两秒一轮、工作时一秒一轮。工作状态刷新不反复扫描整库已结束会话，单次抖动保留最后状态不弹提示，持续失败时区分超时、服务错误和网络故障，断线提示以浮层展示上次更新时间，不挤占页面布局。参见 `lab-startup-request-load`、`bot-status-polling` 与 `group-chat-stable-layout`。

追问时，发给按请求开头做缓存的 Chat Completions 服务的请求保持开头的稳定系统说明与上一轮用户消息之前的历史对话逐字节不变；每轮变化的动态上下文与运行时通知随最新一条用户消息的最前面送达（带图片时排在图片和原文之前；无用户消息或未标明稳定前缀时仍放开头系统消息），复用已缓存前缀。参见 `bot-followup-cache-prefix`。

当前会话的标题栏可以一键收藏，再点一次取消。收藏写在这场会话上，重新打开列表还在。已收藏的会话单独出现在「收藏」分组，也可以只看收藏；一场收藏都没有时，列表说明没有收藏的会话。保存失败时仍是上一次的收藏状态。不是是否收藏的取值不会改掉原来的收藏。

浏览器未捕获异常、未处理 Promise 拒绝与 React 渲染异常记录时间、页面路径、会话 ID、构建版本、浏览器和堆栈，发送到同源 `POST /api/client-errors`。本机日志位于 `stateDir/logs/client-errors.jsonl`，达到约 2 MB 轮转为 `.1`；不主动采集对话或 DOM，移除页面查询参数并在服务端脱敏环境密钥。单页最多报告 10 种异常；上报失败静默处理，不能保证离线时保存。渲染失败提供重新加载入口。构建保留浏览器 source map，用同版本 `.next/static` 对照堆栈定位源代码。参见 `lab-poll-crash-diagnostics` 验收规格。

在后台复盘或检查待派送目标时，已有明确归属的 Bot 只检查主会话是否存在，待继续的目标只检查对应父会话下匹配的子会话，减少打开历史时与后台调度争用的时间。
打开 Bot 后，历史正文与工作台概览分别加载，任务列表返回前即可阅读正文。参见 `history-startup-contention`。

同一用户重新与同一 Bot 单聊时，可以按关键词找回同一租户内旧单聊的决定并展开原文。匿名会话、房间和子任务仍沿用各自的历史访问范围。用户手动压缩、Bot 调用压缩工具和后台压缩都为模型保留一分钟的摘要时间。

Bot 对明确要求逐字确认的任务切换或事实更新回复「收到」。询问先前检查记录的编号时，Bot 可在当前可见的历史工具中搜索并按稳定引用展开原文。遇到多个来源时，由模型结合上下文判断；历史读取继续经过会话权限与工具执行流程。

会话列表的「Grok Bot（本机）」可读取 Mac 桌面应用的本地缓存。首次使用时选择缓存目录；支持记住目录且仍有读取权限的浏览器，下次打开来源时会重新读取。历史消息按缓存中的原顺序展示，附件显示名称。读取在浏览器内完成，不会创建 Lab 会话。

明确查找旧会话原文时，Bot 使用当前可见的历史检索与原文读取工具。准备查找时先等关键词；读取被拒就报告无法核实。执行日志在同一会话内按调用 ID 核对回执，包括先落盘的结束事件。
单聊和群聊中，仅当鼠标悬停 Bot 回复时显示引用操作及该条回复保存时的本地日期和时间，精确到秒。Bot 单聊的同一次回答分多段保存时，各段共享一组时间、纠错和引用操作，时间取最后一段正文的保存时间。

对话页可以按消息正文搜索，入口和「搜索 Bot」分开。`GET /api/search/messages?q=&limit=` 只查当前用户可见会话的消息正文，返回短摘录；空白查询不扫描，默认 20 条，最多 50 条。点击结果打开对应会话。参见 `message-body-search` 与 `message-search-ui`。

普通聊天隐藏运行时的压缩摘要，模型视图保留摘要用于检查。Bot 的任务执行指令按当前有效执行筛选；历史摘要提到的 Goal 以任务库现有状态为准，已完成任务的结果可作为经验查阅。

定时任务的触发消息在普通会话中显示为一行任务名。点击可在弹窗中查看当次指令和随附资料，关闭后回到原消息。详情以文档形式显示，采集摘录中的 Markdown 标题、列表与表格按原文排版。
