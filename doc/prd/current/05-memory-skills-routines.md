## 现在能做什么

记忆、技能和定时任务都挂在一只 Bot 上，并且分得清是谁的。普通对话仍可以读写共享的用户记忆。那是另一层。一只 Bot 只能读到自己的私有记忆。另一只 Bot 的笔记不会出现。子任务能用父 Bot 的记忆，但改不了父记忆，也进不了共享记忆池。群里的内容怎样进后来的单聊，只包括这次真正推送给它或它自己取回的部分。

详情和记忆页默认显示能读的摘要、记忆类型和来源数量。正文和完整来源按需展开，不用内部名字铺满页面。文件来源能打开或预览。消息来源能定位到那条消息。没有权限或不存在时说明原因，不跳到无关的地方。记忆条目显示范围、来源、更新时间，以及最近的替换记录。旧值不继续参与正常召回。人说「这次先这样、以后不用记」时，这句话不进自动抽取，运行时也拒绝把它写成长期记忆。人明确纠正时，不把互相矛盾的旧内容和新内容拼成一条。密钥和令牌的原文不在界面上显示。人可以纠正、删除或撤销相关记忆。

文件与资料页集中查看这只 Bot 相关的历史产物和材料，可以打开允许访问的目录。工作区决定文件操作范围。路径不可用或越界时，不能悄悄换到另一个目录执行。

长期历史可以分页看，压缩之后仍是同一只 Bot。重启后身份还在。这些检查覆盖来源、权限、预算和身份延续。它们不等于无限长对话的模型质量，也不保证每次都能召回很久以前的一句。

详情里能看到这只 Bot 有权使用的技能：自己的、别人共享给它的、历史共享的、公共的。没授权给它的其他 Bot 私有技能看不见。每一项能看出来源、属于谁、是不是只读、现在是启用还是受限。同名的几份要能分开，各自看说明和正文。可以按名字或描述搜索。没有结果时是空状态，可以清掉搜索，不要说成加载失败。仓库里的技能说明，以及本机按约定目录放的技能说明，会按名字合并。同名时本机那份盖过仓库那份。具体每一份技能叫什么、用来做什么，不在这篇列举，见脚本生成的技能对照。

使用范围可以收成一份允许名单。一个都不选再保存，就是一个都不用，不会悄悄变回全部启用。保存后，后面的搜索和加载按这份名单。刷新和重启还在。还没保存时有提示。换 Bot 不会把没保存的选择带到另一只身上，也不会自动保存。保存失败要说原因，不显示成功，不覆盖已经生效的配置，没保存的选择还留着。

自己的技能可以指定给哪些 Bot。接收方下一轮的搜索和加载跟着变，但仍受它自己的使用限制。界面要写出为什么还是不能用。别人共享来的，只能决定自己用不用，不能改原文，不能转共享，不能撤销别人的技能。撤销自己的技能后，所属 Bot 和所有接收方都不能再搜索和加载。已经出现在历史对话里的正文不会因此消失。同名多份各自保存。只给了一个有歧义的名字时，要求人选择，不默认加载其中一份。历史技能保持原来的可见范围，并标成历史共享。要改归属或共享对象时，人必须先看到将要保存的范围。窄屏上，使用范围、保存和搜索分区清楚，字不能被裁掉，长说明在面板里换行。

功能分组和全局可以各有一套共享条文。同名时，分组盖过全局。其他分组、其他用户的私有信息不混进来。页面读回的是保存之后的内容。这只 Bot 下一次请求用的是更新后的有效内容。加载失败不显示成「已经加载、但是空的」。保存失败不报成功，也不把旧范围的内容写进新范围。失败可以重试，正在编辑的内容还在。功能分组不是群聊，也不是团队任务。它用来在列表里收纳，并作为技能或共享条文的范围。

定时任务跟这只 Bot 走，使用它的身份、模型、允许名单和权限。主对话正忙时，任务进入插话队列。正在等审批时暂缓派发。不是 Bot 的定时任务仍使用独立的工作会话，不抄走某条主对话的全部历史。Bot 主对话已经显示本次结果时，不再追加一份相同摘要。运行记录仍保留结果和消息链接。引用结果继续问，不会重跑工作。结果只覆盖这次执行，不混入旧摘要、回顾或下一条用户消息的回答。

没有新情况时可以静默：不往主对话发摘要。已经在主对话里的这类回执也不再显示。历史里仍能看到这次运行，并标成静默，而不是成功。标记只出现在正文中间时，结论仍会送达并显示。预检不通过则跳过，不调用模型。检查因为来源权限被拒绝时，运行记录说明具体原因和怎么授权。即使模型回答「没有新情况」，也不能把没执行的检查算作成功静默。

详情里可以打开和关闭一条任务。关闭期间到点不跑。打开后按原来的下次时间继续。失败时，开关和「还会不会跑」都保持操作前的状态，并说明失败。人能看出这是只跑一次、循环，还是等事件。循环任务能查看原来的时间表达式。改完保存后，下一次按新计划。取消不改变原计划。无效输入或保存失败要说明，不因为打开编辑就马上多跑一次。同一只 Bot 上，另一个用户看不到、也改不了这条任务。安排一条新的定时任务如果按现有规则要人确认，确认之前到点不会跑。

错过该跑的次数会补、结果不明会停住核对、租约恢复按持久的运行记录处理。该送达的至少送达一次。错误投递不会假装已经送到。发送前的批准和工具操作的批准是两回事。批准一份报告不能顺带授权新的工具调用。

已经完成的一次交付可以另存成定时任务。表单带上来源交付、做了什么、时间、时区和输入从哪来，输出到这只 Bot 的主对话或一个已授权的群，以及通知策略。来源版本只作参考，每次运行重新取输入。保存后可以再打开编辑。

通知按报告全文比较有没有变化。选择仅变化时通知，没变化就不重复发汇总。连续失败没到配置的次数时，留下每次记录，不发汇总。达到次数后提醒。已经存在的自动暂停保护触发时，马上提醒。自动发出去的报告可以先进入待审。批准只发送已经看过的这一份，不重新跑模型，也不额外批准工具。拒绝、重复批准、重启之后，都不会把没看过的内容发出去。

实验室的定时任务表单可以关联原来的工作目标，再填写当前做法说明和可选的后台任务。保存后马上生效。执行时重读工作修订和做法。原来的工作约束优先，已有的工具授权不扩大。做法说明读不到、外部任务身份失效，或这一轮没有成功观察到，就明确记成受阻或未核验。不能把模型说的「没有更新」算成成功巡检。观察时间保留证据自己的时间，不用打开页面的时间去刷新它。只有关联目标按现有核对完成或取消，才自动停用这项临时盯梢，历史仍留着。长期健康检查选择独立的长期巡检。已有任务不会靠猜文字自动改成关联工作。解除关联后，还没开始的运行也用最新设置。

需要等待一个真实后台任务时，等待和原工作绑在一起。恢复后先读取实际结果，再核验提交、报告和剩余步骤。进程退出不代表交付完成。取消或修改原工作，不会假装后台进程已经停了。仍在跑或无法核验的，先收口后续安排。关联的后台盯梢必须拿到这一轮对应任务的真实检查。其他任务、旧身份、缺少检查，不能得到健康静默。只是重读旧记录，不会刷新观察时间。检查期间的执行失败要明确报告。

旧的定时任务如果缺少后来加上的附加设置，自动化面板仍可打开和编辑。

## 从哪里进入

记忆、技能、文件和定时任务都在这只 Bot 的详情页签里。共享条文在分组或全局的共享范围里维护。技能允许名单在技能页保存。把一次交付存成定时任务，从该次交付进入表单。临时盯梢和长期巡检在定时任务表单里选择。运行记录里核对将要发出的报告，再决定发不发。单只 Bot 的定时任务不放到团队任务页里改。知识与记忆页用来检查来源、维护事实和偏好。

## 现在还不能当成已经交付

定时任务改成拨动开关、时间一律按本地钟点显示，仍是草稿。现在是打开和关闭，不是那份草稿里的新控件。产品书没有把跨渠道消息总控、岗位套餐或自动代发写成已经交付。真实模型能不能长期记住，要另行验证。软件检查不承诺无限长对话。

技能对照表由脚本生成，本篇不列每一份技能。没保存过的路由方式才回退到运行配置。严格加载时，当轮只能加载已经进入候选的技能。这是运行策略，不是一份新的技能市场。

完整数据迁移没有标成已实现。临时要求不应当自动变成永久偏好；这一点已经做到。不能把「用户离不开」写成已经度量好的商业结果。

### 自建技能与搜索后加载

严格加载下，Bot 可按名称或 ID 直接加载自己已启用的技能；其他技能可通过 `search_skills` 搜索后，在同一会话加载最近搜索命中的结果。两条路径均保留技能归属、共享、启用状态和允许名单检查。短名单是推荐入口，不再阻断这两条恢复路径。见 `skill-load-recovery` 验收规格。
