## 现在能做什么

这里写用户现在能碰到的产品，给人和编码助手一起读。它不是设计笔记，也不是根目录说明的缩写。根目录说明怎么把程序跑起来、代码放在哪；Bot 产品书写每一条交互规则；这一组说明只回答三件事：现在能做什么、从哪里进入、哪些说法还不能当成已经交付。

产品以 Bot 为日常入口。人找到一只 Bot，说清想要的结果，在同一条主对话里看进展、补决定、拿成果。任务、群、记忆、技能、定时安排和外部软件，都挂在这只 Bot 上，而不是要求人先学会一套内部名词。普通对话还在，用来看旧会话和子任务，不再和 Bot 并列成另一套产品定位。

下面七篇按人使用的顺序写。每篇都分成四节：现在能做什么、从哪里进入、现在还不能当成已经交付、依据。依据只指向产品书和已有说明，不另写一套互相打架的规则。和产品书不一致时，以产品书里已经按验收写成现在时的章节为准；产品书标成草稿或只批准未完成的，这里放进「还不能当成已经交付」。

1. [产品是什么](01-product.md)：给谁用、Bot 和普通对话差在哪、商业说法里哪些还不是现成功能。
2. [Bot、名册与工作台](02-bots-and-workspace.md)：身份、列表、详情、子任务入口和目标面板。
3. [主对话](03-conversation.md)：命令、图片、插话、回顾和下一句建议。
4. [目标、协作与外部软件](04-goals-and-collaboration.md)：目标、子任务、群、协作，以及已经能用的软件连接。
5. [记忆、技能与定时任务](05-memory-skills-routines.md)：记住什么、技能怎么共享、到点做什么。
6. [安全、模型与运行方式](06-safety-and-runtime.md)：权限、审批、失败时不假装完成，以及模型、工具、隔离、桌面端和嵌入。
7. [自愈、演进与平台能力](07-evolution-and-platform.md)：自愈、演进、领域包、对话里的交互卡片、研究与编排里文档写明已有的部分，以及写明还没认证的部分。

仓库技能的名称和用途不写在本文件。对照表是 [skills.md](skills.md)，由脚本从各技能说明生成，不要手改，也不要在这里列清单。改了技能说明之后重新生成即可。

读的时候先看「现在能做什么」。商业口号、路线图阶段和「模块在仓库里」都不是交付证明。单机上的软件验收通过，也不等于真实模型的长期质量、长时间运行、实际安装升级或生产发布已经完成。

## 从哪里进入

打开产品后，首页和无效地址进入 Bot。导航里仍有 Bot、普通对话、智能体、任务、知识和设置。已经存在的普通会话和子任务打得开。专业配置在设置和运维里，不是做第一件事的必经步骤。

桌面窗口、命令行和嵌入到自己的程序，是另外的接触面，写在安全与运行、自愈与平台两篇，不改 Bot 主路径的含义。

## 现在还不能当成已经交付

不要把下面这些写成用户现在可以：

- 产品书里的草稿：输入区再瘦一圈、定时任务改成拨动开关并一律显示本地钟点、群成员管理离开主聊天区、用户气泡改用 Bot 主题色。
- 只批准、还没标成做完的发布验收，以及跨机器连续盯梢的组合验收。
- 二十四小时虚拟员工、黑灯软件工厂的岗位套餐、无人值守和可用性承诺。
- 路线图后几个阶段：更多行业包、知识炼油、无中心电脑矩阵、工业级租户与服务承诺。
- 自演进流水线。根目录说明写明它已停止维护，不能当成仍在交付的产品。

技能对照表即使还没生成，也不要在本章补一份手工清单。
