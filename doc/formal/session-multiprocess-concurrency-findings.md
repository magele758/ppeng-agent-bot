# 多进程并发验证发现（2026-10-19）

首次扩展只新增验证，保留了下述原始失败。随后用户独立批准五条修复标准；修复已完成，两份验收均为 implemented，原 15 条及原三组标准的 Given/When/Then 不变。当前绿色证据见文末，原始红色证据不覆盖。

## 方法与判定

真实 RawAgentRuntime/SQLite 在同机共享临时库的不同 OS 进程中执行，控制模型/工具 I/O；观察屏障只暂停原代码的调度。重试场景观察真实重试计时注册，并控制计时回调继续的时机，固定竞争窗口。覆盖 chat/task、初次争抢、存活占用、结束与 SIGKILL 后接续、迟到模型/工具、释放读写窗口、部分/最后审批、双恢复与取消顺序。没有直接写 SQL 构造状态。审批后的迟到恢复执行生产 daemon 的 shouldResumeAfterApproval 判定，未运行完整 HTTP handler、鉴权或连接排空。

独立有界模型：2 个并发进程、2 代占用、2 项审批及工具；通过不代表产品并发安全。未覆盖多机、网络文件系统、数据库损坏、任意调度、外部恰好一次及 Bot 专用队列。

## 已复现产品问题

| 编号 | 场景 | 实际结果 | 对应原验收 | 拟修复标准 |
|---|---|---|---|---|
| F-1 | 两进程初次争抢、存活占用、结束/退出后接续 | 第二个请求覆盖占用并进入模型；没有明确拒绝竞争者 | AC-1、AC-2、AC-4 | 修复 AC-1 |

## 通过的对照与验证器检查

竞争进程仅启动时不改写存活持有者；过期运行的显式 append 被 writer mismatch 拒绝；已在旧占用之后读取状态的简单 stale release 不影响当前持有者（但读写竞争窗口仍失败）；相同/相反的部分审批决定保持一个决定并继续等待；已保存 a 的结果保留、未确认 b 不被伪造成功，模型视图与 transcript 配对；不同会话可独立完成。

三种实际源码变异仅在隔离子进程加载：启动重复执行、旧释放无条件清占用、重复审批继续消息。每种都须让绿对照新增失败，源码指纹不变且恢复基线一致。已有红例不算检出变异。

首次 15 个测试在实现验证器前因缺少模块全部失败。实现后暴露的报告审批 ID 不确定排序已在验证器层修正：先按真实审批与工具关联再规范化，保存原始连续性检查；未修改审批决定或放宽行为断言。缺少进程、IPC 阶段、超时或证据时均须 incomplete 并非零退出。

## 已批准修复与最终结果

五条修复测试先全部失败，再全部通过。执行占用以新的运行 nonce、SQLite 条件更新和 OS 持有的代际锁共同判定；旧异步上下文不能在空占用或新占用下写消息、结束原因及状态。SDK 与参考内核等待异步结束处理落盘后再释放，竞争失败不删除当前执行者控制器。审批决定、状态和唯一继续消息一并提交；暂停保留 checkpoint，但恢复重新争抢新执行资格。取消覆盖全部决定已存但尚未执行的窗口，派发下一工具及发送流式内容前检查取消/代际。

原 58 个场景全部保留，另增加启动持有者退出而另一写入者仍活着、非启动写入者退出而原启动持有者仍活着的 chat/task 检查，合计 **62/62**；另检验显式新输入可继续，旧审批在新工作结束后仍不能复活。真实旧流通过 runTurnStream 先复现迟到内容，再修复；SDK 竞争失败误删控制器也有独立红绿测试。

最终重启 **43/43**、生命周期 **20/20**、配对门禁通过，四组源变异均通过且恢复一致。Core **2901 通过、0 失败、3 个环境跳过**；SDK **408/408**、构建通过；带标签验证/修复及原重启修复测试 **24/24**；形式化相关原单测 **25/25**。Node 22 的九个真实场景和六个 store/stream 单测通过。详见 [修复证据](session-multiprocess-concurrency-fix-evidence.json) 与 [修复汇总](session-multiprocess-concurrency-fix-summary.json)。
