## 哪些应阻断合入，哪些适合集中执行

| 检查 | 每个PR／集成候选必须有的证据 | 可集中批量执行的部分 |
| --- | --- | --- |
| 类型、构建、SDK／包契约 | 改动相关构建、公开API契约、SDK技能同步 | 发布候选补全所有分发形态；同次验证中复用可信构建产物 |
| 功能单测与验收 | 新增/受影响行为、原批准标准的真实通过结果；不把静态标签扫描当运行证据 | 多个待合入变更组成固定候选后跑一次完整回归；不能先合入再补关键验收 |
| 审批、权限、隔离、存储、取消、重启、多进程 | 变更相关源码、依赖、构建配置、验证器或测试时，完整关键验证仍阻断 | 输入未变的同一候选中共用一次完整探查，保留各项标准和反向控制的独立判定 |
| E2E | UI/API关键纵向链路，状态/数据/权限断言 | 不同独立套件可分片；每片独立daemon、SQLite、端口和输出目录；固定集成候选跑全量 |
| 覆盖率与CRAP | 保留现有阈值、基线和工具链检查 | 一次带覆盖率的执行同时提供功能结果与覆盖率；必要的无插桩契约另测，不能假定两种环境等价 |
| 变异 | 涉及受测模块、测试、共享依赖或变异工具链时仍阻断 | 非相关变更的完整变异可移到固定集成候选、定时及发布前；须另批风险分层政策，不在第一步静默改变 |
| 性能、压测、长稳 | 可确定的资源/复杂度保护及本次性能要求 | 毫秒级基准、长压测和24小时稳定性在明确测量条件下集中执行；原性能要求和失败记录保留 |
| 真实模型、Compact A/B | 模型适配改动需要相关协议/行为验证；发布前保留实际模型证据 | 非确定性质量实验适合定时／发布候选集中跑，预算和质量结论单独报告；目前部分本就为诊断项 |

“批量”指先固定一个包含多项变更的集成候选，在它上面取得完整证据，再合入该候选；不是先合并各PR、晚上再补安全测试。同一个输入的一份真实证据可以供多个标准核对，但不能复用不匹配源码/验证器/运行环境的绿灯，也不能省掉标准明定的重复运行或负向控制。

当前仓库属个人账号magele758。GitHub原生merge queue的官方适用范围为组织所有的公共仓库或企业云组织私有仓库，不能假设当前仓库能直接启用。若后续采用批量集成，可先设计明确的集成候选分支与交付流程；不擅自关闭或代合其他PR。参考[官方merge queue说明](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)。

## 建议先做：保持完整验证范围，只消除重复与串行等待

1. PR更新只触发一套昂贵验证；main push保留独立集成检查，手动检查仍可执行。未开PR的分支先提供快速反馈，避免与PR全套重叠。
2. 梳理验证调用图，将独立入口、形式回归和验收映射改成同次执行共享可核对证据；验证器自测、规定重复性和源变异反向控制照常执行。证据附源码/测试/验证器/工具链/参数身份，不匹配或缺失就拒绝复用。
3. 将快速单测、真实进程验证、浏览器/API回归分为隔离作业，让E2E尽早启动；不盲目把共享SQLite的workers从1调大，也不让源变异与普通用例共用被修改的checkout。
4. 普通功能与覆盖率尽量一次执行产出两类结果；明确无插桩要求的测试保留专门执行。统一JUnit汇总，原AC必须仍获得真实通过结果。
5. 保留四组变异及全部现有阈值，先移除同PR重复触发。按runner供给限制并发，避免无上限拆分把墙钟等待转成更长队列。
6. 修正取消与汇总依赖，旧版本不得继续占用当前候选的并发组；新版本自身缺失、失败、超时、不完整仍阻断。
7. 分支保护目前仅要求tests、crap、acceptance三项，未要求包含mutation的Main release gate汇总。后续应将总门禁纳入必需检查并核对兼容性，避免变异失败却能从分支保护缝隙合入；2026-10-20已保留原三项并加入Main release gate，线上API读回核对一致。

第一步不把任何当前必需检查移至夜间、不调整已批准标准。按该轮耗时推演，去掉直接重入并让浏览器/API与覆盖率并行，有机会把约49分钟执行链缩至约15–25分钟；这是待验证估算，取决于保留的验证器自测耗时与runner供给，不保证排队时间。至少收集3次可比新旧运行，分别报告排队、执行墙钟、runner总分钟数、首次通过率。

## 后续另批：按影响范围分层与批量集成

待第一步证据证明无验证丢失，再确认变更分类、共享依赖失效边界、相关变异模块选择、固定集成批次、全量定时扫描及发布前重新验证规则。仅改文案/E2E时无需触发无关模块所有变异；但影响范围无法确定时默认升级完整检查。此政策变化必须单独确认，不能拿来让当前红灯通过。

本次9条验收已由用户批准，见`acceptance/ci-gate-speedup.yaml`。实现已包含触发去重、独立浏览器作业、单次覆盖率功能测试、严格无插桩性能测试、按实际输入绑定的默认探查证据复用及完整汇总门禁。三份形式审查清单加入证据辅助模块；显式故障、子集与重复运行不复用。
