# 对话里的运行策略提醒

`[risk-advisory]` 来自本地 RiskEngine，是发给 Agent 下一轮的策略提示，不是模型自行诊断的安全告警，也不额外调用模型。提示本身不终止执行；硬性轮次限制和 LoopGuard 的停止判定属于另外的控制路径。

## 如何理解

| 信号 | 含义 | 聊天展示 |
|---|---|---|
| iteration_near_limit | 迭代计数接近本次执行上限 | 普通运行提醒 |
| budget_high | 累计用量达到配置预算比例 | 普通运行提醒 |
| tool_error_streak | 同一工具及错误签名连续失败 | 执行异常提醒 |
| tool_repeat | 相同工具调用连续出现 | 执行异常提醒 |
| output_repeat | 输出重复比例达到阈值 | 执行异常提醒 |

`magnitude` 是各信号的内部测量值，不是统一风险等级。特别是轮次差值：内核以零起始的 turn 调用 tick，且发生在该轮工具执行后，不能直接把旧消息里的 magnitude 当作还可执行的完整轮数。

## 触发与频率

默认配置：轮次差值不超过 2，工具错误连续 3 次，预算比例 0.85；提醒之间至少间隔 3 次迭代，每个 RiskEngine 实例最多提醒 3 次。虽然配置字段叫 `maxCoachPerSession`，两个内核当前都是每次执行新建 RiskEngine，所以不是整个长期 Bot 会话终身只提醒 3 次。多次长任务可以各出现提醒。

实现位置：`packages/agent-loop/src/recovery/risk-engine.ts`，legacy 内核 `packages/core/src/turn/kernel.ts`，SDK 内核 `packages/agent-loop/src/turn/kernel.ts`。core 的 risk-engine 模块复用 SDK 实现。

## 合理性与本次范围

接近硬性上限时提醒模型整理产出是合理的；仅出现这一信号不能推出工具失败、危险操作或陷入重复。现有 `formatRiskAdvisory` 给所有信号附加同一段“改变策略、避免重复失败”的英文指令，证据与措辞不完全匹配。聊天卡片按信号解释，不再把容量提醒展示成执行异常，原始内容保留在默认折叠的详情中。

本次仅调整展示，不改变注入模型的提示、阈值、冷却或停止策略。若后续调整运行行为，应把容量信号的收尾建议与失败/重复信号的纠偏建议分开，并同时验证两个内核；不宜仅为了减少消息而关闭保护或无限提高轮次上限。排查真实频率时只输出汇总计数，不把会话正文和本地配置放进文档或提交。
