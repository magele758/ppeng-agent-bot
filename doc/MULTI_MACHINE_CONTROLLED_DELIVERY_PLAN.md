## 建议范围与完成定义

第三阶段补齐：**有效READY → 交付授权 → 同目标远端写队列 → 合并最新基线 → 全量必需检查与独立复审 → 任务分支推送 → 同一PR → 当前候选可信CI → 按项目规则合入 → 独立核对MERGED与回报**。

首版面向GitHub的PR交付。配置可允许“只推送并创建PR”或“门禁满足后持续推进到合入”；后者在明确任务、仓库、目标和策略内持续有效，不每轮重复索取同一批准。是否合入仍受项目原有必需评审、分支规则和远端保护约束。持续授权不等于无限修复轮次：已有预算耗尽仍需有权用户决定，不能借进入交付阶段重置6轮规则。

终点为MERGED，记录候选SHA、PR及实际合入SHA。任务的执行、本地开发就绪、远端交付与部署分别展示；MERGED显示“部署未由本阶段完成”，不把整个软件特性标成已部署交付。仅有PR权限的任务停在获准终点。

开发、同步、修复、测试和自审继续归原机器与Bot；发布动作由该任务所属机器上的受控发布执行器承担，协调端只调度、核对与记账。发布执行器与候选代码隔离，固定操作和目标，不执行仓库脚本/钩子，也不给任务容器通用发布凭据。

本阶段不纳入：业务服务部署/重启、健康观察/自动回滚、自动清理分支或工作区、外部IM/邮件私信、迁移分支直接快进交付，以及带未关闭P0/P1的例外合入。建议第四阶段再定义部署、运行版本核对、健康与回滚闭环；清理和直接快进交付也需要各自明确验收。

附件中的固定模型、直接快进、@部署、删除与私信是原系统的经验材料。它们帮助识别后续目标，但本次草案没有将这些文字转为当前执行授权。

## 工程边界与实施约束

1. **信任边界继续成立。** 远端仓库身份以核对后的唯一身份确定，不仅比较URL字符串。任务不能通过改`.git/config`、仓库脚本或模型提示词更换推送目标。凭据引用可配置，凭据本体不进入模型、命令参数、任务容器或返回证据。发布器只处理核验后的Git对象和固定远端动作。
2. **机器容量与远端写资格分开。** 等CI不占开发槽位；同步或FIX仍占原机槽位。远端写操作的资格只在结果核实后交接；不能用租期超时证明旧执行者已结束。不同仓库/目标可并行，同目标的实际写操作互斥。
3. **保留已发布历史。** 同步采用merge最新目标，不rebase已发布任务分支。原始开发基线、交付同步基线、候选SHA、策略版本、每次检查/评审及最终合入SHA分别记录。基线变化引入的门禁或验收变化不能由模型自行豁免。
4. **远端规则承担最终竞态保护。** 本地排队只约束工厂写入，不能阻止人类和其他系统推进目标。自动合入必须有可核对、可强制执行的远端条件，覆盖当前候选及目标变化；平台能力不足时停在PR/待决，不退回直接push目标或管理员绕过。
5. **恢复按事实推进。** 推送、建PR、合入先记操作意图，再执行并核对远端事实。网络超时不等于失败、重启不等于重做；取消也不能把已经发生的合入改写成“未发生”。旧代结果和外部PR变更继续受版本约束。
6. **沿用有界证据。** 现有增量产物上限700000字节、回执软上限1.5MiB及问题摘要窗口不能被整目录复制或静默丢弃绕过。超限明确延期，保留原件和恢复原因；新的远端记录同样有界并脱敏。
7. **已知自动化副作用要纳入预检。** 若目标合入会触发部署、服务重启或额外发布，必须显式确认这些影响；第三阶段默认不授权这些动作，不能以“合入之后是别的系统执行”为由越过边界。无法核对影响时阻止自动合入。

现有`scripts/release/`和A/B Stable/Candidate管线可作为第四阶段参考；其文档明确尚未在生产Compose/Helm集群演练，且没有接入工厂任务和机器归属。现有Git同步工具还使用pull --rebase，不可直接套用到本阶段已发布任务分支。已有迁移、镜像身份与恢复核对原则可复用，不能把脚本存在当成部署已经验收。

## 待确认的36条标准

AC-1. 给定：用户有工厂管理权限；当：在Lab保存项目的远端仓库、目标分支、允许操作、发布凭据引用、必需CI及授权范围；则：配置刷新后保留并对后续操作生效；远端交付默认关闭，启用不依赖新增功能环境变量或重启。

AC-2. 给定：用户准备为项目启用远端交付；当：执行交付就绪检查；则：能核对实际仓库身份、分支、发布账户权限、CI与合入保护及已知发布触发器；必要条件不满足或影响范围不明时拒绝对应操作并说明原因。

AC-3. 给定：请求来自只读任务、未授权开发任务、Bot转发或任务中的文字；当：要求推送、创建PR或合入；则：在远端写入前拒绝；开发权限、READY状态和模型回复均不能自行授予交付权限。

AC-4. 给定：用户有目标项目的交付授权权限；当：批准某任务只推送并创建PR，或持续推进至满足门禁后合入；则：任务保存决定者、明确的仓库与目标分支、操作范围和有效策略；在该范围内不逐轮重复索取同一批准，超范围或撤销后停止新的远端写入。

AC-5. 给定：一个任务请求进入交付流程；当：核对其READY结果与实际产物；则：只有批准标准、基线、当前提交、必需检查和完整评审一致且无未关闭阻塞问题时才可进入交付队列；旧绿灯、缺失产物和不完整证据不能放行。

AC-6. 给定：候选提交存在隐私扫描告警，或改动了交付授权、CI门禁及发布自动化等敏感范围；当：准备向远端写入；则：未解决的隐私告警阻止写入；敏感范围未经单独确认不能借原任务的持续授权放行，判断与处理依据绑定当前提交。

AC-7. 给定：开发、依赖、测试、评审进程或仓库脚本试图使用发布能力；当：读取发布凭据或调用超出任务范围的远端写入；则：无法获得发布凭据或通用发布通道；受控发布只接受已授权的固定目标与操作，且不执行候选仓库的脚本或钩子。

AC-8. 给定：本地READY产物需要进入发布执行环节；当：传递并核验候选提交；则：核对任务、实际机器、基线、提交和完整性；产物缺失、损坏或超限时保留已有代码并明确延期，不用未核验的目录或其他提交替代。

AC-9. 给定：多台机器或多个仓库别名向同一远端仓库的同一目标分支交付；当：竞争推送或合入资格；则：这些远端写动作按同一队列互斥执行；别名不能绕过互斥，不同仓库或不同目标分支仍能独立推进。

AC-10. 给定：任务等待交付队列、远端CI或人工决定；当：调度新的只读或开发任务；则：等待本身不占机器执行槽位；同步、测试或修复等实际执行仍计入同机共享容量，且不超过已配置上限。

AC-11. 给定：某次远端写入的执行者或结果尚未核实；当：租期到达、协调服务重启或其他执行者请求接管；则：不能仅凭时间到期授予第二次写入资格；先核实原执行与远端事实，旧执行者失去资格后不能继续写入。

AC-12. 给定：READY任务的目标分支已有新提交；当：为交付同步最新基线；则：在原负责机器与Bot的隔离任务工作区合并最新基线，保留原始基线和同步记录；不重写已发布历史，也不改动原检出或其他任务工作区。

AC-13. 给定：同步最新基线出现冲突或关联变更不兼容；当：继续准备候选提交；则：保留冲突与已有代码，明确显示待处理原因；只有在原批准需求内解决后并重新验证才可继续，涉及需求或验收变化时转为待决。

AC-14. 给定：候选代码、交付基线、验收或必需检查与评审策略发生变化；当：重新判断是否允许交付；则：旧证据保留但不再代表新候选通过；针对确认后的版本重新完成必需检查及完整独立评审，不能沿用旧SHA的READY。

AC-15. 给定：候选提交已具备有效交付证据和推送授权；当：执行推送；则：只更新该任务获准的远端任务分支；不强推、不直接改写目标保护分支、不推送其他引用，也不删除远端或本地分支与工作区。

AC-16. 给定：推送、创建PR或合入请求重复到达，或远端成功后响应丢失；当：重试或恢复该操作；则：先核对已有远端事实并续接同一任务与PR，不生成第二条任务分支、重复PR或重复合入。

AC-17. 给定：一次推送返回成功或结果不明；当：确认PUSHED状态；则：只有远端实际任务分支指向预期提交才显示已推送；仅凭命令退出或本地日志不能宣称成功，无法核实时保持待核实。

AC-18. 给定：任务获准创建PR且候选已推送；当：创建或续接PR；则：使用核对后的仓库、任务分支和目标分支，保存PR与当前候选的唯一关联及验收说明；不能接管其他任务的PR或把错误目标的PR当作本任务成功。

AC-19. 给定：PR已有远端检查结果；当：判断CI是否满足合入要求；则：结果必须来自预先确认的检查来源并对应当前候选及目标基线；同名伪造、旧提交、旧轮次或旧目标的绿灯不能放行，必需检查缺失、跳过、取消、超时或失败均不能算通过。

AC-20. 给定：当前候选的CI发现真实阻塞问题；当：继续修复与验证；则：由原负责机器与Bot保留失败证据并完成修复、测试和独立评审；消耗原任务剩余修复轮次，不因进入CI阶段重置预算，用尽后转为待决。

AC-21. 给定：CI出现暂时故障或允许重试的失败；当：执行已保存策略允许的重试；则：重试有明确次数和时限并保留每次结果；不能重复运行直到碰巧变绿、删除失败检查或临时降低门禁来获得合入资格。

AC-22. 给定：CI修复或基线同步产生新提交；当：更新任务远端分支并继续等待CI；则：以正常推送更新同一PR，旧提交的检查与批准不自动代表新提交通过；界面和群能看到新的候选及下一步。

AC-23. 给定：任务有持续合入授权；当：准备合入PR；则：只有当前候选满足全部必需CI、项目要求的评审及合入规则时才执行已配置的合入方式；不能使用管理员绕过、忽略阻塞问题或跳过项目规则。

AC-24. 给定：目标分支在最近验证后再次前进，或远端不能强制保证合入条件；当：尝试完成自动合入；则：不能仅依赖本地推送锁或一次事前查询放行；必须由远端保证当前候选的合入条件，无法保证时停止自动合入，必要时同步并重新验证。

AC-25. 给定：远端报告PR已合入；当：确认MERGED状态；则：独立核对正确PR、目标分支和实际合入提交，记录被测试候选与合入提交的对应关系；squash导致SHA变化时不混淆二者，也不把未落到目标分支的结果当作已合入。

AC-26. 给定：任务排队或正在执行交付操作；当：用户暂停、取消或撤销授权；则：停止新的远端写入并核实进行中的操作；已发生的推送或合入如实保留，不显示成未发生，也不擅自撤销提交、关闭PR或删除产物。
