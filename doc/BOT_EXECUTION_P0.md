# Bot 执行 P0：路由、压缩与完成证据

2026-10-24。本次以 `acceptance/bot-execution-p0.yaml` 为验收契约。

## 行为变化

- 礼貌问句、带问号的实现请求、调查并修复等组合任务保留交付目标。普通任务由当前 Bot 执行；明确并行、委托或指定执行策略继续遵守能力、权限、预算与隔离要求。
- 日志压缩保留首尾；常见 JSON 工具结果压缩长字符串，保留退出码、错误与产物字段。超出预算的结构退回首尾摘要。只改模型视图，原始结果仍可通过 history_read 回查。
- 完成判官使用该执行会话的模型配置。输入先按字段限长，再序列化为完整 JSON；包含原始目标、约束、验收条件、上次缺口及配对工具结果。较早的证据能穿过 compact-summary，显式撤回或非压缩替换的结果被排除。
- 外部行动必须引用现存工具结果，至少一项成功且不是任务登记/启动等记账结果。助手声明、伪造引用、未配对结果不能单独通过。未达标返回具体缺口；服务异常、无效裁决、材料超限或缺少证据进入待核对状态，保留已有产出。
- Bot 提示要求完成已授权步骤、真实调用工具、检查产物和测试并记录阻塞；不再默认要求角色流水线或先登记任务。审批边界保持不变。

- `crates/codegen/xai-grok-shell/src/session/templates/goal_verifier_prompt.md`：依原始契约核对证据，将未完成事项带回执行，避免扩大验收范围。
- Bash 工具输出的首尾保留及原始日志回查设计。

这里沿用本仓库的持久化目标、工具权限和审批模型，没有移植整套运行时。

## 验证与边界

新增测试覆盖中英文路由、控制讨论、隔离和预算、压缩保真、长历史/转义输出预算、伪造与未配对证据、撤回证据、判官失败、会话模型及实际 write_file/read_file 到目标完成的完整链路。既有专业执行者用例改为显式请求子代理，保留其派发和结果断言。

结构校验能阻止没有真实引用的“口头完成”，但结果是否足以满足业务目标仍由模型判官判断；不等同于形式化证明。有限输入预算会遗漏历史结果，包内明确标注遗漏数量与截断，判官不得据此推断成功。真实 Grok 模型上的任务完成率与成本提升尚需固定任务集 A/B 测量，本次本地测试不宣称该提升已被测得。
