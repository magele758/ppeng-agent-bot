# 快速合并与每两小时完整验证

2026-10-20，负责人确认采用 `acceptance/ci-fast-and-bihourly-gates.yaml` 的8条标准，再修复、review并合并所有未合并PR。此政策替代原 `ci-gate-speedup` 的逐PR完整阻断条件。原9条原文及批准和失败记录保留；三旧三新性能统计未验收，不宣称30%中位数提速已通过。

每个PR版本以及main提交自动执行 **Quick gate**：作业总时限2分钟，内部实际验证预算90秒，为checkout、Node和依赖准备预留时间。运行改动函数的圈复杂度（超过30即失败，不等覆盖率）、工作区类型构建、Lab类型检查、四套形式源码审查指纹、短时审批/权限及CI策略回归、验收映射检查。没有增加重试、放宽阈值或将quick结果伪装为完整验收。平台排队另计，超时和证据缺失不得当作通过。

与 Quick gate 并行的 **Core unit tests** 跑核心库、可嵌入循环和控制台单测，不收集覆盖率，不跑浏览器、浸泡或变异。PR 的等待时间是两者中较慢的一个，不是相加，也不是完整验证。

**Full validation** 在合入 main 时立即启动，并仍在 UTC 每个偶数小时的第17分钟运行（每两小时）。也可手动在指定分支执行。完整复用原 release-gate，但云端不再跑浏览器 E2E。HTTP 回归和集成仍在。浏览器用例留在仓库，用 `pnpm run test:e2e` 在本地执行。相同分支完整任务不取消正在运行的任务；更新的排队候选会替换更早的排队，证据按 run/attempt 隔离。定时器由 GitHub 调度，可能因平台负载延迟。

CI的手动入口仍可执行完整验证或冻结旧顺序基线，均不替代当前PR的Quick gate。独立Mutation仍可手动执行，完整变异的定时责任统一归入两小时验证。镜像不再因普通push/PR重复触发完整门禁，仍保留计划与手动发布，发布前原完整验证和容器冒烟必须通过；npm/tag发布的完整门禁保留。

分支保护要求当前版本的 **Quick gate**、**Core unit tests**，以及 PR 上的 **Main full health**。主分支最新完整验证失败时，Main full health 拒绝合并；这个 PR 头已经有一次成功的完整验证时允许合并，避免修复被自己挡住。快速门禁在主分支变红时仍会执行。完整验证失败保留实际候选、日志与制品，不因随后的 quick 绿灯清除，也不能把已合并说成发布就绪。现场部署验收仍后置。

完整浏览器入口为 `pnpm run test:e2e:full`：每个 spec 文件启动独立的临时 daemon、Next、数据库与鉴权 token，避免跨文件累计 Bot 耗尽产品的 50 个名单上限。原上限不变，全部文件均执行；任一文件失败则整体失败，JUnit 和截图/trace 按文件分别保存。指定用例调试仍可使用 `pnpm run test:e2e <file>`。

HTTP soak 驱动的观测账本以 100ms 为窗口提交事务，保留 SQLite FULL 同步，不再为每个读取状态变更单独同步磁盘。仅驱动自身的记录合批；daemon 的持久化、负载、计划发送时间、端到端延迟统计、遗漏时隙检查与性能门槛保持不变。最终报告写出前提交剩余记录。
