# 快速合并与每两小时完整验证

2026-10-20，负责人确认采用 `acceptance/ci-fast-and-bihourly-gates.yaml` 的8条标准，再修复、review并合并所有未合并PR。此政策替代原 `ci-gate-speedup` 的逐PR完整阻断条件。原9条原文及批准和失败记录保留；三旧三新性能统计未验收，不宣称30%中位数提速已通过。

每个PR版本以及main提交自动执行 **Quick gate**：作业总时限2分钟，内部实际验证预算90秒，为checkout、Node和依赖准备预留时间。运行工作区类型构建、Lab类型检查、四套形式源码审查指纹、短时审批/权限及CI策略回归、验收映射检查。没有增加重试、放宽阈值或将quick结果伪装为完整验收。平台排队另计，超时和证据缺失不得当作通过。

**Full validation** 在UTC每个偶数小时的第17分钟运行（每两小时），固定到触发时的主分支提交；也可手动在指定分支执行。完整复用原release-gate，保留全量功能/覆盖率、SDK/CRAP、形式与真实进程、全部变异、HTTP、集成、浏览器及JUnit验收。相同分支完整任务不取消正在运行的任务，证据按run/attempt隔离；待运行候选被替代的记录仍保留。定时器由GitHub调度，可能因平台负载延迟。

CI的手动入口仍可执行完整验证或冻结旧顺序基线，均不替代当前PR的Quick gate。独立Mutation仍可手动执行，完整变异的定时责任统一归入两小时验证。镜像不再因普通push/PR重复触发完整门禁，仍保留计划与手动发布，发布前原完整验证和容器冒烟必须通过；npm/tag发布的完整门禁保留。

分支保护改为要求当前版本的 **Quick gate**，已知review缺陷仍须修复。完整验证失败保留实际候选、日志与制品，不因随后的quick绿灯清除。发布流程继续使用实际发布候选的完整结果；软件合入不等于发布就绪，现场部署验收仍后置。
