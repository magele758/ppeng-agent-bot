# Bot 多目标协调设计与实现

日期：2026-10-21。用户已批准方案并授权多个 Agent 开发。验收：`acceptance/bot-multi-goal-coordination.yaml`。

## 当前实现范围

持久 Goal 与执行尝试位于 `packages/core/src/bots/goals/`，按 Bot 保存、按用户的 canonical chat 隔离。收到新工作后自动登记目标；查询、追加约束、暂停、恢复、取消和优先级调整关联已有目标。混合消息支持多个意图，歧义控制请求澄清。旧会话不会从全部历史消息批量生成目标。

已接主 Bot、隔离 SubAgent、Bot 委派、PTC、Team DAG 与 Swarm pipeline；浏览器、桌面、研究是每次执行的工作配置，仍需实际工具可用。自动路由检查实时工具与权限，记录选择或降级原因。Orchestrator、Self-Heal、Evolution、Factory 的专项生命周期适配尚未开放；研究配置不等于已接入独立 DeepResearch 任务系统。

调度器读取持久状态，协调并发和已声明资源、恢复等待及审批、收集外部结果并推进后续尝试。修改约束会递增版本并停止旧执行；仍在收尾的外部工作保留资源预约。执行返回后独立检查证据；检查不可用时阻塞，不宣称完成。预算、无进展和尝试上限停止继续派发，重要状态变化去重通知。

Lab 的聊天和 Bot 详情中提供目标面板：查看进度、下一步、策略原因、证据和成本，选择目标追加消息，暂停/恢复/取消/调整优先级。并发、预算、尝试上限和策略偏好保存于 daemon KV，后续派发立即生效；前端文案提供 zh/en，无新增环境变量。

接口均校验 Bot 和 canonical chat 所属权限：`GET /api/bots/:id/goals?sessionId=...`、`PATCH /api/bots/:id/goals/settings`、`POST /api/bots/:id/goals/:goalId/actions`。共享同一 Bot 的不同用户不能读取或控制彼此的目标。

运行边界：宿主 daemon/scheduler 需在线；服务重启后恢复持久状态，结果不明的外部操作保持阻塞并要求核实。外部等待目前接已授权的 session、Bot task、Team DAG 和 Swarm 引用，不是任意站点事件订阅服务。成本使用上游报告的用量和已关联独立 worker 成本；不能把共享 Bot 会话历史总费用当作本目标费用，也不承诺所有第三方执行器的实时精确计费或硬美元上限。资源协调依赖声明和保守工作区归类，不能自动识别任意外部系统冲突。

专项回归覆盖多目标状态、插话意图、真实 runtime 续接、跨运行时争用、审批网关、旧版本 fencing、等待/重启、取消、预算、HTTP 权限隔离和控制台操作。仓库既有形式验证仍是其文档所述的有界普通会话范围；新增 Goal 测试补充该范围，不把模型通过解释为整个系统的无限规模证明。

## 边界

Goal 是用户想达到的结果，Execution 是推进它的一次尝试，Conversation 是交流入口。一个 Bot 可拥有多个 Goal；一个 Goal 可经历多个 Execution，也可拆出子目标。执行结束不等于目标完成。长期盯守采用 waiting 状态，不需要持续占用模型。

协调能力位于 core 的 Bot/任务宿主层。agent-loop 继续负责一次运行；除非现有 steer、abort、outcome 契约不足，不扩大 SDK 职责。若修改 SDK，必须同步其 skill 并完成规定测试和构建。

## 消息接收与归属

先持久接收用户消息，再解析成一个或多个意图：new_goal、amend_goal、query、pause、resume、cancel、reprioritize 或普通聊天。一句话可同时包含多个意图。采用显式目标 ID、回复关系、当前选中目标和会话上下文辅助模型判断；模型输出结构化建议，程序校验权限、状态和版本。

查询不创建目标。修改与控制指向既有目标。歧义操作等待澄清，只冻结有争议的变更，不阻塞其他目标。UI 回执说明新建或修改了哪个目标，允许纠正误判；普通闲聊不必生成持久任务。

保留 bot-concurrent-subagents AC-1/AC-2：单项工作由主 Bot 执行；并发时额外独立工作交给子代理。查询、修改不是额外独立工作。主 Bot 执行中的进度查询可由结构化状态直接回答；需要模型处理的插话进入已有安全边界的控制路径，不另开第二个执行者争用主会话。

## 持久状态

- Goal：归属主体与 Bot、标题、目标正文、约束、完成条件、父目标、优先级、状态、版本、预算、进度摘要、证据与来源消息。
- Execution：goalId、goalRevision、策略、适配器运行引用、attempt、租约与 fencing token、检查点、结果、成本。
- Wait：goalId、事件来源与关联 ID、订阅游标、检查条件、deadline、兜底检查时间。
- Event/Outbox：消息接收、意图归属、派发、约束修改、结果、状态变化；唯一去重键。状态提交与待派发事件同事务落盘。

Goal 状态：queued、running、waiting、blocked、paused、completed、failed、cancelled。waiting 必须有明确唤醒条件；blocked 必须有原因和解除条件。持续监控可在处理一次事件后回到 waiting，直到期限、退出条件或用户取消。

执行结果统一为 progress、waiting、blocked、candidate_completed、failed、cancelled。completed 只能由目标完成检查产生。错误、判官不可用或证据不足不能成为完成证据。能用构建结果、产物存在性等确定性检查时优先使用；模型判断作为补充。

## 自动选路

任务执行配置与执行器分开：auto/fast/planner/browser/computer/deep_research 等控制工具和行为；SubAgent、Bot 委派、PTC、Team DAG、Swarm 等负责工作组织。

每次派发先读取实时能力清单：工具注册、模式门槛、配置、权限、工作区、预算和适配器健康。模型提出策略及理由；程序验证后执行。默认选择可满足任务的最简单策略，而非最大化并行或模式数量。

建议映射：问答直接回复；单项实现主 Bot 或单 worker；独立并发工作 SubAgent；已有专业 Bot 用 bot_delegate；资料研究采用研究配置；网页/桌面任务用对应能力；重复数据读取与合并采用 PTC；依赖明确的工程协作用 Team DAG；已有兼容角色流水线使用 Swarm pipeline；Orchestrator/Self-Heal/Evolution/Factory 仅在专属条件满足且适配器验证通过后采用。

首选不可用时可在同等授权范围内降级；不能靠切换策略规避审批、沙箱、子代理权限或扩大数据范围。PTC 配置限定在此次执行，不把整个 Bot 永久改成 PTC。动态工作流的 soft/hard replay 独立校验，不能假定重放等于副作用可安全重试。

## 执行适配器

统一接口表达 capabilities、start、inspect、steer、cancel、collectEvidence；可选能力必须明确标注，不制造所有执行器都支持实时修改或恢复的假象。保持现有执行器的任务、工作区、调度实现，只将运行引用与标准化结果接入 Goal。

不能 steer 的执行器在修订目标后停止后续派发，并尽力取消当前执行；安全边界后重建尝试。迟到旧版本结果保留为证据，但不能直接完成新版本目标。已生效外部动作不声称能够撤销。

## 可靠性与资源协调

任务派发使用持久队列、租约、fencing 和 outbox；重复事件按来源 ID 去重。不能承诺跨任意外部系统 exactly-once：外部操作支持时使用幂等键，否则中断后先验证结果，不明状态转 blocked。

等待订阅与游标持久化，采用先登记再检查或可回放事件，避免事件先于订阅丢失。启动时恢复订阅并对账。无事件接口时由程序自适应轮询，仅变化时调用模型。定时兜底用于租约过期与遗漏事件修复。

对已声明的工作区、分支、部署环境等资源进行冲突协调；未知冲突保守串行，不声称能识别任意外部资源冲突。工程任务优先隔离工作区，统一集成。优先级考虑等待时间，防止饥饿。子任务预算计入父目标，不能换执行器重置预算。有限重试、无进展检测和熔断防止空转。

## UI 与配置

聊天旁显示目标列表：状态、最近进展、下一步/等待条件、执行方式、预算和证据。允许选择目标后追加消息，暂停、取消、恢复及调整优先级。只有需要用户行动、失败、完成或有意义变化时主动通知。

并发、预算、重试与策略偏好走 Lab UI 与持久化配置，后续派发立即生效，不新增功能开关环境变量。所有前端文案同步 zh/en。

## 分阶段交付

1. 目标生命周期与插话归属：接主 Bot、SubAgent、bot_delegate；证据完成检查、状态展示、基本租约去重、重启对账和预算不可后置。旧会话不从历史文本批量猜测目标；已有在途执行只有明确关联后才纳管。
2. 等待和自动选路：事件订阅、外部轻量检查、资源冲突策略；接 PTC、Team DAG 与 Swarm pipeline，逐一验证取消、失败和回传行为。
3. 专项流程适配：独立核验 Orchestrator、DeepResearch、Self-Heal、Factory、Evolution 后接入；缺少证据或状态语义时保持不可选并展示原因。

按适配器逐步开放不应削弱已批准验收。需批准阶段对应范围后才能逐阶段标记实现；本草案不把未接通能力宣称为已交付。

## 验证重点

固定消息序列验证新建、查询、修改、取消和混合意图；在接收、提交、派发、外部动作、结果回传边界注入重启；重复事件和迟到旧版本结果；无权限、预算耗尽、无进展；重叠资源与取消传播。路由用包含正确候选集合、禁止候选和可观察交付结果的任务集评估，不能只验证模型返回了一个模式名。
