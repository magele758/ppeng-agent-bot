# 对话中的技能沉淀

在 Lab「Bots 与 Agents → 技能 → 技能提案」启用技能提案，并设置提醒间隔（例如 10）。配置持久化且立即生效，不需要新增环境变量。间隔按一次运行内完成的工具迭代计数，同轮并行工具只计一次；模型可以自行判断是否值得记录，没有可复用经验时不弹出建议。

模型通过 `skill_propose` 提交 `name`、`description`、`reason`、`summary`。这一步只提交意图，不能提交 `body`。当前对话内出现非阻塞确认框，显示新建或更新、目标名称、理由和范围。用户可以确认、拒绝，或继续对话稍后处理。

确认一次后，运行时使用该会话选定模型的文本完成接口，根据建议提交时的对话证据和已有技能正文提炼。模型不获得工具执行权限，也不能改变已确认的目标名称。验证通过后写入用户技能目录并刷新目录，不再进入第二次正文审核。界面显示处理、成功或失败状态。相同建议的拒绝记录会保留，重复确认不会再次调用模型或安装技能。

非 Bot 对话的旧流程更新支持仓库技能和用户技能，保存到 `stateDir/skills/`，不修改仓库原文件。内置技能和优先级更高的 `~/.agents` 技能不能通过此流程覆盖，模型应改用新名称。若目标在确认前或提炼期间发生变化，本次保存失败并保留原技能。模型不支持文本完成、返回无效内容、疑似凭证或提炼超时也会显示失败。

旧版已存在的待审提案仍可在技能页查看正文、批准或拒绝。新保存技能复用同一安装记录，可在技能页撤销；撤销仓库技能的用户覆盖版本后，仓库原版重新生效。

接口：

- `GET /api/sessions/:id/skill-captures`：当前会话的建议与状态，不返回对话证据或已有正文。
- `POST /api/sessions/:id/skill-captures/:captureId/confirm`：确认、提炼并保存；重复请求复用同一个处理结果。
- `POST /api/sessions/:id/skill-captures/:captureId/reject`：拒绝待确认建议。

三个接口均检查会话访问权；确认和拒绝沿用技能管理的管理员权限，确认只授权当前建议。记录保存在 `stateDir/skill-captures/`，服务重启不会自动重复提炼；中断的记录恢复为已保存或失败。

验证：`packages/core/test/skill-capture*.test.js`、`packages/core/test/skill-proposals.test.js`、`e2e/skill-capture.spec.ts`。验收标准见 `acceptance/skill-capture-intent-confirmation.yaml`。

## Bot 私有沉淀与只读共享

Bot 对话中新提炼的技能默认归该 Bot 私有，确认框显示所属 Bot，可勾选共享给指定 Bot。共享是对同一份技能的只读使用授权，不复制正文，也不默认授权未来新建的 Bot。同一 Bot 的其他对话可以使用其技能；接收 Bot 的既有技能白名单和范围限制仍生效。

Bot 更新自己同名的技能时保留共享对象。其他 Bot 不能通过 `skill_propose` 更新这份技能；可以提出自己的独立私有版本，仍需用户确认。模型更新可提供搜索返回的 `targetSkillId`，运行时只允许更新所属 Bot 的目标。不同 Bot 的同名技能使用独立身份；搜索返回 `id` 和 `ownerBotId`，名称有歧义时 `load_skill` 要求使用具体 `id`。

在「Bots 与 Agents → 技能 → 已批准技能」按 Bot 查看自有和他人共享的技能。用户可保存共享范围或撤销技能；撤销前显示受影响 Bot。取消共享立即影响后续搜索和加载，但不会清除已加载到历史对话中的正文。共享管理操作仅向管理员开放，不向模型提供修改授权的工具。

历史全局沉淀技能继续标为「历史共享」，保持原范围，用户可显式选择所属 Bot 和接收 Bot 完成转换；内置、仓库和外部技能不迁移。旧待确认建议显示新的归属与范围后再确认。普通非 Bot 对话的旧技能流程保持兼容。

Bot 私有技能保存在 `stateDir/skills/.bots/<stable-id>/SKILL.md`，归属和接收者与正文一起原子保存。既有全局技能保留原路径；转换时只移动用户沉淀副本。当前 Bot 的沉淀不会覆盖仓库或其他 Bot 的同名技能。

- 确认接口可接收 `{ "sharedBotIds": ["接收 Bot ID"] }`；省略时保留建议显示的范围，新技能默认空列表。
- `PATCH /api/skill-proposals/:id/sharing` 接收 `{ "ownerBotId": "所属 Bot ID", "sharedBotIds": [] }`；已有归属不可转移，历史共享技能可在此显式归属。无效 Bot、同名归属冲突或保存失败时不改变原内容和范围。
- 管理列表返回所属、共享对象、当前安装状态，以及受既有使用限制影响的接收 Bot。

新增验收见 `acceptance/bot-scoped-skill-sharing.yaml`；测试见 `packages/core/test/bot-scoped-skills.test.js` 和 `e2e/bot-scoped-skills.spec.ts`。

## 在 Bot 详情和对话中管理技能

Bot 详情的「技能」页签展示当前 Bot 有权访问的技能，支持按名称或描述搜索、查看正文、识别来源和同名技能。选择「全部可用技能」或「仅选定技能」后保存；后者空选表示禁用全部。原有技能范围、工具权限与白名单仍生效。配置保存在 daemon_control，立即影响当前 Bot 后续会话中的搜索、加载与提示，不依赖环境变量或重启。

自有沉淀技能可在详情页共享、取消共享或撤销；他人共享和公共技能只读。共享不复制正文，更新影响同一份技能。撤销删除安装文件，但保留处理记录。已经出现在历史对话中的正文不会被收回。

`skill_manage` 提供 `list`、`create`、`update`、`share`、`unshare`、`delete` 操作。列表返回准确技能 ID、归属、可管理状态和可选择的 Bot ID。更新、共享和删除使用准确技能 ID，避免同名歧义。新建/更新只提交意图与变更摘要，由运行时提炼正文。

- 用户明确要求的具体操作：运行时根据当前用户消息核对操作、目标和接收者，匹配后直接执行。
- 模型自主提出的变更：对话显示确认卡，列出目标、理由及受影响 Bot。确认一次后自动执行，沉淀和更新没有第二次正文审核。
- 模型不提供可信的“已授权”开关；无法确认用户指令时进入一次确认流程。`skill_propose` 仍可用于沉淀建议，也会识别明确的用户指令。
- 确认绑定技能正文和共享范围的版本；目标已变化则不执行旧确认。重复提交合并，失败不会报告成功，删除的记录写入失败会恢复文件。
- 操作记录保存在 `stateDir/skill-operations`，包含 Bot、目标、授权来源、结果和时间。Bot 详情汇总该 Bot 各会话的记录。

接口：`GET/PATCH /api/bots/:id/skills`、`POST /api/bots/:id/skills/manage`、`GET /api/sessions/:id/skill-operations`，以及操作下的 `confirm` / `reject`。管理写入和确认沿用管理员权限；模型工具以当前会话 Bot 为边界，不能改变归属、修改公共技能或转共享收到的技能。
