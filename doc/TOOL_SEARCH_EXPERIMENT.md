# 工具检索实验

入口：Lab → 设置 → 工具与技能 → 工具提供方式 → 工具检索策略。

| 对照组 | 工具提供方式 | 工具检索策略 |
|---|---|---|
| A | 全量可用工具 | 任意（全量不使用检索） |
| B | 渐进加载 | 原有关键词（默认） |
| C | 渐进加载 | 增强检索（实验） |

选择后自动持久保存，下一次搜索生效，不需要新增环境变量或重启。配置是应用级，切换期间会影响其他对话的后续搜索；请顺序比较。原有常驻工具、Agent 固定能力包、权限与能力开关、已加载工具保留规则不变。每次试验新建会话；只切换策略不会清空旧会话的工具。可以在原有界面清除临时加载记录，但不会删除历史，因此新会话更适合对照。

增强检索包含：

- 搜索当前 Agent/会话已授权且配置允许的本地目录，包括已经提供的工具；已提供工具标记 `already_loaded`，不重复加载。
- 精确工具名优先，其次按名称、描述、分类和常见中英文别名排序。内置别名是有限词表，不是通用语义模型，也不会自动发送额外 LLM 请求。
- 搜索最多返回五个结果；隐藏工具自动加载，下一轮可调用；搜索不会执行目标工具。
- 无结果时返回授权目录中的分类。调用 `tool_search({query:"",group:"<结果里的分类 id>"})` 浏览；有 `nextOffset` 时用 `offset` 翻页。分页使用全部授权目录，所以已加载工具不会消失导致跳页。目录在翻页期间变化时应重新开始浏览。
- 默认系统指引说明搜索、已加载状态和无匹配恢复，无需先找到另一份 Skill。全量模式仍直接提供工具。
- 外部能力卡继续由外部服务发现开关控制，是信息卡，不等于本次加载的可执行工具；指定本地分类时不混入外部卡。

工具结果记录 `strategy`，增强策略额外记录 `candidateCount`、`matchedCount`、`loaded`、`failures` 和分页位置，可在对话工具结果中展开查看。`candidateCount` 是授权和分类过滤后的本地候选数，`matchedCount` 是分页前的本地匹配数，不包括外部卡。实际调用成功需以目标工具的执行结果为准。

建议使用相同模型、权限、固定包和输入任务，记录任务完成率、搜索无结果次数、搜索/加载/调用轮数、耗时、上下文预览的工具定义开销和实际输入用量。包含中文自然需求、英文同义词、精确名、已加载后再搜、分类多页、禁用能力和连接未配置场景。全量与渐进的差异不是全部由搜索排序决定，不要混用累计 token 与单轮 token。

自动化验证使用规则检索与受控模型覆盖加载链路；不代表真实模型评测已完成。本版本不缩小常驻清单、不自动卸载、不新增领域 Skill 工具依赖协议。先验证召回质量，再决定是否扩大延迟加载范围。
