# Bot goal 默认链路验收（2026-10-24）

本次覆盖四个实测问题：跨执行证据丢失、单任务被拆散、默认工具曝光不满足执行策略、完成通知重跑旧任务。

## 修复与边界

- 完成判官和续跑模型读取相同的结构化工具观察。每条观察附带运行时校验的执行者类型、Bot、执行 ID、委托任务/尝试号和状态。来源限定为当前目标版本的执行记录；委托主会话限定到当前尝试的消息区间，子执行检查用户、Bot 与祖先关系。压缩保留原始证据，显式撤回仍生效。
- 连续步骤、读取核对和约束保留完整上下文；分类超时、异常或模型拆分遗漏内容时使用保守结果。明确独立任务与控制指令仍分别处理。
- 已授权且仍持有有效执行的会话直接获得目标入口；工具搜索支持带 `+` 的名称，不改变 allowlist。执行者交接明确“已被委派”，避免把原始要求再委派一遍。
- 状态通知直接写入既有结构化卡片，不唤醒模型重跑历史任务；过期检查点被拒绝，新用户消息不受影响。完成核验单次最多等待 60 秒，故障仍保留待核对，不假报成功。

原有“仅有 goalId 即可 checkpoint”的测试改为先取得有效执行；证据夹具补齐真实执行关联。保留原有证据完整性、压缩、失败及伪造证据断言。

```sh
pnpm exec tsc -b packages/core
node scripts/agent-eval/goal-chain-live.mjs <本机配置仓库> <已配置模型的Bot-ID> <不存在的验收输出目录>
```

脚本从已配置 Bot 读取模型连接，创建隔离状态与全新默认 Bot，使用真实 `write_file` / `read_file`，不固定工具组、指定目标策略、调整权限或手工接受完成结果。依次验证直接执行、独立子任务、指定 Bot 委托；每条请求包含写入、核对和约束，要求只产生一个目标并自动达到 completed。
