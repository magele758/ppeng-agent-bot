## 记忆删除抑制

在「知识与记忆 → 记忆」或 Bot 的记忆面板删除记忆，会同时持久化抑制记录并移除记忆与向量。抑制保存失败时删除回滚，界面显示错误。面板展示删除原因、自动写回被阻止次数和「重新记住」入口。

自动提取、语义合并及最终记忆写入都检查抑制。匹配限定在同一 scope、user、tenant、Bot；会话作用域额外匹配 session。覆盖 Unicode/空白/标点规范化及明确偏好同义表达，不使用模糊相似度封禁无关事实，也不声称识别任意语义等价。原始历史对话不会被删除。抑制持续到用户主动恢复，恢复会重新写入对应记忆。

- `GET /api/memory/suppressions`，可按 `agentId` 过滤。
- `POST /api/memory/suppressions/:id/restore`。
- `DELETE /api/memory/:id` 原入口改为原子删除并抑制。

## 严格预检

新建带预检任务默认严格；旧任务没有模式标记时保持兼容。Bot 的定时任务编辑表单可保存「严格 / 兼容」模式。模式是持久配置，无新增功能环境变量。

严格脚本必须正常退出，末个非空输出行为 JSON 对象，`wakeAgent` 必须为布尔值。`true` 进入正常审批与串行执行，`false` 在运行记录显示「无变化」。空输出、无效结论、超时、非正常退出、超限或保存失败均显示「预检失败」，不启动模型。预检沿用原有最小环境与断网隔离，输出超过收集上限也拒绝放行。

可选 `state` 是 JSON 游标，序列化 UTF-8 最大 16 KiB；下次脚本通过 `PPENG_PRECHECK_STATE` 读取（尚无游标时为 `null`）。这是子进程输入，不是用户配置开关。合法结论才保存新游标，省略时保留旧值；写失败保留旧游标。游标代表已观察进度，不保证模型工作或外部动作已完成。同任务预检使用独立租约，游标与运行快照在持有租约时提交。人工重试也重新执行预检。

## 定时任务故障治理

入口：「任务 → 运行」的私人例行任务故障治理区。仅作用于间隔和周期任务的未来自动触发，一次性与事件任务不自动重放。

默认策略：连续硬失败 7 次暂停；第二次连续失败等待 2 分钟，此后翻倍、上限 60 分钟；故障通知冷却 30 分钟。界面可调整暂停阈值、等待上限、通知冷却时间，保存后立即生效。无效数值由服务端拒绝。

临时故障（超时、限流、连接与上游暂时故障）参与退避，不增加硬失败次数；凭据、欠费、预检失败等计硬失败。分类复用现有模型错误分类器，并将余额/配额耗尽视作硬故障，即使上游返回 429。未知错误保守归硬故障。

运行成功且非静默时清零失败序列与退避，并对已通知的故障期发送一次恢复通知；无变化、静默、取消、等待审批和结果未知均不清零、不增计数、不发恢复通知。自动暂停需要所有者明确恢复，人工重试成功不会偷偷解除暂停。

故障与恢复通知仅在私人任务中心展示，群聊继续只投递非空成功结果。一个故障期只通知一次，新故障期还受冷却限制。状态和每次运行尝试的处理回执一起持久化，多实例重复处理不会重复计数或通知。

「恢复后续执行」清零失败序列和退避，记住恢复时间，丢弃该时间前尚未开始的自动触发；不补跑暂停期间任务。结果未知运行仍需原有人工副作用核对，恢复按钮不会解除该约束。

- `GET/PATCH /api/cron/jobs/:id/health`：所有者读取状态、通知或保存策略。
- `POST /api/cron/jobs/:id/resume`：所有者恢复后续触发。
