# 常驻任务可靠性

入口：Bot 右侧栏「定时」配置通知；对话右侧栏「上下文 → 长期任务与缓存诊断」维护任务契约和查看缓存观测。

## 中断恢复

调度器获得持久租约后检查原工作会话的闭合检查点、检查点之后的工具调用与回执，以及连接器的未确认效果。存在检查点、效果查询明确返回无未确认效果，且检查点后的工具波闭合并仅包含内置读取工具时，继续原会话，不新建尝试、不删除已完成历史。

没有检查点、效果状态无法查询、开放工具波或尾部包含 shell/插件/写操作时仍隔离为 unknown，保留核验与手动重试入口。不能把 shell 命令描述为“读取”来获得自动恢复。已结束的会话直接结算。运行详情显示恢复结果与检查点序号。该实现不声称任意第三方操作具有 exactly-once 保证。

## 重要变化通知

策略通过原有任务 API 和 Lab 编辑保存，调度判断读取最新策略，无需重启。旧任务默认仍使用文本比较。

- 事实比较：优先采用前置检查保存的 `state`；否则最终报告须是 JSON，包含 `facts` 字段。对象键顺序不影响比较，数组顺序有意义。其它报告字段可自由变化。不提供事实时正常通知，不能据此判定无变化。
- 安静时段：使用任务的 IANA 时区，支持跨午夜。开始和结束相同表示不限制。
- 每日通知预算：按任务及其本地自然日计数；界面 0 表示不设置上限。
- 延迟的已完成报告保留在运行记录中，在时段或预算允许时，合并成一条包含次数和最新结果的摘要；原始结果仍可查。等待人工发布审批的报告不会被另一摘要吞掉。
- 失败仍按既有失败阈值和健康告警处理，绕过成功报告的安静时段与预算，避免隐匿执行故障。
- 运行详情解释未变化、安静时段、预算限制及已合并状态。审批拒绝继续阻止发布。

## 长期评测

先构建 core，再运行 `pnpm run test:always-on`。确定性测试使用虚拟日期推进七天，检查事件重复提交、SQLite 重开、要求更新、摘要信息丢失、失败及通知次数。另有真实持久化压缩和模型调用边界测试，验证两次压缩后仍发送最新任务契约，并记录模拟上游的实际 usage 字段。

这是一组可重复的生命周期回归，不是模型连续运行一个月的质量证明。测试无需模型密钥，不调用真实外部发送服务。

## 缓存诊断

最近 30 次成功的模型调用保存在会话元数据。系统提示、完整工具定义、稳定系统消息与模型覆盖配置分别生成指纹。界面显示相邻记录改变的段，以及上游返回的 cachedInputTokens/inputTokens。首次请求没有可比较的前次记录；缺失用量显示未知，零值保持为零。片段变化不等于供应商缓存未命中。

诊断存储只保存哈希和计数，不额外保存提示词原文。诊断写入故障不应重试已成功的模型调用。

## 压缩任务契约

用户保存目标、约束、未完成事项、证据引用后形成带来源、时间和递增版本的独立任务状态。保存使用版本检查，旧页面不能覆盖后来保存的版本。每次实际模型请求预算计算前，将最新版本附加到最近 user 消息；摘要再有损，也不作为当前契约的权威来源。契约不写入 system 前缀，也不反复落入原始对话。

更新要求后可在面板同步修改；当前直接用户指令优先于契约。契约来源是用户维护，并非模型推测或自动授予权限；现有审批与沙箱仍独立生效。字段数量及总体大小有硬上限。摘要与证据引用不产生额外的执行授权。

API：`GET/PATCH /api/sessions/:id/reliability`，沿用会话所有权鉴权；PATCH body 为 `{version: 当前版本或0, contract: {objective, constraints, todos, evidence}}`。
