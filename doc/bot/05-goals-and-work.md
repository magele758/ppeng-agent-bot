# 05 目标与子任务

一句话可以变成一件还要继续做的事。Bot 把它记成目标，自己选一种已经授权的做法去推进，并留下证据。人不用先选「任务模式」。

规格：`bot-multi-goal-coordination`、`bot-autonomous-execution-coverage`、`bot-concurrent-subagents`、`bot-task-permission-inheritance`、`bot-fork-retrievable-inheritance`、`bot-goal-result-return`、`bot-product-p0`、`bot-product-p1`、`bot-product-p2`。面板什么时候出现见 [03 工作台](03-workspace.md)。

## 三层不要混

| 层 | 含义 |
|----|------|
| 对话 | 人说话的入口，就是主对话 |
| 目标 | 要达到的结果。一只 Bot 可以同时有多件 |
| 执行 | 推进这件目标的一次尝试。一次结束不等于这件目标完成 |

目标的状态是：排队、进行中、等待、受阻、暂停、完成、失败、取消。等待必须说清什么会把它叫醒。受阻必须说清原因，以及怎样才算解开。

完成只能来自一次独立的核对。模型说做完了、判官暂时不可用、证据不够，都不能算完成。能用构建结果或文件是否存在来核对时，优先用这些，模型判断只是补充。判官暂时不可用时，已经走完的回合保留已有结果并继续，不把目标收成受阻。

子会话、委派给另一只 Bot、团队任务图、Swarm、工厂和演进的结果都会回到原来那件目标。子会话结束会结算这次执行。对方 Bot 再开的子会话也带着原目标。子任务失败后，在尝试次数用尽前会带着失败记录再试，相同失败继续没有进展时会受阻；结果不明的子任务不自动重做。队友启动失败、任务列表为空、外部记录缺失，会把目标收成失败或受阻，不会一直等待，也不会把缺失记录当成完成。

Bot 持久目标是状态与最终核验的唯一来源；旧会话目标不会再另外决定 Bot 是否完成。普通非 Bot 会话仍支持会话目标。明确失败的执行报告会把目标记为失败；等待核验、预算耗尽等需要处理后才能恢复的情况仍记为受阻。

完成、失败和取消的目标不会常驻对话底部。在对话顶部展开「目标历史」可查看结果、失败原因和已有证据，升级前的旧会话终态也保留在这里。历史默认折叠，展开时刷新。进行中的多目标面板仍只在至少两件未结束工作时出现，历史不计入这个数量。

## 一句话进来以后

先把这句话存下来，再判断它是这些意思中的哪几种。一句话可以同时有几种。

| 意思 | 发生什么 |
|------|----------|
| 新的一件事 | 记成新目标 |
| 给已有的事加约束 | 改那件目标，版本加一，还在按旧版本做的执行停下来 |
| 问问进展 | 不新建目标。能用当前状态回答就直接答 |
| 暂停、恢复、取消、改优先级 | 作用在已经存在的那件上 |
| 闲聊 | 不产生持久任务 |

指哪一件，看明确的目标、这条消息回复的是谁、当前选中的目标，以及这场对话的上下文。判断不清的那一下只停住有争议的修改，其他目标继续。回执要说新建或改的是哪一件，人可以纠正。

旧对话不会把全部历史一次性猜成一堆目标。

## 自己选做法

每次派发先看现在真正能用的东西：工具、权限、工作区、预算、适配器是否健康。默认选能完成这件事的最简单做法。

大致对应关系：

| 事情 | 做法 |
|------|------|
| 问一句就能答 | 主对话里直接回 |
| 一件要做的事 | 主 Bot 自己做，或一个工人 |
| 同时多出来的独立工作 | 每件多出来的交给一个子任务 |
| 另一只更合适的 Bot | 委派给那只，用它的权限 |
| 查资料 | 研究配置 |
| 网页或桌面 | 对应的已授权能力 |
| 重复地读和合并 | 动态工作流，且只对这一次执行生效 |
| 依赖关系清楚的协作 | Team DAG |
| 已经有角色流水线 | Swarm pipeline |

首选不可用时，只能在同样的授权范围内换一种。不能靠换做法来绕过审批、沙箱或扩大能看到的数据。做不到就说明具体原因，请求人做必要的那一步，不假装完成。

取消作用在对应的那件执行上。取消之后不再派后续工作，迟到的结果也不能把它重新启动。

编排器、自愈、Evolution、工厂这些专项流程，要各自核过生命周期之后才接进来。没接上时保持不可选，并说明原因。研究配置不等于已经接上独立的深度研究任务系统。

## 同时做几件事

只有一件在做：不派子任务，主 Bot 自己做。

两件或更多同时在做：主对话留下一件，多出来的每一件各有一条子任务。主对话仍是协调者。

子任务可以检索父 Bot 的笔记、这只 Bot 的记忆、技能、文件和上下文。找不到另一只 Bot 的私有记忆，也进不了共享记忆池。向别人求助只送到父 Bot 和同一只 Bot 的其他子任务。对外发消息、改定时任务、改写父记忆，子任务做不到。

子任务从哪打开，见 [03 工作台](03-workspace.md)。

## 权限跟着谁

| 情况 | 新任务用谁的权限 |
|------|------------------|
| 同一只 Bot 再开任务，主对话是自动 | 自动。该审批的仍要审批 |
| 同一只 Bot，主对话是完全放行 | 完全放行。不因为拆了一条会话就再确认一次 |
| 同一只 Bot，档位更严或是计划模式 | 保持更严。计划模式禁止的执行和委派仍然禁止 |
| 委派给另一只 Bot | 用目标那只当前的权限。源 Bot 的放行覆盖不了它，源 Bot 更严也不把它改严 |
| 有人声称自己是某只 Bot 来提权 | 拒绝。只能沿真实来源或合法委派目标已经生效的档位 |

权限档位传下去，不等于多给工具或数据。子任务仍受这只 Bot 的访问范围和原有能力限制。已经存在的会话不会被成批提权，挂着的审批也不会自动通过。

## 可靠与交付

- 改了约束之后，旧版本晚到的结果可以留下当证据，不能直接把新版本判完成。已经发生、撤不回的外部动作要照实说。
- 结果不明就停在受阻，等人核对。未核对前不自动再做。
- 授权失效可以重新接上再继续。
- 每次执行留下自己的交付：报告、这次的产物、软件回执、失败原因。用户上传的文件不算 Bot 的产出。报告能导出，文本产物能限量预览和下载。来源或回执没有的，不编一个。
- 部分失败时，做成的和没做成的分开写。成功的成员不再跑一遍。可以只重试失败的那个。
- 预算、没有进展、尝试次数用尽，就停止继续派。重要的状态变化合并成一次通知，不刷屏。
- 服务重启后恢复已经记下的状态。本进程已经不再持有的执行会收口：可安全重试的本地工作继续排队，结果不明的外部操作变为受阻并等待核实，不再停在进行中。子任务在重启时被标成结果不明后，同样立即收口，不用等租约到期。主对话上一次进程留下的写入锁会放开，目标状态仍能写进主对话。宿主进程不在线时，新的派发不会自己发生。
- 点名某一件目标追加要求时，要求写进该目标的约束，不另开一件目标。指代不清时仍先澄清。
- 子任务停在需要人批准的步骤时，这张待批准出现在该 Bot 的主对话里，目标写明在等这个批准。批准或拒绝之后，子任务按这个决定继续或停住。待批准不会被自动通过，也不会被当成目标已经完成。
- 费用用这一次上报的用量和独立工人的费用。不能把整段主对话的历史总费用算成这一件目标的费用。没有账单回执时，成本就是未知，不用估算冒充实付。

并发、预算、尝试上限和策略偏好在 Lab 里改，保存在配置里，下一次派发就生效。

同一只 Bot 名下，不同用户的目标互相看不见，也不能操作对方的。

单次执行默认不限步数。Bot 设置中的「单次执行步数上限」提供无上限、24、48、96；已有明确保存的有限上限不会自动迁移。这里的一步是一次模型执行循环，不是内部推理 token，也不是目标尝试次数。不限步数仍受用户停止、循环检测、审批与错误处理约束；目标尝试预算及群聊预算各自独立。

## 目标需要人处理时

即使只剩一件目标，待核对、受阻或暂停时也会显示独立的「目标需要你处理」卡片。待核对结果可以接受或填写原因打回；普通单目标仍不展示多目标列表。尝试次数达到上限不取消已有结果的核对机会，最后一次外部执行仍等它结束，结果回来后可以核对，不会自动重做。

可以只为这件目标追加预算或批准额外尝试。新增额度不清零历史成本、尝试次数或结果，也不修改其他目标及默认设置。额外尝试同时增加该目标允许的无进展余量；额度保存后由用户恢复，待核对结果仍需接受或打回。默认预算只影响新建目标。

等待已有执行时不能直接恢复成新执行；先暂停并等原执行停止，或核对阻塞原因。外部工作与停止中的执行持续占用目标并发额度，直到结束回流或确认停止。

跨 Bot 委派的来源单独保存在任务上，在该任务被领取时才绑定准确的接收会话；不覆盖接收方自己的目标，也不修改同一 Bot 下其他用户的会话。子任务带着本次尝试编号，旧尝试的结果不用于结束新尝试。
