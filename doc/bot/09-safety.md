# 09 安全与设置

Bot 模式不另做一套安全规则。它用实验室里已经有的权限、审批、沙箱和敏感路径拒绝。这里只写 Bot 上人能看到、并能改的那一层。

规格：`bots`、`bot-task-permission-inheritance`、`loop-guard-model-switch`、`bot-product-p0`、`unattended-approval-expiry`（无人值守的审批到期是全局规则，定时任务也走它）。

## 权限档位

每只 Bot 有自己的档位。新的主对话默认是自动：按规则能做的就做，该问人的仍问人。

改成完全放行必须再确认一次。请求里没带这次确认，服务器拒绝，档位不变。其他档位不用二次确认。

入口在对话头部，打开的是这只 Bot 已有的权限、工具审批和允许名单。

| 档位 | 人能期待的 |
|------|------------|
| 自动 | 默认。允许的操作按自动规则走，原本要审批的仍要审批 |
| 完全放行 | 只在二次确认之后生效。同一只 Bot 新开的任务沿用它，不重复确认 |
| 更严的档位、计划模式 | 保持更严。计划模式禁止的执行和委派仍然禁止 |
| 跟随旧的默认放行 | 打开设置时有警告，可以一键改成自动。不擅自改 |

跨 Bot 委派用目标 Bot 的档位，不用源 Bot 的档位去放宽或收紧它。声称身份来提权会被拒绝。

工具允许名单和技能允许名单是另一层。名单空着表示不额外限制（技能名单空选并保存，则是一个都不用，见 [06](06-memory-skills-routines.md)）。权限档位传给子任务，不会把名单外面的工具一起带上。

## 审批

需要人点头的操作，展示来源任务、要做什么、影响谁、实际将要发出的内容或配置变更。凭证字段打码。看不出副作用的，要求人核对，不默认通过。

批准或拒绝之后，对话、列表和任务详情一起更新。

无人处理的审批在已有的十分钟期限后过期。过期是失败，不是成功。明确批准之后，从原来的工作会话继续，批准这个动作本身不等于工作已经做完。

群里的审批默认转到这只 Bot 的私聊，见 [07 群聊](07-rooms.md)。

## 重复检测

同一套工具被原样调用很多轮，或目录浏览、代码搜索次数太多时，弱模型会被打断。强模型默认不会。

设置在「对话默认行为」里，三项：

| 选项 | 行为 |
|------|------|
| 仅弱模型 | 默认。本地演示模型，以及名字分段里带 mini、small、haiku、flash、nano、lite 的模型会停。其余模型，以及认不出来的名字，不停 |
| 全部模型 | 强模型也停 |
| 关闭 | 谁都不因为重复或查看次数停 |

保存后下一轮生效，不用重启。没有单独的环境变量开关。

关掉或对强模型不生效时，这些限制仍在：打开图形界面、没有深度上限的扫盘、读取 `.env` 这类敏感文件、沙箱、该有的审批。同一次调用（同一工具、同一组参数）连续失败也会停，那是失败，不是重复。换着参数失败不共用这条熔断。没有工具调用、只是重复同一段正文，也跟重复检测同一个开关。

对话如果因为重复检测停住，停因要能看出是重复检测。连续失败的停因要能看出是这次调用失败，而不是一句笼统的工具循环。

## 不假装做完

这几条在交付、目标和软件调用里重复出现，因为它们是同一条产品规则：

- 模型说做完了，但核对没有通过：目标不算完成。
- 核对的判官不可用：标成受阻，证据留下，不宣称完成。
- 外部系统的结果还不知道：停住等人核对，不自动再执行。
- 连接断了：说不能确认，并留下上次更新时间。不显示成空闲或完成。
- 没有账单回执：费用是未知。不用估算填成实付。
- 部分成员失败：做成的留下，只处理失败的那个。不把协调者自己的一句回复当成全组完成。
