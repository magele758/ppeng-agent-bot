# Bot 模式产品目录

> **你只管目标，Bot 全天候为你工作。**

整个产品以 Bot 为统一入口组织：对话承接需求，目标与执行推进工作，交付、记忆、技能、群和定时任务围绕 Bot 展开。

**先读 [完整功能说明（产品审阅版）](00-functional-guide.md)**：一篇看完整体定位、24 小时虚拟员工与黑灯软件工厂的商业价值、信息架构、功能、典型流程及交付边界。下面 01–10 保留逐项交互规则。统一入口是当前产品方向；现有导航与默认路由的差异见完整说明第 2 节。

这是 Bot 模式现在怎么用、对象怎么分、每条规则用户能看到什么的总目录。实现细节、接口字段和历史方案留在文末的设计笔记里。

用户能观察到的行为以 `acceptance/*.yaml` 为准。这里和验收标准不一致时，先改这里，不要让两份说法并存。设计笔记和代码若和已实现的验收标准不一致，以验收标准为准。

投资人 PPT：[18 页演示与资源附录](investor-deck/README.md)，含开发、推广、营销及运行资源方案。

投资人沟通另见 [9 分钟演示稿](11-investor-demo.md)：开场台词、现场操作、商业价值、融资用途及备用方案。

任务协作（临时负责人、按需邀请与证据汇总）已作为独立切片实现；下文仍待收口的群子任务指完整专项规格，详见 [群聊](07-rooms.md)。

## 现在会怎样 / 还不会怎样

已经按验收标准实现、用户现在可以用的，写在 01–09。下面这些还不是当前产品：

- **草稿，未实现。** 输入区再瘦一圈、定时任务改成拨动开关、群成员管理离开主聊天区、用户气泡用 Bot 主题色。规格还在 `draft`，见 [10 状态](10-status.md)。
- **规格已批准，尚未标成已实现。** 活动栏按主人隔离、发布验收、一部分群规模界面、群目标、群内原位批准、群子任务接力、例行任务完整生命周期、软件执行的验收收口、插话必须马上出现、默认 Super Bot 的派工汇总。意图写在对应章的「还没收口」里，不要当成已经验收通过。
