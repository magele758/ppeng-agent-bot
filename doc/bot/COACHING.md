# Bot 调教与经验验证

Bot 设置 → 概览 →「调教与经验」保存职责、默认执行位置、执行入口、完成条件和最多四个固定流程技能。配置保存后下一步执行生效，不需要环境变量或重启。不同 Bot 各自保存，乐观版本检查拒绝覆盖他人刚保存的修改。固定技能只从已经通过 Bot 可见性、策略与任务模式筛选的目录加入短名单，不扩大工具或技能权限。

经验先记录为候选，填写规则、来源、验证场景、结果和证据位置。只有最后一条验证为通过且证据完整，才能保存为已验证；候选和退役规则不注入执行上下文。出现新失败时退回候选或退役。已经登记的验证不可改写或移除；有验证记录的规则要改义时建立新候选，旧规则退役。证据位置和结果由操作者记录，系统验证完整性与状态一致性，不自动证明业务效果或检查证据链接真实性。

对话可使用 bot_coaching_get 和 bot_coaching_save，沿用 Bot 管理工具的归属、审批和只读模式限制；保存前读取 revision，保留完整台账。

接口：GET /api/bots/:id/coaching；PUT 同地址，提交 revision、profile、lessons。未知 Bot 和跨归属访问遵守既有 Bot 访问控制。数据保存在 daemon_control 的 Bot 独立键中，不直接混入长期记忆。运行时只注入当前契约与已验证规则，作为当前授权下的默认值；候选、旧任务、引用资料不变成派工。前缀缓存不变，契约变化刷新每轮上下文。

调教流程：从真实偏差定位第一处错误 → 保存前配置快照 → 独立诊断基线 → 调整职责和流程 → 回读配置 → 相同权限与场景复测 → 逐项记录证据和未验证范围。实际执行调用、加载成功与回答复述分别评估。开发交付、研究交付、巡检报告有不同终点。rc=0、启动进程或开 auto-merge 不能替代测试、review、合并或部署验收。

不能仅凭一次问答或技能加载成功宣布 Bot 已经调教完成。机器不可达、审批阻塞、模型错误单独标记，不能计成遵守规则，也不能靠放宽权限去改善分数。忙碌 Bot 用独立诊断会话，不取消或替换它正在运行的任务。试验的模型、权限和输入必须记录，配置修改前后使用相同条件；只读探针的改善不等于真实开发交付成功率提升。
