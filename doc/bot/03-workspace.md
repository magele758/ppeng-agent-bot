# 03 工作台

Bot 工作台是列表、主对话、详情三块。切换 Bot 时，主画面、详情和还在输入的上下文一起换成新的那只，不把上一只正在吐的字留在新 Bot 的画面上。

规格：`bot-console-selection`、`bot-switch-live-turn`、`bot-panel-reset`、`bot-entry-simplification`、`bot-pin-area`、`bot-functional-groups`、`bot-group-drag-only`、`bot-detail-menu`、`bot-detail-child-tasks-tab`、`bot-detail-skill-management`、`bot-skill-panel-layout`、`bot-child-task-chat-entry`、`bot-child-task-stream-entry`、`bot-goals-panel-threshold`、`bot-goals-panel-rules`、`low-interference-onboarding-goals`、`bot-first-task-new-user`、`bot-first-task-dismissal`、`goal-update-presentation`、`bot-workspace-interaction-polish`。

## 列表

Bot 列表只放 Bot 自己的主对话和群。子任务不在这里，也不进置顶，也不算进功能分组的数量。

- **置顶区**在列表上方。钉住的是 Bot 的主对话。点进去打开的是这只 Bot 自己的对话，不是它的某条子任务。
- **功能分组**把 Bot 收成几组。分组名比 Bot 名弱一档，但要能读清。把 Bot 移到另一组只靠拖拽，没有另一套移组按钮。
- 删一组时要先说清楚影响。确认后成员回到未分组，组没有了，Bot 还在。删一只 Bot 和只删一条会话不是一回事，确认文案要把这点说出来。取消不改数据。
- 顶部只有一个「新建」。悬停或打开后可选新建 Bot、新建群、新建功能分组。三个动作各开各的界面，取消回到当前对话。

普通会话列表是子任务的入口。一条子任务的标题是任务原文，不是裸的 Bot id。能看出它属于哪只 Bot：优先是名字，没有可读名字时用一个短标记，不展示一长串 id。当前打开的那条有明确的选中状态。另一只 Bot 的子任务不会和这只混到看不出归属。没有子任务时，不多出空行。

## 切换

从 A 换到 B 的那一刻，主画面改画 B 已经有的内容。A 正在生成的占位、气泡和后面才吐出来的字，不再出现在 B 的画面上。A 的回合可以在后台继续，那是 A 的事。

迟到的「打开 A」结果不能把已经选中的 B 盖回去。

换 Bot 时，上一只的记忆面板、暂停开关和软件连接选择一并重置，避免还看着 A 的开关、改到 B 的配置。

开发时默认 Bot 的加载被取消过一次，下一次仍然要继续载入，不能永远停在没选中。

## 首次引导

只有新用户看到第一次任务引导。不是每新建一只 Bot 都再来一遍。关掉引导，或发出第一条消息之后，其他 Bot 和刷新后的页面都不再出现。

## 详情

主对话右侧有这只 Bot 的详情，可以收起。收起后对话拿回宽度。窄屏时详情盖在对话上，不把对话挤没。

页签包括定时任务、文件与资料、记忆、技能、子任务。子任务是其中一个页签，不铺在顶部。没有子任务时，这个页签里有一句空状态，顶部不留空白长列表。换 Bot 后，页签里只有新的这只的子任务。

- **定时任务：** 能看见这只 Bot 的安排，并直接开或关。切换失败时保持原状态，并说明失败，不能显示成已经成功。规格 `bot-detail-routine-switch` 还是草稿，所以这里仍是现有的开启/关闭操作，还不是拨动开关，时间也还没有按那份草稿改成一律的本地钟点。
- **文件：** 列出这只 Bot 产生的历史文件或资料。可以打开文件所在的目录。不允许的路径直接拒绝，不打开任何目录。
- **记忆：** 只显示这只 Bot 的记忆。密钥和 token 原文不出现。
- **技能：** 见 [06 记忆、技能与定时任务](06-memory-skills-routines.md)。
- **子任务：** 每条标题是任务原文。点一条，主对话区打开那条会话。列表在页签内部滚动，页签栏和关闭按钮留在屏幕里。

三块主要区域如果都是空的，各自有空状态，而不是一片空白。

## 主对话里的子任务入口

主对话流里，在对应的话附近放一块小入口，读得出每条子任务在做什么（任务原文的短摘），不把详情里的长列表铺进对话。点一条就打开那条子任务。

入口按子任务出现的时间插在对话之间：较早的在两句话之间，较晚的在较晚那句话之后，不堆在最后一句后面。另一只 Bot 的子任务不出现。没有子任务时不留空块。用户自己的话和助手回复不会被收成这个入口。

## 活动跳转

右侧活动卡有关联会话时，点击状态或摘要即可打开那条会话，整卡支持键盘访问；没有可打开会话时不呈现为可点击控件。`bot-activity-open-session` 与 `bot-activity-rail` 已通过软件验收；活动栏只汇总当前主人有权访问的在途工作，无登录本机使用安装身份。

## 目标与进展

主对话旁的「目标与进展」只在**同时有至少两件还在做的事**时出现。还在做包括排队、进行中、等待、受阻、暂停。已完成、失败、取消不占这个数。

少于两件时，面板不展示，也不留空白。目标本身还在，执行不受影响。降到两件以下时面板自己隐藏。

面板里能看状态、最近进展、下一步或等待条件、执行方式和证据。可以选中一件再追加消息，也可以暂停、恢复、取消、改优先级。

## 目标更新怎么出现在对话里

目标有值得告诉用户的变化时，对话里出现一块小卡片：标题是目标标题，状态是人话（受阻、进行中、完成等），再加一句原因。不显示以 `[goal update]` 开头的花括号原文，也不把内部编号当标题。

完成检查暂时不可用时，卡片写明证据留着待查，不把英文提示原文铺出来。没有内容的更新不制造空卡片。别的会话里的目标更新不出现在当前对话。用户的话和助手回复不会被收成卡片。

## 长列表与上下文长度

会话很长时，一次操作要在一秒内有可见反应，不持续白屏，消息不重叠。长消息默认是有界摘要，展开才看全文。阅读位置保持住；只有人本来就在底部时，新消息才把画面带下去。

最近一次已经发给模型的请求，要能看到估算的输入长度、占模型窗口的比例，以及这次请求的时间。这个数包含系统提示、工具定义和最终送出的消息。发送前的预览、发送时的估算、上游报回来的实际用量、历史累计，四者分开，缺了就显示未知或等待，不用累计用量冒充这一次的长度。

已实现的 `turn-stats-end-time` 在已结束轮次的用量行显示本地结束时间，最后一轮标为会话结束；进行中或缺少有效时刻时不显示。这里是结束时间，不是消息发送时间。
