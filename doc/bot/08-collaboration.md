# 08 协作与外部软件

Bot 可以请另一只 Bot 做事，也可以去调用已经接上的软件。两件事都带着身份和权限，不能借对方的名义扩大自己能做的范围。

规格：`bots`、`bot-product-admin`、`bot-product-p0`、`bot-product-p1`、`bot-product-p2`、`bot-software-execution`（软件执行的验收规格还没标成已实现）。

## Bot 之间

在主对话里，一只 Bot 可以给另一只有权联系的 Bot 发消息。对方的主对话收到，并开始处理。发给自己，或发给别人名下的 Bot，直接拒绝，任何一边都不写入内容。

委派给另一只 Bot 时，用对方当前的权限，见 [05 目标与子任务](05-goals-and-work.md)。对方再往下派任务，也沿用对方的权限。

协作如果拉成一组：每一项有负责人和能追踪的状态。总体完成看全组，不把协调者自己的输出当成全组完成。成员仍用自己原来的授权。局部失败时，做成的留下，只重试选中的失败成员。还在等审批的成员显示受阻，批准之后从原来的执行继续，不把已经成功的兄弟再跑一遍。

## 默认 Super Bot 的派工

意图是用进来就有的那只 Super Bot 查看其他人的状态、把工作派出去、收回成果和失败原因。被派的 Bot 自己的权限仍然有效，Super Bot 不代替人批准。

规格 `default-super-bot` 还没标成已实现。在它收口之前，派工以已经落地的 Bot 互发和委派为准。

## Super Bot 配置多机软件工厂

专项规格 `superbot-factory-setup` 已实现，与默认 Super Bot 的完整派工汇总是不同范围。安装主人或管理员可以让 Super Bot 保存机器 SSH 别名、容量、关联 Bot 和协调者，创建并关联包含自己的工厂群，用已有别名发现远端 Git 检出，并在满足连接、仓库和派单权限后发起只读试跑。

未明确要求时巡检保持关闭。配置可在“设置 → 运维 → 多机软件工厂”核对与继续修改。它不能因此获得 daemon 令牌、SSH 私钥或任意远端命令执行授权；配置与试跑完成也不等于生产全流程已经认证。

## 软件连接

连接在 Lab 里配，凭证进密钥库，不新增功能环境变量。每次写入凭证用独立引用，避免一次不确定的响应盖掉旧授权。

人能看见的是：

- 连接上了没有、范围是什么、上次验证是什么时候。
- 授权失败时说人话，并可以重新连接之后继续原任务。
- 调用使用的是这份连接自己的凭证。撤销之后再调用会被拒绝。
- 不支持的接口明确拒绝。
- 失败时不把凭证显示出来，并守住地址和结果的长度限制。
- 结果不明就留下待核对，不盲目再做一次。人可以看操作记录并登记核对结论。

第一次使用时有连接引导。可以用表单接 HTTP 或 MCP，也可以导入 OpenAPI，并滤成只读范围。高级的接口导入仍留着。创建时如果冲突或格式不对，不覆盖已经保存的连接。

`bot-software-execution` 把「真的执行并返回结果、不把一句声明当成成功」收成验收标准，目前还是已批准。上面这些是 P0/P1 已经落地的连接和回执行为。

## 产品与配置

对话里的 Bot 可以管理它负责的产品和配置：看当前值、改已有设置、说清失败原因。改配置走原来的权限和审批，不因为是「管理」就绕过。

已完成的一次交付可以另存成定时任务。表单会带上这次的来源版本、做了什么、时间、时区、输入从哪来、通知发到主对话还是一个已授权的群。来源版本只作参考，每次执行重新取输入。保存后可以再打开编辑。

通知按报告全文比较有没有变化。没到连续失败的阈值时，留下记录，不发汇总。已经存在的自动暂停保护触发时，仍马上提醒。自动发出去的报告可以先进入待审：批准只发送已经看过的这一份，不重新跑模型，也不额外批准工具。拒绝、重复批准、重启之后，都不会把没看过的内容发出去。

## 任务页和对话的分工

团队任务页看一组人的目标、完成数、谁堵住了、已有的交付。展开成员才能看到详情、回到对话处理审批，或只重试失败的那个。

单只 Bot 的定时任务仍在它的详情里改。运行记录里核对待发的报告，再决定发不发。

Bot 主对话保留执行过程。任务页不取代对话。

## 与其他应用的 Agent 协作

「设置 → 集成与可观测」提供两个入口：

- **外部 Agent 任务交接**：按接入方授权允许的 Bot，外部请求使用 `botId`。Bot 以自己的权限执行独立任务，调用方只查询此任务的结果，不获得主对话历史。可以仅授权 Bot，不授予通用执行者。
- **外部 Agent 连接**：保存远端地址、凭证、目标 Bot/执行者和允许使用连接的本地 Bot。授权 Bot 使用 `external_agent_list`、`external_agent_delegate`、`external_agent_status`、`external_agent_cancel`、`external_agent_input` 完成派工与跟踪。

连接保存立即生效，凭证不回显。对方需要支持本项目的 HTTP 任务交接协议，或部署转换适配器。接收状态不等于完成；接收结果不明时保留原派工标识重试。具体配置、接口、撤销和恢复方式见[外部 Agent 任务交接](../EXTERNAL_AGENT_HANDOFF.md)。
