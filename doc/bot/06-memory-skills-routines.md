# 06 记忆、技能与定时任务

这三样都挂在一只 Bot 上，并且分得清是谁的。普通对话仍可以读写共享的用户记忆。

规格：`bots`、`bot-scoped-skill-sharing`、`bot-detail-skill-management`、`bot-skill-panel-layout`、`bot-routine-main-session`、`bot-gateway-delivery`、`bot-product-p2`、`bot-workspace-interaction-polish`。例行任务的完整生命周期规格 `bot-routine-lifecycle` 还没标成已实现，下面「定时任务」写的是已经落地的规则。

## 记忆

一只 Bot 只能读到自己的私有记忆。另一只 Bot 的笔记不会出现。用户级的共享记忆，普通对话仍能读写，这是另一层。

子任务能用父 Bot 的记忆，规则见 [05 目标与子任务](05-goals-and-work.md)。群里的内容怎样进单聊，见 [07 群聊](07-rooms.md)。

详情和记忆页默认显示能读的摘要、记忆类型、来源数量。正文和完整来源按需展开，不用内部键名铺满页面。文件来源能打开或预览。消息来源能定位到那条消息。没有权限或不存在时说明原因，不跳到无关的地方。

记忆条目显示范围、来源、更新时间，以及最近的替换记录。旧值不参与正常召回。人说「这次先这样、以后不用记」时，这句话不进自动抽取，运行时也拒绝把它写成长期记忆。人明确纠正时，不把互相矛盾的旧内容和新内容拼成一条。

密钥和 token 的原文不在界面上显示。

`bot-history-memory` 和 `bot-identity-continuity` 仍是已批准、未标成已实现。长期历史能不能撑住「一直聊」、身份会不会在压缩和重启之后断掉，以那两份规格收口为准，这里不把它们写成已经验收通过。

## 技能

详情里能看到这只 Bot 有权使用的技能：自己的、别人共享给它的、历史共享的、公共的。没授权给它的其他 Bot 私有技能看不见。

每一项能看出来源、属于谁、是不是只读、现在是启用还是受限。同名的几份要能分开，各自看说明和正文。可以按名字或描述搜索。没有结果时是空状态，可以清掉搜索，不要说成加载失败。

使用范围：

- 可以收成一份允许名单。一个都不选，就是一个都不用，不会悄悄变回「全部启用」。
- 保存后，后面的搜索和加载按这份名单。刷新、重启还在。
- 还没保存时有提示。换 Bot 不会把没保存的选择带到另一只身上，也不会自动保存。
- 保存失败要说原因，不显示成功，不覆盖已经生效的配置，没保存的选择还留着。

共享：

- 自己的技能可以指定给哪些 Bot。接收方下一轮的搜索和加载跟着变，但仍受它自己的使用限制。界面要写出为什么还是不能用。
- 别人共享来的，只能决定自己用不用，不能改原文、不能转共享、不能撤销别人的技能。
- 撤销自己的技能后，所属 Bot 和所有接收方都不能再搜索和加载。已经出现在历史对话里的正文不会因此消失。
- 同名多份各自保存。改一份或撤销一份不影响另一份。只给了一个有歧义的名字时，要求人选择，不默认加载其中一份。

历史技能保持原来的可见范围，并标成历史共享。要改归属或共享对象时，人必须先看到将要保存的范围。

窄屏上，使用范围、保存、搜索要分区清楚，字不能被裁掉，长说明在面板里换行。

## 共享条文

分组和全局可以各有一套共享信息。同名时，分组盖过全局。其他分组、其他用户的私有信息不混进来。

页面读回的是保存之后的内容。这只 Bot 下一次请求用的是更新后的有效内容。加载失败不显示成「已经加载、但是空的」。保存失败不报成功，也不把旧范围的内容写进新范围。失败可以重试，正在编辑的内容还在。

## 定时任务

定时任务跟这只 Bot 走，用它的身份、模型和允许名单。每次触发有自己的工作会话，不复制主对话的历史、压缩状态和还没处理的审批。主对话正忙，也不挡住这次独立的工作。

主对话只在自己空下来之后收到一条摘要和链接。人可以引用这条摘要继续问，后续仍在主对话里进行，工作会话不会被重跑。

没有新情况时，任务回复 `[NO_UPDATE]`。回复去掉空白后以这个标记开头或结尾，都算静默：不往主对话发摘要，已经在主对话里的这类回执也不再显示。标记只出现在正文中间时，结论仍会送达并显示。历史里仍能看到这次运行，并标成静默，而不是成功。预检不通过则跳过，不调用模型。

详情里可以打开和关闭一条任务。关闭期间到点不跑。打开后按原来的下次时间继续。失败时开关和「还会不会跑」都保持拨动前，并说明失败。

人能看出这是只跑一次、循环，还是等事件。循环任务能查看原来的时间表达式，改完保存后下一次按新计划，取消不改变原计划。无效输入或保存失败要说明，不因为打开编辑就马上多跑一次。

同一只 Bot 上，另一个用户看不到、也改不了这条任务。

安排一条新的定时任务如果按现有规则要人确认，确认之前到点不会跑。

更细的错过补跑、租约、事件签名和投递，见 [定时任务生命周期](../BOT_ROUTINES.md)。那份是运行说明。产品上已经能观察到的是：静默不发摘要、至少一次把该发的送达、预检失败就不叫醒模型。
