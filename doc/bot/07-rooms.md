# 07 群聊

群是一份共享记录，不是每只 Bot 各说各的再拼起来。至少两只、互不重复的 Bot 才能建群。建好之后有自己的名字、成员和历史，重启还能读。

规格：`play-bot-group`、`bot-rooms`、`room-debate-mode`、`room-budgets-default-off`、`group-chat-stable-layout`、`group-member-partial-roster`、`group-mode-instant-selection`、`bot-room-sparse-routing`、`bot-room-wave-dispatch`、`bot-room-recall`、`bot-room-touched-memory`、`bot-room-speaker-identity`、`bot-room-speaker-pick`、`bot-create-named-tools`。

从 Bot 列表的「新建」里建群，选已经有的 Bot。群出现在同一条列表里，和单只 Bot 的行区分开。之后可以再加入或移出成员，不能减到只剩一只，也不能把同一只加两次。不是成员的名字不会被拉进来。

对话里可以用 `create_room` 创建，标题、成员和主持人与说的一致。工具名单里没有这项的 Bot 看不到它。

## 谁说话

以下描述按相关性回复模式。群还可保存为任务协作模式或辩论模式，见下文。

所有群都是稀疏的，包括只有两只或三只的小群。没有点名时，不是每位成员轮流说。

| 情况 | 谁说话 |
|------|--------|
| 用 @ 点了名 | 只叫醒被点到的、并且不超过这一轮人数上限的成员。没被点到的不说 |
| 点名没有命中任何人 | 群里说明没找到，不叫醒别人 |
| 引用某只 Bot 的回复 | 只叫醒被引用的成员，即使其他成员更贴题 |
| 没有 @、也没有引用 | 按名字、头衔、简介和职能组匹配，先叫醒过门槛且不超过人数上限的成员，并行回答 |
| 没人达到相关性门槛 | 整群可以零回复，两三人的小群也一样，不发兜底套话 |
| 成员选择沉默 | 不往群里发消息，不算失败，也不占用这一轮的有效发言次数。已经选中的下一位仍可以说 |

专家有实质回复后，尚未发言的群主可以补一次短收尾；没有新信息就不发。群主已经回复后，若还有明显更贴题且未发言的成员，最多再补一位；这名成员能看到已有回复，不再唤醒全体。静默标记和“我不知道”等短否定不显示，也不占有效回复次数。

被选中的成员可以同时处理，谁先做完谁先出现。群主由建群时指定，未指定时为成员列表第一只。

用户停止或取消之后，还没出现在群里的回复不再出现。初选受人数上限约束；短收尾和最多一位补充按上述规则处理，不能扩大成第二轮全体发言。达到预算，或用户暂停、移出成员，按群自己的停止规则收住。工具或费用预算导致执行中止时，这次回合显示失败及具体原因，正在执行的成员一并收口，不保留「回合已完成、成员仍运行」的矛盾状态：还在执行的成员被取消，不再继续花费，也不发言；这时已经写完回复的成员，回复照常出现在群里，不丢。群聊顶部的提示列出没有回复的成员。

每只 Bot 从这一轮一开始就用自己的身份发言，不先匿名再补名字。

## 任务协作模式

`room-task-collaboration` 已实现。群可保存为「任务协作（临时负责人）」模式；下一轮先启动一位临时负责人，由负责人按需邀请群内协作者，并为每位指定具体任务和交付证据。非负责人不能派发，群外成员不能加入，明确点名不触发未点名成员兜底。

共享记录保留负责人、任务、公开回复证据及执行状态，由负责人汇总，不自动唤醒无任务成员。预算不足时保留待核验状态。`room-task-collaboration` 与 `bot-room-tasks` 均已通过软件验收，接力仍受成员、权限和本轮人数限制。

## 辩论模式

`room-debate-mode` 已实现。群可保存为「辩论」。之后用户发出的每条未点名消息都是一个辩题，参与者在同一个回合里自动多轮交替发言，最后由裁判裁决，不需要用户逐轮 @。

怎么用：

1. 打开群聊设置，在「回复方式」里选「辩论」。选择立即生效。
2. 下方出现「辩论设置」：轮数、裁判、参与者（勾选谁参加，用上下箭头排发言顺序，填每个人的立场）。改完点「保存辩论设置」，下一个辩题生效。不填也能开辩。
3. 回到群里发出辩题。群里显示「辩论进行中：第 x / y 轮」和正在发言的成员。
4. 想提前结束就点停止。停止后不再出现新发言。

默认值：3 轮；主持当裁判，其余成员按成员顺序轮流；立场依次是「正方」「反方」。只有两名成员时两人对辩，不设裁判。主持被放进参与者时，默认也不设裁判。裁判可以改成任一成员，或选「不设裁判」。裁判不能同时是参与者。

| 项目 | 范围 |
|------|------|
| 轮数 | 1 到 10，默认 3 |
| 参与者 | 2 到 8 名 |
| 立场 | 自定义文字，最多 60 字 |
| 一场辩论的发言 | 轮数 × 人数不超过 40 条，裁决另算 1 条 |

发言规则：

- 严格一人一条、按顺序进行，不并行。同一成员每轮发言一次。
- 每位发言者都被告知当前第几轮、阶段、自己的立场，并且必须回应对方最近一条的论点。第一轮是立论，最后一轮是结辩，中间是反驳。只有一轮时只有立论。
- 辩论里不能沉默跳过。成员仍然交回沉默标记，或这一条执行失败时，群里留一句「这一轮没有给出发言，辩论继续。」，后面的轮次和裁决照常。
- 发言者能看到这场辩论此前的全部发言。其他参与者各自最近的一条是全文，不按 2000 字截断。裁判拿到整场辩论的全文。全文合计超过 6 万字时，较早的发言以缩短的形式列出，可以用只读工具取回原文。
- 辩论中主持不能再加人，发言顺序以开辩时的设置为准。开辩后再改设置，只影响下一个辩题。

上限与停止：

- 群自己的「发言数上限」打开时，一场辩论的发言总数不超过它；被截短时留最后一条给裁判。上限为 1 时没有裁决。
- 工具和费用上限照常生效，触发后这一回合显示失败及原因。
- 每分钟回复数上限照常生效。达到时群里说明等待到什么时候，时间到后从停下的那一条接着辩，不丢轮次也不重复。每轮人数上限只用于按相关性选人，不限制辩论的参与者。
- 停止群会立刻取消辩论，正在准备的那条不会发出来。只是暂停群时，辩论停在当前位置，恢复后继续。
- 进程在辩论中途重启后，这一回合标为待核对，不自动续辩，也不会重发已经发过的发言。下一个辩题可以正常开始。

在辩论群里用 @ 点名或引用某条回复，仍然是向那位成员的普通提问：只有他回答一次，不开辩。

没有结构化评分。裁决是裁判的一条普通发言，内容是双方论点的总结、交锋点和胜负理由。

## 群里能看见什么

被叫醒的成员看到的是这次推给它的那一份：群滚动纪要、群共享条文、最近的一段消息。它可以用只读的方式再去取更早的原文、附件和群产物。取不到、也没被推送的内容，不因为「它在这个群里」就自动出现。

私人对话的原文不会整段抄进群。它自己的单聊记忆可以用，所以单聊里记住的事实可能出现在群回复里。这是故意打通的，不是泄漏漏洞。

配置在 Lab 里改，保存在群设置中，不用新增环境变量。每轮的费用预算和工具调用上限默认关闭：新建的群没有这两项，在那个群的设置里可以打开，「设置 → 群规模」可以保存新群的默认预算（0 为关闭）。升级前建的群如果还带着旧默认值（费用预算 1 美元、工具调用上限 100 次），新版本第一次启动时把等于旧默认值的那一项关掉，只做一次；其它数值和之后人改的值都不动。名册和单群人数可以调高。已经存在的群，自己的发言预算保持到人去改那一群。

## 触达之后的单聊

一只 Bot 后来的单聊，可以用它这次真正碰到的群内容：推给它的纪要和最近消息、它自己取回的原文和附件、它自己发出的群消息。

没推给它、它也没取回的群消息，不进它的单聊。只发生在私聊里的审批过程，不写回群历史。

## 需要人处理的时候

默认：群里遇到要真人登录、验证或批准的步骤，转到这只 Bot 和用户的私聊里做完。群里只留一句短说明。结果不自动贴回群。私聊链也不回写群历史。

群内原位批准（`bot-room-inline-approval`）已通过软件验收，默认关闭。用户在 Lab 单独启用后，等待只挂在那个成员身上，不把整群卡在等待批准。

## 群目标、任务与规模界面

以下专项已通过单机软件验收；群成员移出主区仍是草稿：

| 规格 | 意图 |
|------|------|
| `bot-room-tasks` | 群里的子任务和成员之间的接力；进度与局部失败分别可见 |
| `bot-room-goal-intake` | 群自己的目标，以及人在群里中途插话。群目标不写进某只 Bot 的单聊目标 |
| `bot-room-console` | 大群折叠成员、搜索与整组加入、独立滚动及目标条 |
| `bot-group-members-off-canvas` | 草稿。成员管理离开主聊天区，收进群设置 |

群共享条文继续用已有的共享范围，不另建一套黑板。
