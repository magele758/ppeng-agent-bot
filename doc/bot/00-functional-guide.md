# Bot 统一入口产品功能说明

> **你只管目标，Bot 全天候为你工作。**
>
> 一个越来越懂你的 Bot，帮你管理消息、处理重复任务、整理和消化信息，让工作持续向前。

更新日期：2026-10-23 · 用途：产品功能审阅 · 范围：整个产品以 Bot 为统一入口。

这份说明按用户从提出需求到拿到成果的过程组织，集中说明产品定位、入口、功能、协作、安全与当前交付边界。详细规则继续维护在 [01–10 分章说明](README.md)中。

**产品口径：用户找到一只 Bot，说清想要的结果；Bot 持续承接对话、组织执行、保留成果，并在需要时请求人处理。** 任务、群、技能、记忆、软件连接和运维都是围绕 Bot 展开的能力。用户不需要先理解 Agent、编排器、研究引擎或工作流才能开始。

本说明随单机收尾更新。下文区分三种状态：**已实现**指相关规格标为 `implemented`；**待收口**指规格为 `approved`，可能已有部分代码，但尚不能宣称整套能力验收完成；**设计方向**指统一入口的产品组织方式或现有草稿。状态依据为仓库当前规格，验证范围见 [单机收尾](../SINGLE_HOST_COMPLETION.md)。

## 1. 产品定位与使用人群

产品首先提供一个用户可以长期托付工作的 Bot。用户说清目标，Bot 组织必要能力、持续推进并交付结果。每只 Bot 有稳定身份、固定主对话、独立能力范围和持续工作记录，既可以回答问题，也可以执行任务、协作和定期工作。

核心设计判断是：要求用户自己学习和管理 Skill、会话、连接器、子任务、Teams 及编排模式，会把完成工作的成本转移给用户。Bot 模式要把这些专业概念收进产品内部，让用户主要关注目标、结果和必要决策。这是本产品针对自身使用门槛的设计取舍，不是对所有 Agent 产品能力的概括。

| 使用人群 | 主要诉求 | 产品提供的工作方式 |
|---|---|---|
| 个人用户 | 问问题、整理资料、处理文件、持续跟进事项 | 与一只 Bot 长期对话，历史、记忆和成果可追溯 |
| 专业用户 | 研究、开发、运营等领域工作 | 配置模型、技能、工具、工作区和软件连接 |
| 多角色协作者 | 多个专业角色分工、讨论、汇总 | 多 Bot 委派、群聊和团队任务视图 |
| 自动化使用者 | 定时执行、只在有变化时通知 | 将已完成任务转为例行任务，查看运行与发布记录 |
| 安装主人与管理员 | 管理接入、授权、运行状态及机器资源 | 设置与运维辅助页面，以及已授权的 Bot 管理能力 |

这些是使用角色，不等同于系统中新增的权限角色。能做什么始终由登录身份、资源归属和实际授权决定。

### 1.1 商业定位：从长期助手到持续工作的数字团队

**从一个全天候为用户工作的 Bot 开始，按工作需要扩展为虚拟员工团队与黑灯软件工厂。**

个人用户不必为了开始使用而先组建一支团队。一个 Bot 是主要的委托与结果入口；内部需要多少技能、执行者或机器，由产品在授权范围内组织。专业用户仍可展开细节、管理成员与配置。

这两个方向与产品已有设计相符：固定身份和记忆承接长期岗位，技能与软件连接提供工作能力，目标和交付定义责任，多 Bot 协作组织分工，定时与事件触发让工作不必每次都由人发起。用户通过 Bot 统一入口分配工作、查看结果和处理例外。

商业价值主张是缩短任务等待与交接时间、减少重复操作、积累可复用的工作方法，并提高可验证交付的持续性。这些是需要通过实际业务试点验证的价值假设，不在此承诺节省比例、替代人数或收益数字。

### 1.2 24 小时虚拟员工

“虚拟员工”指承担明确职责、拥有必要工具和授权、持续保留工作上下文的 Bot。用户可以为它定义岗位目标、输入来源、交付格式、工作频率、预算和需要人工介入的情况；这些岗位约定可通过现有说明、技能、任务与配置表达，本文不宣称已新增专门的岗位配置界面。

| 岗位场景示例 | 可承接的工作设计 | 用户购买的价值 |
|---|---|---|
| 研究与情报助手 | 定期获取已授权来源、整理变化、保留依据并输出简报 | 持续跟进与可追溯的信息整理 |
| 运营助手 | 汇总业务材料、准备内容、检查变化，按规则提交发布审批 | 减少重复准备工作，保持交付节奏 |
| 开发与测试助手 | 接收问题、实现修改、执行检查并交付结果与证据 | 缩短从任务到可审阅成果的等待 |
| 运维值守助手 | 按已接入能力巡检、记录异常、在授权范围内处理或升级 | 覆盖非工作时段，及时发现需要人处理的事件 |

以上是应用方案示例，具体岗位仍取决于实际接入的工具、数据和验收规则，不表示已提供开箱即用的全部岗位套餐。

“24 小时”表达全天候承接和按需推进的部署目标：服务、机器、模型和外部连接需要持续可用，任务有触发机制、恢复机制和资源预算。它可以在无任务时等待、有事件时工作；遇到审批或未知副作用仍进入待处理状态。当前没有据此作出 7×24 可用性 SLA 或所有任务均可无人处理的承诺。

### 1.3 黑灯软件工厂

“黑灯工厂”在本产品中首先指**软件与数字任务的自动化生产体系**：由多个专业 Bot 和执行机器协作，在预先约定的范围内持续接单、生产、检查与交付。实体制造设备和产线控制不属于当前说明的能力范围。

目标流程是：**需求进入 → 协调 Bot 拆分与派工 → 专业 Bot 执行 → 自动检查与独立验收 → 汇总交付 → 按授权发布或转人工处理 → 沉淀技能与例行任务。**

人负责目标、验收标准、授权边界及异常决策；已验证的常规流程可以持续自动推进。适合探索的场景包括软件维护、批量资料加工、报告生产与规则明确的运营流程。每一类流程都需要单独验证输入、输出和失败恢复。

当前已有多目标、子任务、团队协作、交付快照、部分失败恢复、例行任务，以及多机工厂配置与只读试跑等基础。端到端“黑灯”生产还要完成具体业务流程的接线与验收，验证自动质检、调度恢复、发布与回滚、成本控制及人工升级。多机配置成功不等于生产闭环已经无人值守。

### 1.4 商业落地与价值衡量

可以按单岗位、协作团队、工厂流程三个层次组织试点。先为一个范围明确的岗位建立稳定交付，再把已验证岗位组合成团队，最后把重复生产流程部署到持续运行的资源上。这是商业落地思路，不是已经确定的收费套餐或新增功能承诺。

| 层次 | 交付给客户的内容 | 价值验证重点 |
|---|---|---|
| 单岗位虚拟员工 | 岗位职责、必要连接、技能、交付模板及例行安排 | 结果是否可用、人工介入是否减少 |
| 虚拟员工团队 | 协调与分工、成果汇总、异常升级和共享工作方法 | 交接是否更快、整体交付是否稳定 |
| 黑灯软件工厂 | 已验收的生产流程、运行资源、质量门禁和维护机制 | 持续产出、恢复能力与单位合格交付成本 |

商业效果以合格交付衡量。可沿用现有验收成功率、首次有效交付耗时、人工干预、故障恢复与成本统计；进一步评估无人介入完成率、非工作时段有效交付和连续运行可用性时，需要补充观测及统计口径，不能把未采集的数据写成已有指标。最终回报应连同模型、机器、软件连接、人工复核与维护成本一起核算。

### 1.5 核心体验：把目标交给 Bot

主 slogan：**你只管目标，Bot 全天候为你工作。**

配套说明：**一个越来越懂你的 Bot，帮你管理消息、处理重复任务、整理和消化信息，让工作持续向前。**

这里的“只管目标”是降低使用门槛的设计原则：用户表达需求、授予必要权限、判断成果；系统负责能力选择、上下文管理、执行分工、进展追踪和恢复。必要的登录、授权、澄清和高影响决策仍需用户参与。“全天候”沿用第 1.2 节的运行条件，属于产品定位，不新增服务可用性承诺。

| 面向用户的问题 | Bot 模式要承接的复杂度 | 理想的用户体验 |
|---|---|---|
| 不知道该找哪个 Skill、用什么工具 | 根据目标选择已授权能力，缺项时提供必要接入引导 | 直接说想做什么 |
| 不知道要新开会话还是继续旧会话 | 保留长期主对话，管理历史、记忆与工作归属 | 接着说，不反复交代背景 |
| 不知道何时拆子任务、启用 Teams | 根据任务需要组织执行者和协作，汇总结果 | 委托给同一个 Bot，查看整体进展 |
| 消息散落在多个地方，难以跟进 | 在已接入和授权的渠道内识别重要信息、待办与后续动作 | 知道什么需要处理、什么已经推进 |
| 重复的事每天都要重新交代 | 把有效做法沉淀为可复用任务与触发安排 | 交代清楚后按约定持续做 |
| 信息看了很多却没有形成判断 | 整理、去重、关联背景、提炼结论并保留来源 | 获得与自身目标有关的要点和下一步 |

后面三项构成面向个人用户的核心场景：**管消息、做杂事、消化信息。** 消息管理包括整理与跟进；对外回复或发送仍需对应渠道能力及授权，不能由“管理消息”自动推导为允许代发。当前连接、记忆、目标、例行任务等提供组成能力，上述完整跨渠道体验是产品设计方向，尚不能宣称已全部开箱即用。

判断交互是否符合这一定位，可以问：用户是否又被迫学习一个内部概念？这一步能否由 Bot 根据已知信息完成？用户能否直接找到结果或明确的下一步？高级配置保留给需要的人，日常主流程围绕目标、进展、成果和必要决策展开。

### 1.6 长期价值：积累一个真正懂自己的 Bot

**创建一只 Bot 应当简单，培养一只真正懂用户、可靠替用户工作的 Bot 则是长期积累。** 名字和模型只是起点；更有价值的是用户逐渐交给它的信息、关联消息、偏好、项目背景、有效工作方法和经过验证的交付记录。

这些积累可以形成持续改善的使用过程：**完成工作 → 留下可追溯的背景与方法 → 下次少交代、少纠正 → 更稳定地交付 → 用户愿意托付更多工作。** 长期身份和记忆让服务关系得以延续，实际成果让用户建立信任。

从商业上看，重新培养另一只同样了解用户的 Bot，需要重新建立上下文、连接、工作约定和信任。这种重新建立合作关系的成本，可能带来较高留存和使用黏性；它应建立在持续有用、可靠交付之上。用户对自身数据的查看、纠正、删除、授权撤销及迁移需求应作为产品设计要求考虑，不能把限制用户取回数据当作留存手段；完整数据迁移能力不在此标为已实现。

因此，“用户离不开”应作为价值假设验证：用户是否持续主动委托任务，重复说明背景是否减少，人工纠正是否下降，定期工作是否稳定完成，以及成果是否真正被采用。已有统计可提供部分依据；留存、使用深度、上下文复用和重新配置成本需要另行定义与采集，不能用历史消息数量直接证明商业价值。

## 2. 统一入口与信息架构

### 2.1 主体验

产品围绕一条路径展开：

**进入自己的 Bot → 说清目标 → 看进展／处理必要决策 → 收到成果 → 持续跟进。**

技能选择、连接使用、会话整理、子任务和团队调度由产品在背后承接；只有缺少必要信息或授权时才引导用户处理。专业管理页是可展开的辅助能力，不应成为完成第一项工作的必经学习流程。这是统一入口的目标体验，当前界面差异见下文。

| 区域 | 用户在这里做什么 | 与 Bot 的关系 |
|---|---|---|
| Bot 工作台 | 选择 Bot 或群，创建、置顶、分组 | 日常工作的统一入口 |
| 主对话 | 提需求、补充信息、问进展、调整方向、看回复 | 每只 Bot 一条长期主对话 |
| Bot 详情 | 查看定时任务、文件与资料、记忆、技能、子任务 | 当前 Bot 的能力与成果侧栏 |
| 目标与进展 | 同时管理多件未完成工作 | 展示 Bot 的持久目标及执行证据 |
| 任务辅助页 | 查看队列、协作成员、运行记录与待处理事项 | 对话之外的集中管理与追踪视图 |
| 知识与记忆 | 检查来源、维护事实和偏好 | 支撑 Bot 后续回答与执行 |
| 设置与运维 | 管理模型、安全、工具、连接、健康和工厂 | 产品运行与能力配置，不要求日常用户先进入 |
| 普通会话与历史入口 | 查看兼容会话和独立执行记录 | 保留已有数据及子任务访问路径 |

**当前入口：**首页和无效地址默认进入 Bot。导航继续提供 Bot、Chat、Agents、任务、知识、设置，已有普通会话与子任务入口仍可访问。

### 2.2 Super Bot 的位置

Super Bot 的产品角色是默认总助手：承接没有明确归属的需求，了解已有 Bot，协调分工并收回成果。用户仍能直接找专业 Bot，不需要所有工作都经 Super Bot 转发。

默认创建／选择、查看名册、派工与结果汇总的组合规格 `default-super-bot` 已通过单机软件验收。**已实现的专项能力**包括 Super Bot 为有权限的主人配置多机软件工厂及发起只读试跑，详见第 14 节。

## 3. 产品对象与归属

| 对象 | 功能定义 | 主要边界 |
|---|---|---|
| Bot | 有名字、外观、模型、工具、技能和权限的长期助手 | 不等于一个临时执行会话 |
| 主对话 | 用户与这只 Bot 持续交流的记录 | 压缩、停止、换模型不更换主对话身份 |
| 目标 | 用户希望达到的结果 | 一次执行结束不代表目标已经完成 |
| 执行／子任务 | 为推进目标展开的一次工作或独立会话 | 必须能追溯到所属 Bot、任务和结果 |
| 交付 | 某次执行的报告、产物、回执及验证情况 | 用户上传的材料不冒充 Bot 产物 |
| 例行任务 | 一次性、周期性或事件触发的工作安排 | 每次运行有独立工作记录 |
| 群 | 多只 Bot 共享的讨论空间 | 有自己的历史，不拼接成员私聊全文 |
| 功能分组 | 整理 Bot，并提供技能或共享条文范围 | 不等于群聊，也不等于协作任务 |
| 技能 | 可检索、加载和受控共享的工作方法 | 可见、启用、允许使用分别受范围约束 |
| 记忆 | 供以后使用的事实、偏好和工作知识 | 必须区分所属、来源及适用范围 |
| 软件连接 | 已配置的外部系统接口、凭证引用和授权范围 | 接上接口不代表得到全部操作权限 |

## 4. Bot 创建、身份与管理

**已实现。**用户从列表的“新建”选择 Bot、群或功能分组，各自进入独立表单。创建 Bot 填名称、显示标题、描述、脸型与颜色；未指定外观时按名字生成默认脸。非法名字或重名不会创建，取消不产生数据。

也可以在对话里要求有相应工具权限的 Bot 创建 Bot 或群。创建只保存身份和已配置的模型引用，不把 API key、密码或令牌写进 Bot。

每只 Bot 可跟随全局模型，或固定使用一个已配置模型；选择持久保存。对话头部进入该 Bot 已有的权限设置，不建立第二套授权系统。

列表、头部、详情用一致的脸和名称。工作期间持续显示状态动画；空闲列表可有轻微动作；启用减少动态时保留可辨识的状态而减少动作。身份和动画都按实际工作的 Bot 展示，不让整个群跟着一名成员一起变成工作状态。

Bot 可以置顶、归入功能分组。移组使用拖拽；删除分组后成员回到未分组，Bot 本身保留。删除 Bot 与删除会话须明确区分影响。

旧数据没有主人时，不因第一个打开它的人而自动转移归属。旧版默认完全放行的 Bot 会提示用户处理，不静默提权或改档。

详细规则：[身份与名册](02-identity.md)。

## 5. 工作台与首次使用

**已实现。**工作台以列表、对话、可收起详情组成。窄屏详情使用覆盖层，关闭后回到对话。新用户可直接输入第一件事或选择示例；关闭引导或发送首条消息后，不因换 Bot 再次打扰。

Bot 侧栏只显示主对话和群，不把子任务铺成额外的 Bot。子任务可从主对话内的任务入口、详情子任务页签和普通会话列表打开，标题尽量保留任务原文并标明所属 Bot。

切换 Bot 后，对话、详情和配置上下文同步切换；前一只 Bot 的迟到回复不能串进当前画面。后台工作可继续。长对话按需加载，浏览旧消息时保留位置，不能一有新消息就强拉到底。

活动卡有对应会话时，整卡可以点击或通过键盘打开该会话；没有可达会话时不伪装成跳转控件。活动栏按主人隔离的 `bot-activity-rail` 专项已通过软件验收。

详细规则：[工作台](03-workspace.md)。

## 6. 持续对话与输入

### 6.1 交流方式

**已实现。**用户在固定主对话里持续提问、发任务、引用回复和补充材料。回复支持流式呈现；推理、工具信息和长内容按需展开。引用区显示作者与摘要，取消引用保留输入草稿，发送后仍保留原消息关系。

Bot 忙时仍能接收用户要求继续执行的追问，持久保存并在后续轮次处理；同一输入不能重复执行。仅保存且未要求运行的消息不会因为当前回合结束而自动执行。待审批、取消或待人工核对时，追问不能绕过这些状态自动续跑。

“插话立即上屏、失败恢复草稿”的 `bot-steer-visible` 专项已通过软件验收。

### 6.2 命令与压缩

| 输入 | 行为 |
|---|---|
| 整句 `/new` | 在原主对话内压缩较早内容，不新建主对话 |
| 整句 `/stop` | 停止当前回合，保留对话 |
| 整句 `/model 供应商/模型` | 切换这只 Bot 后续使用的已配置模型 |
| `/model default` | 恢复跟随全局默认 |

句子中提到命令、或命令文字带附件时按普通消息处理。不明确或不存在的模型不覆盖原选择。

主对话达到真实模型窗口约一半时进行结构化摘要，到 85% 时进一步压缩；摘要保留目标、约束、决定、进展和下一步。工具调用与结果保持配对，较早原文有归档可检索。当前请求估算、上游实际用量、累计用量分别展示，不混成一个数字。

图片历史继续保留；换成不支持图片的模型后，不因历史图片让所有后续对话持续失败。本轮新图不兼容时明确提示，不假装识别成功。

### 6.3 下一步行动建议

**已实现。**Bot 回复结束、输入框为空时，由模型基于本次对话生成下一步行动建议，以淡色提示展示。建议应指向具体对象与可执行动作，没有合理下一步时允许为空，不用固定套话填充。正文最多 500 字。

按 Tab 才采纳为真实输入，用户可修改后再发送；直接打字则让位，未采纳的建议绝不自动发出。可关闭建议功能。

同一轮最多调用一次推荐模型，并保存结果；切换会话再回来、刷新或重启后可复用。空结果及失败不造成同轮重复调用，新轮不被旧轮迟到结果覆盖。

详细规则：[对话](04-conversation.md)。

## 7. 目标管理与自主执行

**已实现。**Bot 区分新目标、已有目标的补充、进展查询、暂停／恢复／取消和闲聊。一句话可包含多个意图；进展查询不凭空创建新任务。目标归属不明确时，只暂停有歧义的修改，其他工作继续。

| 状态 | 对用户的含义 | 后续处理 |
|---|---|---|
| 排队 | 已收到，等待资源或执行时机 | 可查看、调整或取消 |
| 进行中 | 正在推进 | 看进展、补充约束或停止 |
| 等待 | 等指定事件或条件 | 查看唤醒条件 |
| 受阻 | 有具体阻碍，暂时不能继续 | 看原因，补权限／输入／核对结果 |
| 暂停 | 主动暂停 | 用户恢复或取消 |
| 完成 | 目标已通过独立完成核对 | 查看交付，继续修改或复用 |
| 失败 | 执行明确失败 | 看已有成果及失败原因，决定重试 |
| 取消 | 不再推进 | 保留记录，不被迟到结果重新启动 |

至少两件未结束工作时显示“目标与进展”；只有一件时不占额外面板，目标仍在运行。完成、失败、取消进入可展开的目标历史。

Bot 根据可用工具、权限、工作区、预算和适配器状态选择做法。简单问题直接答；独立并行工作可拆子任务；专业工作可委派其他 Bot；可用时采用研究配置、网页／桌面能力、动态工作流、Team 或 Swarm。某种能力未接入或不健康时说明限制，不因产品里存在相关模块就假定可以自动调用。

只有一件工作时主 Bot 自己推进；多件同时推进时保留主对话协调，多余工作各有独立子任务。子任务可检索父 Bot 授权的上下文、文件、技能和记忆，不能任意访问其他 Bot 私有数据或改写父记忆。

约束更新产生新版本，旧执行的晚到结果不能直接把新版本判为完成。目标完成要核验证据，优先使用文件、构建或实际回执；核验不可用则受阻，不能用“我做完了”替代。

并发、预算、尝试上限与策略在 Lab 保存后供下一次派发使用。单次循环步数与目标尝试次数分开；无步数上限也仍受停止、审批、错误处理和循环检测约束。宿主进程离线时不会继续产生新的调度。

详细规则：[目标与子任务](05-goals-and-work.md)。

## 8. 交付、版本与效果统计

**已实现。**每次执行单独保存交付快照：报告、本次产物、软件回执、验证情况和失败原因。报告可导出，文本产物可限量预览、下载；缺少来源或回执时保持缺失，不编造证据。

用户可以基于某一交付版本继续修改，新成果记录来源和版本关系，旧版本仍可查看。无需重新从长聊天里粘贴整份成果。

多人协作同时展示已完成与未完成部分；只有协调者回复了不能视为整组完成。失败恢复只重跑必要成员，成功成果保留。外部效果不确定时先人工核对，不盲目重复写入或发送。

用户可记录交付验收。效果统计支持时间范围，包含首次有效交付耗时、验收成功率、已记录的人工干预次数、故障恢复成功率和成功交付成本。统计需说明分母和样本来源；没有上游账单回执的成本保持未知，Token 定价估算不等于实付账单。

依据：`bot-product-p0`、`bot-product-p2`；实施记录见 [产品优化进度](../BOT_PRODUCT_PROGRESS.md)。

## 9. 记忆、文件与技能

### 9.1 记忆与历史

**已实现的基础能力。**Bot 私有记忆与共享用户记忆区分。界面可查看内容、范围、来源、更新时间及替换记录；历史值不继续参与正常召回。消息来源可定位，文件来源可预览或打开，无权限或缺失时给出原因。

临时任务要求不自动变成长久偏好。用户纠正事实后，后续使用纠正后的内容，不把互相矛盾的新旧事实简单拼接。可纠正、删除或撤销相关记忆；敏感凭证原文不在记忆面板展示。

文件与资料页集中查看 Bot 相关历史产物和材料，可打开允许访问的目录。工作区决定文件操作范围，路径不可用或越界时不能悄悄换到另一目录执行。

长期历史、压缩后身份连续性的专项已通过软件验收；自动化检查覆盖来源、权限、预算与持久身份，不等于保证无限长对话的模型质量。

### 9.2 技能与共享条文

**已实现。**Bot 详情可搜索、查看和选择技能，区分自有、授权共享、历史共享和公共来源。同名技能分别显示，来源不明确时不能随便取其中一份。

保存技能范围后，后续检索与加载遵守范围；明确空选保存表示禁用全部技能。保存失败保留草稿和此前生效配置，换 Bot 不串配置。

自有技能可共享给指定 Bot；接收者只能决定是否使用，不能修改原文、转共享或撤销源技能。撤销后停止新的检索与加载，历史对话已经出现的正文不被抹掉。

分组和全局可维护共享条文，同名时分组覆盖全局。保存后下一次请求使用有效内容；其他组、其他用户的私有信息不混入。

详细规则：[记忆、技能与定时任务](06-memory-skills-routines.md)。

## 10. 定时、例行与持续跟进

**已实现的基础及成果复用能力。**用户可安排一次性、周期性或事件触发任务，查看、编辑和启停；关闭期间不执行，保存失败保持原计划。需要确认的安排在确认前不运行。

例行任务使用所属 Bot 的身份、模型和允许名单，每次触发独立工作会话，不复制主对话全部历史或待审批状态。主对话忙时不阻塞独立运行，结果摘要等待主对话合适时机送达。用户引用摘要追问，不重跑原任务。

完成任务可“保存为例行任务”，表单带入来源交付与执行内容，再配置时间、时区、输入来源、输出到 Bot 对话或已授权群，以及通知策略。来源版本作为参考，每次运行重新获取输入。

| 通知选择／情况 | 行为 |
|---|---|
| 仅变化时通知 | 比较报告全文，未变化不重复发汇总 |
| 连续失败达到阈值 | 留存每次记录，达到配置次数后提醒 |
| 自动暂停保护触发 | 即时提醒 |
| 发送前审批 | 审核本次报告与目的地，批准后只发布该版本，不重跑模型 |
| 没有更新 | 静默留存记录，不向主对话发无意义摘要 |
| 预检不通过 | 跳过本次，不调用模型 |

发送审批与工具操作审批相互独立。批准报告不能顺带授权新工具调用。错误投递、未知副作用、错过补跑与租约恢复已按 `bot-routine-lifecycle` 通过软件验收。

详细规则：[定时任务](06-memory-skills-routines.md#定时任务)、[生命周期设计](../BOT_ROUTINES.md)。

## 11. 多 Bot 协作与群聊

### 11.1 委派与团队工作

**已实现。**Bot 可向同一授权范围内的另一只 Bot 发消息或委派任务，目标 Bot 按自己的权限处理。不能发给自己或跨越其他用户的私有范围。团队视图展示统一目标、成员状态、完成数、阻塞点与已有成果，可展开成员并回到对话处理。

局部失败只继续必要工作；待审批成员批准后续跑原执行，不能重做成功成员的外部操作。默认 Super Bot 的名册、派工、回收、汇总组合已通过软件验收。

### 11.2 群创建与发言

**已实现。**群至少包含两只不同 Bot，有独立名称、成员、主持人和历史。创建时可指定群主；未指定则使用成员列表第一只。成员变更不能使群只剩一只或产生重复成员。

以下是按相关性回复模式的规则；任务协作模式见下文。

| 用户行为 | 谁处理 |
|---|---|
| @ 指定成员 | 仅命中的成员，受本轮人数限制 |
| @ 没有命中 | 提示没找到，不唤醒无关成员 |
| 引用某只 Bot 的回复 | 仅被引用的成员 |
| 未点名也未引用 | 根据名字、头衔、简介和职能组选出相关成员，先并行回答 |
| 没有相关成员达到门槛 | 可以零回复，包括两三人的小群 |

专家实质回复后，尚未发言的群主可补一次短收尾；没有新增信息则不发。群主已回复后，如另有明显更相关成员，可最多再补一位，不再次唤醒全体。静默标记及“我不知道”等短否定不展示为群消息，也不占有效回复次数。

停止后未发出的回复不再送入群。发言从开始就带真实 Bot 身份。

### 11.3 群与私聊的知识边界

成员获得本轮推送的纪要、共享条文和最近消息，可按权限只读找回更早原文、附件或产物。没有被推送、也未主动取回的内容不自动进入它的私聊记忆。

成员可以使用自己的私聊记忆辅助群内回答，因此个人事实可能出现在群回复中；产品不承诺“私聊记忆绝不影响群回复”。完整私人对话不会直接拼进群历史。

需要真人登录、验证或批准时，当前默认引导到对应 Bot 私聊；群里保留短说明，私聊审批过程和结果不自动回写群。

已实现的 `room-task-collaboration` 提供可保存的任务协作模式：当前消息先由一位临时负责人推进，负责人可邀请群内成员并指定任务与交付证据，最后汇总；共享记录保留执行状态与公开回复证据。明确点名不会额外唤醒未点名成员。

群目标、成员接力、群内原位批准及大群界面均已按各自专项通过软件验收。群内批准默认关闭，单独启用后只挂起对应成员。

详细规则：[群聊](07-rooms.md)。

## 12. 软件连接与外部入口

**已实现的连接与回执能力。**默认表单支持 HTTP、MCP，支持导入 OpenAPI 并筛选只读操作，也保留高级自定义接口入口。格式错误、名称冲突或不支持的接口不覆盖已有有效连接。

连接展示授权范围、可支持的任务及最近验证时间。执行使用本连接的凭证引用，凭证放密钥库，界面不回显；撤销或失效后明确拒绝并给出修复入口，恢复连接时保留任务上下文。

Bot 根据实际回执说明成功、失败或待核对，不把“已连接”“已提交”当作任务完成。`bot-software-execution` 的 HTTP/OpenAPI 与 MCP 执行器已通过软件验收，未支持接口仍明确拒绝。

已有 IM／Webhook 等外部接入可以在配置与授权后承接消息；已绑定 Bot 的入站沿用主对话与命令语义。不同渠道能力并不相同，不能理解为任意聊天软件都支持双向控制或一键授权。当前平台清单以 [IM 接入说明](../IM_AGENT_INTEGRATION.md) 为准。

详细规则：[协作与外部软件](08-collaboration.md)。

## 13. 权限、审批与恢复

**已实现的基础规则。**每只 Bot 有独立权限档位、工具范围和技能范围。默认自动模式按既有规则执行，需要审批的仍然审批；切换完全放行要二次确认。计划模式与更严档位继续限制执行，完全放行不等于取消所有数据边界与沙箱限制。

同一 Bot 子任务继承真实来源权限，不因拆会话重复确认已生效档位；跨 Bot 委派使用接收方权限，不能用源 Bot 的权限提权。已有待审批动作不会因为切档或新建子任务被自动批准。

审批展示来源任务、对象、完整待执行内容或配置差异，凭证脱敏。无人处理按现有十分钟期限过期，过期不算成功；批准只恢复相关执行，不表示任务已完成。

| 异常 | 用户看到的结果 | 恢复原则 |
|---|---|---|
| 连接中断 | 状态暂时不可确认、最后更新时间 | 重连读取最新状态，不假装空闲或完成 |
| 软件授权失效 | 缺少授权与修复入口 | 修复后继续原任务 |
| 外部效果未知 | 待核对及操作记录 | 核对前不自动重复外部动作 |
| 成员失败 | 已有成果与失败部分分开 | 只重试必要成员 |
| 完成核验不可用 | 受阻、证据待查 | 不自动宣称完成 |
| 配置保存失败 | 原配置仍生效、编辑内容保留 | 可重试，不显示假成功 |

重复检测可选择仅弱模型、全部模型或关闭，保存后下一轮生效。关闭重复检测不关闭敏感文件拒绝、沙箱、审批或连续失败保护。

语言支持中文／英文，偏好在浏览器保存。产品策略优先通过 Lab 持久配置即时生效，密钥、上游连接和进程启动配置另按部署需要管理。

详细规则：[安全与设置](09-safety.md)。

## 14. 运维、软件工厂与高级能力

产品运行支撑页负责模型接入、执行轨迹、健康、工具、安全、连接和多机软件工厂。日常任务从 Bot 发起，必要时跳到这些页面配置或核对。

**已实现的 Super Bot 工厂配置范围：**

- 有权限的安装主人可让 Super Bot 保存机器 SSH 别名、容量、关联 Bot 与协调者。
- 创建包含 Super Bot 的工厂群并关联配置；未指定协调者时使用 Super Bot 自己。
- 用已有 SSH 别名发现远端 Git 检出；只发现一个仓库时可填入该路径。
- 默认不开启巡检，明确要求后再开启；配置后可继续修改。
- 满足连接、仓库、派单权限等条件后发起只读试跑。
- 非主人或管理员不能修改配置；Bot 不获得 daemon 令牌或 SSH 私钥。

这项 `superbot-factory-setup` 已实现，范围是配置与只读试跑，不能推导为任意命令、生产发布或全流程无人值守已认证。多机生产就绪、Evolution、自愈、深度研究等另有专项生命周期与验证要求，不能仅因为模块存在就自动归入普通 Bot 的可用执行方式。

参考：[多机生产就绪计划](../MULTI_MACHINE_PRODUCTION_READINESS_PLAN.md)、[自主执行说明](../BOT_AUTONOMOUS_EXECUTION.md)。

## 15. 典型完整使用流程

| 场景 | 操作过程 | 应拿到的结果 |
|---|---|---|
| 第一次交付 | 找 Bot → 描述任务 → 补齐必要连接或权限 → 执行 → 查看交付 | 有结果、验证情况，或明确失败与下一步 |
| 同时推进两件事 | 追加独立需求 → 分别形成目标 → 看目标面板 → 点开子任务 | 两件事可区分、各有进展和归属 |
| 修改已有成果 | 打开交付 → 基于该版本继续修改 → 再次验收 | 新旧版本保留关系，旧结果不丢 |
| 长期跟进 | 完成一次工作 → 保存为例行任务 → 配时间、时区、输出与通知 | 独立运行记录，按规则提醒 |
| 专家讨论 | 建群 → 提问或 @ → 专业成员答复 → 按需短汇总 | 有关者参与，无关者不刷屏 |
| 修复局部失败 | 查看失败成员与已有成果 → 修授权或核对 → 仅续跑必要部分 | 保留成功交付，不重复已完成动作 |
| 建立长期偏好 | 告知偏好 → 查看记忆来源与范围 → 纠正旧值 | 后续使用有效偏好，临时要求不污染长期记忆 |
| 准备多机工厂 | 告知已配置 SSH 别名 → 保存机器和群 → 查仓库 → 只读试跑 | 可在运维页核对配置及试跑结果 |
