## 回退与复核

1. 暂停向待切换的实例派发新任务，等待正在执行的工具批次结束，按现有发布程序切回变更前的 daemon、core 和 agent-loop 整套产物。保留 stateDir、模型配置和会话库。源码分支使用 git revert 回退本次合并后重新构建和发布。
2. 无数据库结构迁移。旧版忽略 daemon_control 中以 request-context:v1: 和 request-wire:v1: 开头的派生值；无需删除账本、事件、聊天消息或恢复旧数据库备份。
3. 打开原会话，要求仅依据既有证据回答，检查会话 ID、旧工具结果、答复、权限及新回合状态。隔离演练已用旧版二进制打开候选版的同一 SQLite 库和会话，正确复述 DNS_TIMEOUT、trace-4，无额外工具执行。
4. 若发现来源不可追溯、撤权后仍能执行、工具重复派发、日期错误或确认的缓存回退，先执行上述回退。排查时按 request_prefix 和 turn_end 对照实际输入变化与上游 usage。缺少上游用量的请求单独统计。
