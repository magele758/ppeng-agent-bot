# 群聊任务协作实验

群聊设置新增 `task-collaboration`（任务协作），现有 coordinator 与 all-members 保留。设置持久化到群配置，下一轮生效，不使用环境变量。

每轮先选一个临时负责人：明确点名/引用优先，否则按已有相关度评分，未命中时用群主持人兜底。未命中任何成员的明确 @ 不启动其他人。所有成员仍沿用现有租户、工具、审批与预算边界。

负责人使用 `room_route_turn` 邀请协作者时，必须提供 `assignments: [{ botId, task, evidence }]`。只接受本群成员，每个协作者只执行一次；预留负责人收尾的发言预算，不能借分工突破人数/工具/费用上限。协作者只做指定任务并提供证据或阻塞原因。角色为本轮临时负责人，不改变群主持人或成员权限。

共享记录复用群目标/子任务存储。协作者公开回复保存为 materialIds 和 summary，仅进入“待负责人核验”，不因为发言结束而完成。负责人在收尾阶段使用 `reviewedTaskIds` 验收任务；完成主目标还必须提交 `completeGoal: true`、`verificationSummary` 和 `evidenceMessageIds`，后者必须引用本轮已公开的 Bot 结果。没有证据、存在未验收任务、成员取消或退出，都不能完成主目标。验收是模型负责人作出的判断，并非独立证明器。

即使没有协作者，正常预算下仍有负责人收尾阶段：先发布交付，再核验。预算只有一轮、工具预算耗尽、静默或未调用验收工具时，目标保留为待核验；不会伪装成成功。当前实验按每条用户消息建独立目标，未自动合并跨消息目标，也不自动恢复历史待核验目标。

群聊上方的“协作记录”默认折叠，保留负责人、任务、预期证据、实际结果及状态。完成与失败留在历史。停止群聊取消当前目标，迟到回复不会写入证据；移出协作者保留取消任务，移出负责人取消该轮。

对比实验应统一总预算，记录完成率、验收结果、重复工作、人工介入与成本；任务协作的收尾核验本身需要一轮预算，不能只比较发言数量。
