# 协作质量门禁验证 · 2026-11-11

Swarm 不再把成员结束或固定分数当作品质通过。独立审查检查实际产物，独立测试使用真实命令执行证据；Orchestrator 的 review/test 仅接受完整的结构化通过结果。失败、缺证据、权限不足、审批未完成、超时和取消均有阻断回归。

## 真实模型样本

[脱敏证据](collaboration-quality-live-2026-11-11.json)记录最终生产源码四个核心文件的 SHA-256，以及既有配置模型 `grok/grok-4.7-build-fast@500k` 的独立本地 Git 仓库试验：一个实现会话、Swarm 审查/测试两个会话、Orchestrator 审查/测试两个会话。任务为按账户汇总整数分金额、排序并拒绝非法整数与溢出。5 项事先固定的验收测试通过；操作员脚本再次独立运行测试，退出码为 0，验收文件 SHA-256 未变，宿主独立执行的 Git 基线差异检查退出码也为 0。测试阶段使用事先声明的固定命令，探索性测试提议与本次验收分开。

附加负向试验将实现临时替换为始终返回空数组的错误版本。独立真实模型测试者执行原测试得到非零退出码，质量门禁拒绝该交付。恢复原实现后，操作员复验退出码重新为 0。不是只让模型口头报告失败。

重现入口（须显式选择已有模型和新的隔离输出目录）：

```sh
node scripts/agent-eval/collaboration-quality-live.mjs <settings-root> <configured-bot-id> <new-output-directory>
node scripts/agent-eval/collaboration-quality-negative-live.mjs <settings-root> <configured-bot-id> <completed-trial-directory>
```

隔离运行显式授权 work_evidence，用来执行这项任务的本地测试；没有修改生产 Bot 的配置、凭证或权限。不要在生产工作区使用负向试验。

首两次试验分别暴露无收件人的信箱交接查找，以及网关隐藏调用编号导致检查者查找运行记录的问题；两次中止记录保留在本机隔离输出中，没有计作成功。实现者现由调度器直接接收结果；证据用工具名加路径/命令引用，由宿主解析为真实持久编号。后续复跑保留了两类额外失败：路径表示差异造成的误拦截已修复；未初始化 Git 的试验目录使检查者的 git diff 命令失败，门禁正确拒绝。试验入口现先创建本地 Git 基线，固定验收文件可用哈希和差异同时核对；不通过忽略失败命令来获得通过。另外保留了测试助手写错额外断言导致的拒绝，以及只读审查者尝试执行其他阶段指令导致的无效报告。角色提示现明确把交付请求视作检查对象，审查只检查源文件与测试文件，执行由独立测试阶段负责；没有降低测试证据要求。最终正向、负向和源码指纹已写入同一证据 JSON。各次调试改变了条件，不作为同条件成功率统计。
