# 协作质量门禁验证 · 2026-11-11

Swarm 不再把成员结束或固定分数当作品质通过。独立审查检查实际产物，独立测试使用真实命令执行证据；Orchestrator 的 review/test 仅接受完整的结构化通过结果。失败、缺证据、权限不足、审批未完成、超时和取消均有阻断回归。

## 真实模型样本

[脱敏证据](collaboration-quality-live-2026-11-11.json)记录既有配置模型 `grok/grok-4.7-build-fast@500k` 的独立本地试验：一个实现会话、Swarm 审查/测试两个会话、Orchestrator 审查/测试两个会话。任务为按账户汇总整数分金额、排序并拒绝非法整数与溢出。5 项事先固定的验收测试通过；操作员脚本再次独立运行测试，退出码为 0，验收文件 SHA-256 未变。

附加负向试验将实现临时替换为始终返回空数组的错误版本。独立真实模型测试者执行原测试得到非零退出码，质量门禁拒绝该交付。恢复原实现后，操作员复验退出码重新为 0。不是只让模型口头报告失败。

重现入口（须显式选择已有模型和新的隔离输出目录）：

```sh
node scripts/agent-eval/collaboration-quality-live.mjs <settings-root> <configured-bot-id> <new-output-directory>
node scripts/agent-eval/collaboration-quality-negative-live.mjs <settings-root> <configured-bot-id> <completed-trial-directory>
```

隔离运行显式授权 work_evidence，用来执行这项任务的本地测试；没有修改生产 Bot 的配置、凭证或权限。不要在生产工作区使用负向试验。

首两次试验分别暴露无收件人的信箱交接查找，以及网关隐藏调用编号导致检查者查找运行记录的问题；两次中止记录保留在本机隔离输出中，没有计作成功。实现者现由调度器直接接收结果；证据用工具名加路径/命令引用，由宿主解析为真实持久编号。

## 回归与审查

13 项针对性回归通过，包含空/失败/畸形报告、精确逐项覆盖、伪造引用、成功后失败的测试、失败后成功重测、用户/租户身份、父 Agent 与会话两层白名单、空列表重置、独立检查者、超时、异常、并发暂停及取消后不再启动下一检查者。

独立代码审查发现的问题均已修复后再提交。原始整库本地单测执行 6,483 项，其中 6 项受首次离线依赖中 Electron 安装不完整及 PRD 尚未提交的清洁性检查影响；修复本机依赖并提交后，相关 PRD/原生依赖 23 项重验通过，桌面 ASAR 检查通过，缺少打包产物的检查按原规则跳过。整库最终判定以 PR 的干净环境完整 CI 为准，不把局部重验写成整库全绿。

形式验证保留原配对、生命周期、真实重启与多进程范围；源文件映射按实际改动复核，并补齐了既有 abort-lineage 依赖。它们不是多 Agent 业务正确性的形式证明。
