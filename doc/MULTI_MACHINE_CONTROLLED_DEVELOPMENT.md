# 多机软件工厂：第二阶段受控开发

验收：[multi-machine-controlled-development](../acceptance/multi-machine-controlled-development.yaml)。范围依据：[已确认方案](MULTI_MACHINE_CONTROLLED_DEVELOPMENT_PLAN.md)。第一阶段说明见[只读试运行](MULTI_MACHINE_READONLY_PILOT.md)。本次实现和验证记录见[第二阶段报告](reports/multi-machine-controlled-development-review-2026-10-19.md)。

## 终点与权限

任务沿批准需求→指定机器→独立仓库→失败测试→开发→检查→同机独立评审→有限修复→本地READY运行。READY指向本地提交与完整证据，不代表已推送、远端CI通过、合入或部署。当前不提供这些发布操作，也不自动删除分支或工作区。

开发默认关闭，配置与操作均按既有登录主体隔离。管理员在Lab保存开发配置、批准验收标准；任务必须同时满足机器和项目开发授权。原只读入口、工具过滤与第一阶段23条验收保持原有限制；开发由独立显式入口派发，不把普通Bot会话开放成远程shell。

## 运行条件与配置

执行端需要Linux/WSL、已有SSH连接、可用Docker、固定摘要镜像及已安装的兼容编码CLI。首个运行适配器支持可独立运行的Claude原生可执行文件；CLI参数和模型由Lab配置，编码与评审分开执行。JS启动器及额外运行时依赖不会被自动挂载；预检失败时不会降级直接在宿主运行。

可用[执行镜像Dockerfile](../deploy/factory/Dockerfile)在受信任准备步骤构建镜像；这不会安装宿主全局工具。构建完成后取`docker image inspect`的完整本地`sha256:<64位>`或仓库固定digest，填入Lab。编码CLI仅以只读文件挂载；任务代码不能访问Docker socket。

在 **运维→多机软件工厂** 的第二阶段区域选择机器、仓库：

- 填写镜像、编码工具绝对路径、模型名称与服务地址、执行机凭据引用。
- 配置允许开发的用户、必需检查列表、失败测试检查标识、独立依赖准备命令。
- 填写并批准用户视角的验收标准；配置时限、修复轮次（默认6）、故障重试、磁盘保留空间和任务工作区上限。
- 保存后对精确基线SHA执行就绪检查，通过后派单。模型、工具和策略无需新增功能环境变量；凭据不在页面录入。

`credentialRef=claude-settings`读取执行账户既有Claude配置中的模型连接；也可引用执行机私有`~/.config/ppeng-factory/credentials/<引用>.json`，包含`baseUrl`和`apiKey`。引用仅允许简单标识。配置的模型地址必须与该引用记录完全对应。默认使用HTTPS；为兼容已有内网模型网关，也支持管理员明确配置的RFC1918字面IP或回环HTTP地址，拒绝公网HTTP。

就绪检查实际运行非root、只读、无额外权限的镜像探针，验证Git/Python/Node、CLI及有界模型调用，并检查基线与磁盘。镜像和宿主工具的准备独立于任务代码。依赖准备也在隔离内执行；当前任务网络只开放受限模型接口，因此应使用预先准备的依赖镜像或离线安装策略。普通安装脚本需要额外互联网时会失败，不能借模型代理下载任意资源。

## 执行边界

每任务使用独立Git仓库和任务分支，其Git元数据不与原检出共享。编码、依赖脚本、测试、后续Git操作和评审均在容器内执行；宿主只操作控制器记录和受控产物，不执行任务工作区内容。

容器以非root用户运行，网络关闭、根文件系统只读、移除capabilities并禁止提权，限制CPU、内存、PID、时限和输出。仅任务工作区可持久写入；评审阶段工作区只读。模型代理通过专用socket提供固定接口，服务端固定上游和模型、重建认证头，按阶段授权且限流，不提供通用代理或推送通道。SSH、GitHub和其他宿主凭据不挂入任务环境。

工作区大小与剩余磁盘每秒监测，超限中止；这是监测式限制，不是文件系统硬配额。终止未确认时仍占容量并显示待核实。共享内核容器也不是对宿主内核漏洞的绝对防护。

## 检查、自审和修复

控制器先要求编码工具只写行为测试，独立执行失败测试并保存实际断言失败证据。基线生产文件不得在RED阶段提前实现。之后冻结测试及依赖/门禁定义；实现和修复不得通过修改这些文件绕过验收。需要变更标准或测试时，应进入重新确认流程。

必需检查由保存的策略决定，记录实际命令结果、提交、退出码、跳过情况及有界输出；正常无输出的检查也会记录明确执行证据。已知基线失败逐项核对，不能只比较失败数量或由模型临时增加豁免。必需检查缺失、被跳过、超时或新增失败均不能READY。当前对检查中的skip/TODO采取保守拒绝；项目已有跳过用例也不能靠基线失败列表豁免。应先解决或按项目治理流程单独处理这些用例，再将该检查用于READY门禁。

评审是同机另一次独立执行，控制器分配完整diff覆盖范围，记录每段的精确SHA、策略版本和有效结论。未覆盖、缺少结论、无效输出或未关闭P0/P1均阻止READY；P2等非阻塞问题保留。旧问题跨轮、恢复与策略确认继续保留，不能通过省略或降级抹除；关闭须记录独立评审的理由、验证依据和当前提交，新提交使旧关闭依据重新待核验。CLEAN不是对代码绝对正确的证明，需要同时核对测试和覆盖证据。

一轮为FIX→TEST→REVIEW。最多执行配置的修复轮次；用尽进入待决。工具或模型故障有独立重试预算，不无限空转。Lab可查看问题、证据、追加轮次、恢复或明确改派。加轮不授予发布权限，改派必须先确认旧执行结束并保留旧机器执行历史。每次恢复、加轮及策略确认均保留上代结果；每代在任务容器外追加阶段日志，记录提交、轮次、检查与评审摘要。回执时间线和证据文件元数据有大小上限并明确标识截断，完整日志和有界命令输出留在执行机，证据中保存文件名、大小与摘要。完整回执超过1.5MiB时停止新阶段，保存私有快照并明确延期；相关进程尚未确认结束时仍显示待核实、保留占用，不截成READY。

## 状态与恢复

看板同时展示执行状态、开发阶段、轮次、提交和下一步。READY后保留分支、工作区和证据；无运行进程时释放执行槽位。策略变化会使原READY证据失效，需要明确确认并重新检查。

暂停、取消和超时终止整个任务容器，确认进程结束后才释放容量；无法确认保持待核实。协调服务重启、SSH断开时先核对已有回执与进程身份，不重复启动。恢复沿用任务编号、轮次和冻结测试；新执行代次隔离旧报告。无法核实的任务不通过“恢复”按钮直接清除占用。

显式依赖指定上游任务编号与精确提交。依赖未就绪不占槽位；上游READY后还需受控传输与核对增量Git bundle，目标容器验证并导入后才能执行。产物不经普通群消息传送，当前单个bundle上限700000字节，超限会明确延期供处理。原基线保持请求值，依赖提交可从只读`/input/dependency.bundle`消费。

群内显式指令：

```text
/factory develop {"machineId":"worker","repositoryId":"project","baseline":"<40位SHA>","requirement":"<已批准需求>"}
/factory status <任务编号>
```

从Lab或群重复提交同一请求使用原任务编号；同一幂等键换成不同需求会拒绝。自动报告去重，01:00–08:00 Asia/Shanghai仅提醒新卡点或待决；用户主动查询即时返回。待决记录在Lab及原群，不自动向外部即时通讯或邮件私信。巡检沿用每小时规则，等待依赖、暂停、待决及正常READY不当作停滞。

## API与验证

| 接口 | 用途 |
|---|---|
| GET/PATCH `/api/factory/development/:machine/:repository` | 项目策略；修改需要管理员 |
| POST `/api/factory/development/:machine/:repository/preflight` | 对精确基线做实际就绪检查 |
| POST `/api/factory/development/tasks` | 已批准需求派单，带requestKey |
| GET `/api/factory/development/tasks/:id` | 当前证据、阶段及策略是否仍有效 |
| POST `/api/factory/development/tasks/:id/control` | pause/cancel |
| POST `/api/factory/development/tasks/:id/decision` | add-rounds/resume/confirm-policy/reassign |
| GET `/api/factory/development/decisions` | 当前主体待决及可恢复任务 |

真实双机试跑脚本：

```sh
node scripts/factory-development-pilot.mjs <私有配置.json> <本地证据目录>
```

配置仅放本机，`machines`至少两项，各项有id/name/sshAlias/capacity、专用试验repositoryPath、baseline、image、toolPath、model及modelUrl。脚本创建临时本地协调服务和工厂群，在两台机器运行真实编码与评审，注入一次明确的源代码缺陷并要求修复，重复投递请求，并杀死/恢复临时协调服务核对续接。模型连接沿用执行机私有凭据，配置中不放密钥。

脚本独立读取源仓库状态，并在隔离容器中核对结果SHA、干净工作区、回执与工作区数量，保存完整证据。模拟测试不替代真实双机结果；证据和试验产物保持本地可复查，不自动删除。
