# Bot 历史摘要循环

规范 Bot 主会话的自动维护采用后台摘要。正常请求读取已有折叠摘要及未覆盖消息，不等待摘要模型。摘要达到真实模型窗口的既有 50% / 85% 档位才更新；自动维护不使用旧的 56 条消息强制触发条件。普通会话和显式 compact 工具的契约不变。

后台输入为上一份累计摘要与本次待覆盖的新历史，旧摘要替换节点不会再作为历史重复发送。成功后事务性更新当前摘要及替换区间，原始 transcript 保留，模型可通过历史检索工具回查。当前模型视图只保留一份生效摘要和未覆盖尾部。

同一 Bot 的后台任务由内存单任务调度和 SQLite 有时限租约共同去重。输入指纹和重试时间持久化在 daemon_control；历史与模型预算均未改变时不重复请求。失败保留旧摘要与原历史，至少退避一分钟；后台摘要限时一分钟。进程退出取消后台工作，崩溃后租约可过期回收。发布前核对源消息、已有摘要和租约，过期结果不能覆盖后续更新。

硬上限是例外：如果历史已经超出扣除系统提示、工具及输出预留后的模型预算，发送路径等待已调度的压缩；失败则明确报上下文超限，不丢历史、不发送超限请求，也不立即再重复调用一次摘要。显式手动压缩仍可按原流程执行。

验证：`packages/core/test/bot-async-summary.test.js`，以及 bot-dual-compact、bot-startup-summary-latency、context-compaction-reliability、long-session-compact 回归用例。
